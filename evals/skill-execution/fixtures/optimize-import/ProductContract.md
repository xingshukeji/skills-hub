# 导入功能合同

模型用于检验优化是否保留功能，不代表真实 XRain 的字段、固定限额或 API。

- prepare 接受非空 JSON 行数组；每行有唯一的非空 code 和 values 对象。按 JSON 往返语义保存值，保持行顺序与精确字符串，字符串包含合法 Unicode。字符串值按 maxValueBytes 校验 UTF-8 字节，参数是本案例调用输入，不是平台固定限额。
- prepare 读取当前成员资格和元数据修订，冻结输入，返回不透明计划标识与摘要。原调用者以后修改输入不影响计划；准备阶段没有业务写入。
- 摘要 v1 为冻结行数组的标准 JSON 文本的 UTF-8 SHA-256，小写十六进制。优化保持与旧接口完全相同的字节及摘要，不能换版本规避兼容。
- 计划只供原 tenantId、actorId 提交。提交时仍检查当前写资格；撤权后不能提交或取得原回执。元数据在首次提交前变化时拒绝旧计划。
- repository.commitAtomic 已提供授权、修订检查、原子行写入和回执。相同计划标识的重试与并发只产生一次业务写入；已提交后响应丢失仍通过原计划取得原回执。新计划独立判断当前数据冲突，不能只因内容相同返回另一个计划的回执。保存失败不得留下部分业务行，合法重试仍能完成。
- 取消在提交前或等待中发生时不写入，并保持原计划可恢复。当前调用取消不能当作另一个已完成提交的回滚证明。
- 相同 code 可以分别存在于不同租户，结果和回执互不混用。调用者修改返回对象不改变存储与后续回读。
