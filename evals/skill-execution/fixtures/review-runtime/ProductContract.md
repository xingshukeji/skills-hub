# 会话服务业务规则

本目录是本地 Node.js 会话服务模型，不包含 JVM 服务。已有测试只覆盖当时已有的小规模正常行为，不能代表完整范围。

绑定保存成功后，当前进程读取和重开读取应看到同一批绑定。保存可以被拒绝，但不得在已保存后静默保留旧的进程内状态。绑定数量会随用户使用积累，产品没有固定数量上限。

用户可以读取已加载的完整历史，再向前读取更早记录。结果按序号连续，不自动删掉旧历史；空历史保持可读。

一个连接应接收其全部可见会话的新消息，也应得知订阅失败。当前目录可能包含三个或更多会话。服务的资源预算必须在并发请求下成立；等待期间仍需遵循同一连接的累计预算和读取资格。

权限值只在有效期内可读；运行入口不在缓存 miss 时查询权限源。活动会话的 scope 登记供后台重新预热，在该会话显式退出时解除；值的 TTL 不是活动会话期限。没有活动会话的 scope 不得继续由该登记刷新。
