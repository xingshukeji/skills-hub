# 验证技能的实际执行

这组隔离任务用于补充 `task-scenarios` 的选择和下一步检查。它要求实际审查或修改文件，不能用计划回答代替。夹具为合成业务，取材于已经出现的纠偏类型，不含客户资料或真实会话。

1. 在临时目录保存本次修改前、修改后的完整技能与所需路由。修改前是实际内容基线，不能无条件用较旧的 Git HEAD 替代。
2. 分别为两个条件复制 `fixtures/`；每个任务使用独立工作目录。向执行者提供 `cases.json` 中对应请求、上下文和该条件的技能目录，隐藏 `rubric.json`、另一条件及作者分析。
3. 执行者只操作该任务目录，运行其中已有工具，保存实际输出和最终回答。禁止访问真实平台、账号、发布入口或执行 Git 写入；不自行委派。
4. 按 `rubric.json` 人工核对实际增量、执行过程和结果。输入、只读目录及技能快照核对内容哈希；完整目录同步核对相对文件集及每个文件内容。
5. 分别报告结构检查、作者走查和独立执行。未经委派授权不能自行启动评估代理；准备好任务或作者跑过夹具不表示独立行为已通过。

review 组保留自然审查请求，不在请求中指定缺陷、维度或预期数量。`rubric.json` 单独保存已知根因、全部受影响入口、合法反例和来源归因。协作操作、打包、共享视图与提交案例改编自实际纠偏类型，使用合成源码和数据；不得称为原历史版本回放或真实平台验收。共享视图案例采用后来明确的合同，专门检查当前判断，不能据其结果倒算原任务漏检。会话关闭案例在本轮主技能候选固定后加入，不用于正文编写；它仍是合成案例，独立性取决于实际评估者是否看过答案。

夹具中的 smoke 检查只提供当时已有的正常或局部保护证据。仓库维护测试 `tests/skill-execution-fixtures.test.mjs` 在评判侧验证已知缺陷可达及相邻正常行为；不要将该测试复制给审查执行者。它通过表示案例有效，不表示模型发现了问题。比较时分别记录根因找回、同类入口遗漏、误报、范围扩张和检查项证据；未做的检查不能填为零问题，也不靠关键词自动评分。预期清单只列已知问题；额外发现须按实际合同与触发核验，不能直接判为误报。核实后可补入后续案例基准，但保留本轮原始判定快照，单列本轮额外发现。

`review-runtime` 以 Node 会话服务提供语言特性、规模和并发的合成回归输入，同时保留合法的活动注册行为作为反例。它参与了语言与运行时方法编写，不能当作最终未见任务或真实产品负载；缺陷见证留在评判侧，不随工作目录交给执行者。

修改前后的技能使用相同文件与请求，各组只看到自己一份技能。提前固定对照版本和案例；观察结果后调整技能须另记一组，不能覆盖原结果。独立执行者不看作者分析、后续纠偏、判定测试或另一组回答。保留模型配置、实际读取及工具输出，先核对只读文件和技能哈希，再评判结论。

`diagnose-contrasts` 用相似失败表象和不同原始轨迹检验归因。向执行者只提供该工作目录、对应自然请求和技能条件；分类、应改及应保持的文件由评判侧 rubric 持有。各 q 目录互相独立，读取返回与当前来源/安装内容可比对，状态查询脚本只消费本地响应模型。作者侧 `tests/skill-evolution-fixtures.test.mjs` 核验输入差异、业务后置条件和请求的实际返回，不能复制到执行输入或当作模型评分。该组参与了本轮方法设计，只能作为回归材料；最终未见检验需另留任务，不能从这组改名取得。

将用于改写、用于选择候选和用于最终检验的材料分开。提示已知错误的共同输入可用于作者校准，不能测自行发现；参与候选选择的案例不能再作为最终未见检验。最终案例也应给基线和候选两个条件执行。没有独立执行时照实报告结构检查、夹具核验和作者走查，不要求额外委派来满足形式。

需要比较后续真实效果时，记录原要求遗漏、重复确认和无效停顿；用户新需求、必要业务选择与权限请求不计为技能造成的返工。这组小样本不支持激活率、稳定性或对话轮数的总体结论。
