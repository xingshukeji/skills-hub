# Repository instructions

- Team work starts from [Workforce](../xrain-workforce/AGENTS.md) and continues in this Local checkout under the same authorized chat. This repository is the sole authoring source for the retained Suhong Zhuwei skills, including shared methods and project-specific skills. New recoverable work is registered only in Workforce.

- Work in the saved Local checkout. Do not create or use worktrees unless the user explicitly requests one for this task.
- Skills live in `skills/shzw-<name>/`; the directory, frontmatter name and invocation use the same `shzw-` namespace. Install and update from the default branch; do not add skill versions, release tags, or a version catalog. Before consolidation, pull the current default branch and select the last content-modified complete directory for each duplicate name. Use Git content history for committed files and local modification times for uncommitted or personal sources; copying or checking out a directory does not make its content newer.
- Copy the complete skill directory, including references, scripts, assets and notices. Its own resources must resolve inside that directory. Keep the discovery description within 500 characters so the Workforce catalog does not truncate its trigger or exclusions. Resolve target-project source, commands and formal documents through that project's entrypoint, never through the skill installation location or an assumed sibling checkout. Conditional peer methods use their installed names or canonical skills-hub links.
- Choose one primary task entry from the natural request and necessary prior context. Load only relevant mode guides and product topics. Product usage knowledge remains complete for consumers without private source; product contracts and implementation facts remain owned by their projects. Policy and Git workflow actions live in `support/shzw-*/GUIDE.md`, outside skill discovery, and are copied completely when adopted or routed by a project.
- For material skill changes, separate original task inputs from later coaching and expected findings. Check task selection, responsible project, actual consumers, failure paths and completion evidence. Structural checks and author self-review are not independent model measurements. Use the existing evaluation tooling; do not create a runtime router or require skills to load all peer methods.
- Use `skills/shzw-skill-evolution/SKILL.md` for demonstrated skill failures, overlapping responsibilities, rewrites and consolidation. The user has authorized minimal proactive method and direct-routing improvements during actual tasks, including source and selected complete consumer copies. Distinguish execution mistakes, new requirements and environment failures first; return to the original task after validation. Product review remains read-only for product code; skill maintenance uses this separate scope. Explicit understanding-only, discussion-only and no-edit requests prevail. This does not authorize external actions, cross-chat messages, agents or changes to the workflow authorization baseline.
- Maintain the XRain CLI in `src/xrain-cli/`. Run `npm run build` after changes and commit the generated `skills/shzw-xrain-cli/scripts/xrain-cli.mjs` and third party notices. Do not hand-edit generated files.
- The proposed DeskPilot migration is owned by [src/deskpilot-cli/DESIGN.md](src/deskpilot-cli/DESIGN.md). It defines the planned source and complete skill delivery in this repository; it is not evidence of an implemented CLI, supported platforms, or a completed retirement of window10GUI.
- The XRain CLI and JavaScript helpers need Node.js 22.12+ (24 LTS recommended); npm dependencies and bundling are only for maintainers. Only the `authoring` mode of `shzw-xrain-app-package` requires .NET 10 for its offline validator; installing an existing package does not. Project development skills use the target project's declared toolchain.
- Keep credentials out of output, fixtures, and Git. Use temporary state directories and mock services for routine tests. For user-authorized live verification, reuse the target service's registered fixed test identities and follow its account, authentication and permission contracts; do not create a new long-lived identity per run or scenario. Use synthetic roles, entities and packages only within the authorized isolated fixture scope. Keep live state and evidence in ignored `.local-validation/`.
- Preserve browser authentication, token-bound tenants, session protection, and package integrity checks when changing CLI behavior.
- Run `npm run check` before delivery, plus the affected skill's focused tests. Changes to the application-package validator require `npm run test:appkg`. The README and llms.txt skill indexes are generated by `npm run index`. Project and personal installations are consumption copies; edit here, then explicitly update the selected complete directories and their references.
