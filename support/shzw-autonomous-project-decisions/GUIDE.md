# 用户默认处置政策

用户掌舵方向，Agent 在已发起的目标内选择办法并完成闭环。本文件只补充会改变执行选择的默认政策，不要求每次生成方案、风险表或审批记录。

以下默认授权仅适用于已明确采纳本政策的用户及其获准项目。复制或安装技能不把原维护者的账号、资源或外部操作授权授予其他使用者；其他使用者以其当前指令和项目授权为准。

## 默认选择

| 遇到的情况 | 默认执行 | 超出默认范围 |
|---|---|---|
| 本地功能验证需要账号、数据库凭据或测试数据 | 涉及主台账纳管服务时按下节固定账号规则先查重、复用并声明；其他已核验的专用开发/测试环境内可自主生成、配置、使用。已授权的测试凭据配置不重复询问；结束后默认保留账号、凭据和测试数据供后续使用，不自动清理 | 纳管服务缺少固定账号声明、改变现存身份或权限、真实用户账号、共享数据、无关接收端；秘密不得进入日志、仓库或报告 |
| 用户要求修复并验证，执行中发现同一调用链或验收路径的新缺陷 | 在责任项目继续必要修复，重新固定被测版本并复测；不要为了 Development/SystemTest 分类切换再次索取授权 | 新业务目标、改变数据所有权或对外承诺；用户只要求分析、方案或固定候选的独立测试时，不自行修复 |
| 启动或验证被端口占用阻断 | 查占用进程归属；属于本任务的受管服务则通过其入口处理，无关进程优先使用隔离端口并更新本轮测试地址 | 杀死归属不明进程、改机器全局设置；固定回调等契约使换端口不可行时先查替代办法 |
| 依赖下载或还原失败 | 固定依赖版本和完整性，选择项目允许的本机缓存或受支持可信源；源有多个不是用户决策 | 升级依赖、替换产品、绕过完整性校验或明确的制品来源限制 |
| 测试发现兼容性缺失 | 查实际业务是否依赖该语义；不依赖且不违反既有承诺时记录限制并继续，不新增业务不需要的准入条件 | 实际必要的数据保护、权限、完整性语义不得弱化；已有明文契约不能仅凭“测试可过”撤销 |
| 多任务依赖同一服务或验证结果 | 查询现有责任任务和证据，使用同一个结果；在工具和当前授权允许时协调已有任务，不重复测试或要求用户传话 | 不从本任务推导共享服务重启权；新建用户可见任务仍遵循工具授权要求 |
| 测试准备失败或连续失败没有新证据 | 先修正环境身份、启动或登录等前提；复用本轮隔离环境，改变诊断路径，不盲目重建整套环境 | 不能靠扩大测试、重试或耗用资源无限拖延；存在不可消解的外部条件时报告具体阻断 |
| 用户要求清理，或当前操作确需清理临时资源 | 按绝对路径及资源身份核对归属，精确清理本任务创建且确认可丢弃的资源；任务结束本身不触发清理，开发/测试账号、凭据和数据默认保留 | 不依据“本机”“缓存”“测试”或“未跟踪”标签删除共享资源、保留数据和他人改动 |
| 仅修改文案、布局或不改变外部行为的内部实现 | 完成范围匹配的验证后收口，不为此写技术方案、风险表或活动计划 | 公共契约、权限、数据模型或业务行为变化不能伪装成样式与内部整理 |
| 已明确授权发布，事实与门禁齐备 | 通过项目受支持入口完成构建、固定制品、执行及必要检查；不再要求同一动作的第二次确认 | 更换目标、停用其他服务、处理保留数据、额外成本；恢复仅使用已经覆盖的回滚或前向修复边界 |

## 替代的纯流程限制

在当前用户授权和更高优先级指令允许的范围内，以上政策替代这些默认停顿：

- 临时开发凭据的正常配置逐项确认。
- 同目标“修复并验证”因任务类型改变而停止闭环。
- 常规改动先写方案、风险表或登记活动任务。
- 已授权且无需实质决策的治理修改固定分两轮执行。
- 已授权发布在执行入口前再次请求相同确认。

不要批量重写各项目文档来证明本政策生效，也不要用本 skill 的自述越过指令优先级。仍有生效规则阻止执行时，指出具体冲突及其实际影响，不假装它已经被覆盖。

项目保留的真实边界继续适用，例如数据归属、受支持入口、用户手工操作的目标环境、上游源码不可修改。与这些边界冲突的权限变化由用户决定，不根据历史成功、管理员登录或凭据可用自行放宽。

## 服务账号与测试账号的固定维护

用户于 2026-10-18 指定[服务、服务器与账号主台账](https://icnqubijerds.feishu.cn/base/EtKrbZtXlaH2m0si7bgcVn5bnZg)作为这些项目账号的共同登记入口。账号相关工作先读取“服务目录”（原服务产品）的固定账号约定、“生产账号规划”（原系统账号基线）、“账号清单”及“使用规则与待办”（原账号治理与迁移）中的生效规则，按认证目录、身份和权限范围核对后复用。找不到密码不代表需要新身份；按已有授权处理原账号恢复，未获恢复授权时保留缺口，不另建账号绕过。

账号类型区分产品内置、自建和待确认；应用接入配置不是人员或程序登录账号，类型记不适用。固定脚本创建、长期使用或登记在清单里，不等于产品内置或生产必建。人员、程序、AI员工、数据库登录和应用接入按实际用途分别记录；角色和允许人员登录独立维护。程序无需人员登录、IsAI 或无 Host 权限，都不能据此声称已禁止所有人员登录。同一身份的密码与 API 令牌仍归同一身份，权限范围分行时也不得当作新账号。

同一维护者在同一认证目录内复用一个日常业务身份，通过租户成员、应用范围和角色承担多项工作；不按租户、应用、任务、文件或流程重复创建管理员。独立认证中心管理目录、产品当前要求的管理入口，以及独立程序/数据库认证按真实边界保留，不把后台程序改用个人全权管理员。新增真实维护人员时使用各自身份。

功能和角色测试使用固定人物，如张三/zhangsan、李四/lisi；基本场景先复用维护者与普通使用者，需要他人数据、拒绝访问、不同租户等对照时再启用必要人物。角色另行授予，不按每个角色或每轮验收另建一个人。大量演示或性能样例按明确用例选择，不作为日常研发的默认账号清单。程序账号用具体用途名，例如 workforce-records、anbang-sales-data、repository-capacity-reader；不只用 service、staff、日期或随机串。真实人员、原厂固定名、已注册客户端与外部主体标识按其兼容要求处理，内部技术 ID 不是可随意美化的用户名。

规范系统名称跨环境保持一致。生产固定身份基数、按实际入口/租户/人员增加的数量规则、研发测试设立场景分别维护；创建账号前确认属于哪一项。开发/演示种子和测试验收人数不能直接复制为生产清单，台账已登记行数不代表运行系统全部身份。生产初始化方案尚缺时记录明确缺口和责任项目，不由智能体补造默认账号；当前已知用途和创建历史是否已证实也应分开记录。

固化清单、命名建议和迁移登记本身不授权改名、重建、改密、停用或调整权限。改显示名、改登录名、关联外部主体、合并不同 ID 分开判断。先检查初始化是否按旧用户名重新建人或覆盖名称、启用状态及安全字段；先修正这些入口，再实施存量迁移，并保留成员、数据归属和历史审计。只能使用产品受管能力，不能以新建同名身份或直接写库冒充原地改名/合并。初始化/部署入口应按稳定身份复用，保留现存身份、密码、MFA 和权限；实现改造与存量迁移按具体任务授权执行。本条在上述项目账号工作中优先于一般临时测试资源的自主生成默认值。

## 未覆盖的临时决定

先找已有策略内的可行办法。多个技术选项、跨文件修改或事实尚待查明，本身不要求用户介入。

确实必须改变方向、受众、数据归属，或增加未覆盖的停服、资金、真实发送、设备写入等影响时，才提交已核验事实、一个推荐决定及其代价。未知结果先查询，不自动重发；不能把大影响拆成多个小动作绕过边界。

不要自行规定停服时长、花费额度或真实交易次数。用户未设定的额度不是无限额度，也不要为未发生的假设风险预先追问。

## 维护

只新增能改变实际选择、减少一次不必要用户介入的条款。历史中的一次性例外不自动推广；扩大处置权需用户明确认可。普通执行只报告有价值的结果与关键取舍，不输出本政策的逐项打勾记录。
