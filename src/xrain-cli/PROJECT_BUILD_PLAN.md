## 开发体验与职责校准

目标是让业务开发者维护业务源码及其实际依赖，使用公共工具和产品能力完成开发。平台包、宿主扩展及函数可以是不同制品，但必须能从同一项目追踪其来源、使用条件和实际结果。统一开发入口应调用各产品已有构建能力并报告各自结果，保留现有 CLI 命令兼容，不自动安装或发布。`project build` 已验证平台包构建，不代表整个业务应用的宿主及运行能力已经完成。

Salesforce 的项目配置可以声明包及版本依赖；默认的包版本创建会校验依赖和元数据。缺少所需依赖时，安装也会失败。它的价值是由平台和工具提供一致的开发、版本和验证入口，不是消除所有依赖。参考 [项目配置](https://developer.salesforce.com/docs/platform/sfdx-dev/guide/sfdx-dev-workspace-setup.html)、[包依赖](https://developer.salesforce.com/docs/platform/pkg2-dev/guide/sfdx-dev-dev2gp-create-dependencies.html)和[创建包版本](https://developer.salesforce.com/docs/platform/pkg2-dev/guide/sfdx-dev-dev2gp-create-pkg-ver.html)。

当前两类问题分别处理：

- **宿主能力。** 铵帮 `clients/web/scripts/sidebar-contract.mjs` 在企业构建时调用 Runtime 和 Workforce 的公开接口，验证业务定义所需的结果引用。锁定 Runtime `0.2.5` 的公开入口没有该校验函数，其内部定义校验也不接受 `resultReference`；锁定 Workforce `0.3.22` 不提供对应结果引用能力。预览制品支持这条链，但使用相同版本号，不能冒充已交付包。Workforce 和 Runtime 负责提供、验证及交付可解析的兼容版本组合；业务负责自己的定义和报价结果。先保留现有检查，直到可替代的公开能力和原业务验证均已就绪。
- **平台资源依赖。** 铵帮使用 Workforce 公共顾客包持有的稳定对象 ID。现行 XRain 包支持按目标有效元数据校验包外引用，但 `DOC-0051` 明确未提供跨包版本依赖声明；项目描述也没有该字段。这不是上述宿主构建失败的原因。按现有顺序安装公共包和业务包仍可使用；是否需要平台增加依赖声明，应按实际使用场景及 XRain 产品契约决定，不能由 CLI 虚构平台支持。

建议的开发流程：项目模板提供可解析的公共产品版本组合；业务开发者维护元数据、业务函数、智能体配置及自身扩展；统一入口调用平台构建和 Workforce 的受支持构建能力，分别返回实际生成的制品及失败位置；开发启动复用同一公共宿主。项目仍通过包管理器固定实际依赖。源码预览和正式包使用各自明确的来源，不以相同版本号推断内容相同。已有 `project build` 的平台包行为和既有原包命令保持兼容；协调入口不自动导入、安装或发布。

具体职责判断如下。这里列出待处理边界，不表示代码已经迁移：

| 当前内容 | 责任和处理方向 |
| --- | --- |
| skills-hub 项目初始化、项目描述、源码组装与 CLI | 保留共用工具；复用 XRain 的实际包接口，不在 CLI 复制一套平台安装或 Runtime 语义。 |
| XRain 包格式、资源引用及安装预检 | 保留在 XRain。需要新增包版本依赖时先由 XRain 明确产品合同、兼容旧包和实际消费者。 |

验收应覆盖两个相邻场景：仅有平台资源的项目可构建平台包，不依赖报价侧栏；使用结果引用的项目必须使用支持该能力的宿主和 Runtime，并在实际业务入口验证结果。先完成公共入口及其消费者，再清理业务侧的重复实现；不能通过删除检查隐藏缺失能力。
