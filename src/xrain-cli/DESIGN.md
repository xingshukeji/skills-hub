## 用户结果与现状

使用者安装完整 Skill 后，通过 CLI 配置目标并登录。使用者可以查询当前身份，再按实际权限管理智能体定义、个人订阅和应用选用，并发起、继续和回读对话。平台、租户、智能体入口与使用身份由同一连接配置表达。使用者不需要读取开发仓库或编写登录脚本。

`auth login` 的浏览器和设备方式从平台取得登录配置；原生账号方式直接使用平台原生登录接口。成功后均保存租户会话。`auth whoami` 向平台查询实际用户和租户。profile 可保存平台地址、租户、Runtime 地址及默认应用 ID；智能体定义与对话也保留单次 `--runtime` 覆盖。CLI 将所选平台凭据发送到 Runtime。平台的智能体订阅和应用选用仍使用平台地址。

本机开发配置中的 `http://127.0.0.1:15380` 是该开发组合的统一宿主地址。它不是 CLI 登录的返回值，也不是其他使用者的默认地址。平台现有 CLI 登录配置和应用列表没有提供客户端可用的 Runtime 地址。平台的定义目录地址用于其自身目录读取，不能当作各客户端的执行入口。

## 入口来源与连接配置

| 选择 | 用户操作 | 依据与影响 |
|---|---|---|
| 推荐：在 profile 中配置智能体入口 | 首次从实际服务所有者的接入信息取得可访问地址，并保存一次；后续命令复用 | 沿用现有 CLI 连接配置和登录；不引入平台地址登记服务。地址变化时由使用者更新相应 profile。 |
| 平台自动发现 | 登录后从平台取得与用户、应用和运行实例匹配的执行入口 | 当前平台合同未提供该信息。要实现此选项，需要另行确定公开地址的所有者、登记和多实例选择合同。不能将平台已有的内部目录地址直接暴露或当成执行地址。 |

推荐方案允许使用实际应用宿主对外提供的 Runtime 入口。只有该宿主确实开放所需接口时，应用网址才能用作该入口。CLI 不根据平台域名、应用名称或固定端口猜测地址，也不把本机开发地址设为通用默认值。缺少入口时，智能体运行命令提示配置；平台命令仍可使用。

profile 支持可选的 Runtime 地址和默认应用 ID。默认应用 ID 为空时使用个人上下文。多个环境或不同 Runtime 使用不同 profile。显式 `--runtime` 和 `--application-id` 保留单次覆盖能力。`--personal` 供适用命令在本次请求中选择个人上下文；`profile set --personal` 清除已保存的默认应用。`agent directory --mine` 始终使用个人上下文。

地址解析顺序为命令显式参数、当前 profile 中的对应字段。只有有效的平台地址与租户和该 profile 保存的目标一致时，才复用 profile 的 Runtime 和应用配置。若单次命令切换平台或租户，应显式提供对应 Runtime，或选择对应 profile；不能把原目标的地址静默用于新目标。订阅和订阅审批始终使用个人订阅语义。应用选用的管理命令继续使用明确的应用 ID。

`profile set`、`profile show/list`、`auth status` 和帮助文本处理并展示新的非秘密配置。当 `profile set` 修改平台或租户时，CLI 清除没有同时重新指定的旧 Runtime 和应用关联。成功登录同一平台与租户时，`auth login` 保留该 profile 的 Runtime 和应用配置；登录到不同平台或租户时，清除旧关联并提示重新配置。`auth logout` 继续保留 profile，`profile remove` 沿用现有删除语义。地址不是凭据，不存入登录会话；会话保护方式保持不变。

以下命令需要包含本次实现的 Skill 及支持身份检查的 Runtime：

```text
xrain-cli profile set --server <平台地址> --tenant <租户ID> --runtime <智能体入口地址>
xrain-cli auth login
xrain-cli auth whoami --agent
xrain-cli agent definition options
xrain-cli agent definition create --name <名称> --values-json <定义文件>
xrain-cli agent definition enable <agentId> --expected-revision <版本>
xrain-cli agent policy set <agentId> --visibility public
xrain-cli agent directory --mine
xrain-cli agent subscribe <agentId>
xrain-cli agent chat start <agentId> --message <问题>
xrain-cli agent chat send <sessionId> --message <后续问题>
```

应用场景可以通过 `profile set --application-id <应用ID>` 设置默认应用，也可以在适用命令上显式提供 `--application-id`。管理者按实际权限创建并启用定义、设置订阅策略或配置应用选用；这些动作不会自动为使用者订阅或批准申请。普通用户沿本人订阅资格使用个人入口。

## 登录与身份诊断

复用平台浏览器或设备登录，以及平台租户会话。对于平台原生租户账号，`auth login --native --user <账号> --password-stdin` 从标准输入读取密码，并通过平台原生登录接口取得同一种租户会话；不接受命令参数形式的密码。保持现有凭据选择顺序；`auth status` 和 `auth whoami` 展示实际凭据来源。如果环境变量中的凭据优先于已保存会话，使用者可以显式选择 `--auth session`。命令不输出凭据。

普通 `auth whoami` 继续查询平台实际用户和租户，并展示已配置的智能体入口和应用上下文。配置展示不表示 Runtime 已连接或应用已授权，不因 Runtime 不可用而改变平台身份查询结果。

`auth whoami --agent` 使用同一所选凭据分别查询平台与 Runtime，并展示两个服务各自确认的用户和租户。Runtime 的只读本人身份入口 `GET /v1/dsh/whoami` 返回服务端认证得到的 `userId` 和 `tenantId`，不返回令牌或权限全集。CLI 比较两个实际响应，标明一致、不同或未验证。一致仅表示两个响应中的用户和租户一致，不单独证明两个服务属于同一部署。已有 `/v1/dsh/agent-catalog` 只返回租户及目录，不能证明 Runtime 报告的用户 ID。

应用 ID 在身份结果中仅表示选定上下文。应用准入和智能体可用性仍由现有 `agent directory`、逐次使用判断及实际操作确认。身份查询成功不表示管理、订阅或数据权限已获授予。

旧 Runtime 未提供本人身份入口时，`whoami --agent` 保留平台身份结果并明确报告 Runtime 身份未验证。网络失败、登录失效和权限拒绝保留各自原因。诊断不是每次业务操作的前置门槛；旧 Runtime 已支持的智能体命令仍可按原合同使用。Runtime 身份合同由 xrain-harness 持有。

## 智能体命令与会话

定义、工具、工作区、目录和对话使用所选 Runtime。订阅规则、本人订阅和应用选用使用平台。CLI 对适用命令传递显式或 profile 选定的应用上下文；Runtime 和平台分别按当前主体执行原有权限检查。

创建会话时保留实际 Runtime、应用上下文、sessionId 和 requestId 的可见结果。继续、等待和处理待答事项时使用同一 Runtime 与原应用上下文。更换 profile 后，不根据智能体名称、平台默认应用或同名会话猜测原目标；使用者可选回原 profile 或显式指定原入口和应用。现有会话历史由 Runtime 持有，CLI 不建立副本。

对话继续等待本轮完成，并区分接纳与完成。提交结果未知时回读原会话或等待原 requestId，不自动重发。待处理审批或问题仍由使用者明确决定；登录、创建定义或订阅不隐式发起对话。

`--wait-timeout` 是从本地输入校验结束、首次网络动作前开始的总预算，覆盖会话创建、流连接、输入 POST 及本轮跟随；每个 HTTP 请求另受 `--timeout` 约束。流与输入提交并行观察，只有关联到本请求、输入及本轮终态的事件才能先于迟到回执完成。预算到期或断流时，已尝试提交的输入保留结果未知及原标识；本地中止连接不调用服务端取消入口。

## 实施归属与验收

skills-hub 修改 CLI 源码、构建结果及完整 Skill 的连接和智能体使用知识。xrain-harness 按本人身份合同增加只读入口并维护对应契约。平台继续负责登录、本人资格与应用准入；本方案不要求平台新增 Runtime 登记或执行转发。正式产品和运行事实仍由各责任项目持有。

交付需验证：

1. 在独立安装的 Skill 中，从 profile 配置、正式登录和 `whoami --agent` 进入智能体目录；不用开发配置文件或另写脚本取得凭据。
2. 使用有管理权限的身份完成定义创建、配置、启用及回读。使用有订阅权限的实际身份申请并按现有策略取得结果。应用选用和个人订阅分别验证，不互相代替。
3. 在选定 Runtime 和身份下发起真实对话、继续同一会话并回读历史。确认返回的 sessionId、requestId 和完成结果；一次普通文本成功不代替工具或业务写入结果。
4. 覆盖重新登录保留同目标配置、profile 切换、单次覆盖、个人与应用上下文、旧 Runtime、身份不一致、未配置入口和服务不可用。保留原有平台命令及既有 `--runtime` 用法。
5. 使用临时或已授权环境和既有受管身份验证。保留既有账号、定义、订阅、会话和工作区；需要写入时按实际授权与环境合同操作。

对话、登录及身份入口的源码测试只能证明对应实现；真实登录与实际 Runtime 消费证据另行记录。构建、方案或本机隔离测试不证明其他部署已经更新。

## 平台设置与定义配置管理规划（待实施）

本节解决“页面上的设置能否通过 xrain-cli 可靠管理”。范围包含智能体定义大小上限、定义本身的配置，以及后续平台设置的接入方式。本轮交付方案，不改变 CLI 代码、现有配置或运行环境。

### 已核对的能力和缺口

截至 2026-10-31，CLI 可以管理普通定义字段，但没有完成这些设置的统一管理闭环。

| 设置或动作 | 当前实现 | 需要补齐的结果 |
|---|---|---|
| 平台定义大小上限 | XRain 已有 Host 管理接口，页面可以配置；CLI 无对应命令。 | 通过正常 Host 登录读取和修改同一值，显示 MiB，传输整数字节。 |
| 名称、工作要求、模型、推理等级、工具、推荐问题、业务操作和侧栏 | `agent definition update` 接收字段 JSON，使用明确版本，并保留未修改的现有字段。 | 与当前 Runtime 字段和继承语义同步，完成当前页面配置的代表性互通验证。 |
| 启用和停用 | CLI 先读取定义，再提交整份定义；Runtime 已提供轻量启停接口。 | 只提交 ID、版本和启用状态。降低写入上限后，仍可停用已有的大定义。 |
| 选择已有文件夹 | Runtime 支持直接目录。CLI 的公开说明和归一化逻辑主要覆盖登记工作区；直接目录需要调用者自行构造相互一致的底层字段。 | 支持当前页面的直接选择语义，保留未修改目录，不自动新建文件夹或维护可选列表。 |
| 定义文件导入和导出 | 页面有版本化交换文件；CLI 只有更新请求 JSON，没有对应的交换文件命令。 | 页面和 CLI 使用同一种文件格式；交换文件、更新补丁和 Runtime 存储文件分别处理。 |
| 大文件与定义读取 | CLI 文件和 stdin JSON 输入、通用 HTTP 响应均有固定 32 MiB 上限。`show` 读取整个定义列表再选一个 ID。 | 对齐动态写入限额，按单条定义读取，避免多份合法定义合计超过响应限制而使单条查询失败。 |
| 个人偏好 | XRain 的 `/api/tenant/v1/settings` 实际操作当前人的 USER 设置；CLI 没有专门命令。 | 按个人设置接入，不能拿它写同名键来代替 Host 全局设置。 |
| 本机连接和进程启动参数 | `profile set` 保存 CLI 连接。Runtime 环境变量等启动配置归运行所有者。 | 保留两者职责；修改 CLI profile 不宣称平台或 Runtime 参数已改变。 |

证据入口为本目录的 [命令定义](schema.mjs)、[定义命令](agents.mjs)、[登录](auth.mjs)、[身份查询](diagnostics.mjs)、[输入](core.mjs)和[传输](http.mjs)。现有[智能体命令测试](../../tests/cli-agents.test.mjs)与[独立随附包测试](../../tests/cli-agents-bundle.test.mjs)覆盖普通生命周期、版本冲突、权限拒绝和未知写入结果；它们不证明新增平台设置命令已经实现或完成真实联通。

### 设置归属与共同规则

推荐复用已有领域接口。CLI 提供命令、单位转换和结果表达，服务端继续持有权限、校验、事务和持久化。首轮不新增设置表、配置服务或任意 `app/key/level` 的全局写入入口。

| 设置归属 | 事实所有者及身份 | CLI 接入规则 |
|---|---|---|
| Host 全局设置 | XRain；实际 Host 管理员会话 | 使用 `host settings`，调用页面相同的受控接口。租户管理员权限不能代替 Host 权限。 |
| 租户或应用级业务设置 | 对应产品；有相应业务管理权限的租户主体 | 逐项使用已有领域接口；缺接口时由产品补齐，不从个人偏好接口或 Host 设置自行推导租户覆盖规则。 |
| 智能体定义 | xrain-harness；目标 Runtime 的租户主体 | 保留 `agent definition`，由 Runtime 核验版本、目录、工具和业务引用。 |
| 订阅和应用选用 | XRain；对应业务主体 | 复用现有命令，不与定义保存合成一个事务。 |
| 个人偏好 | XRain；当前人 | 后续按现有 USER 接口接入，不把路径中的 tenant 解释为租户级管理设置。 |
| CLI 连接与服务启动配置 | CLI profile 或对应服务运行所有者 | 分别使用现有入口。CLI 不通过 SSH、改数据库或覆盖运行文件代行动态设置。 |

同一个设置的网页和 CLI 共用同一后端合同。后端负责决定值的范围、默认值和生效方式。CLI 不再硬编码第二个 16 MiB 默认值，也不把模型上下文 token 数转换为定义文件大小。MiB 按 1,048,576 字节换算；定义上限约束文件或保存请求的 UTF-8 字节，包含 JSON 结构及转义后的实际大小。

命令输出沿用现有结果格式和退出码约定，并包含实际目标及作用域。只显示必要的原值、新值和单位，不输出凭据。多个设置的 `batch` 仍是顺序操作，之前成功的写入不会因后一步失败而回滚；不宣称跨平台、Runtime 和本机配置的一次性事务。

未来接入密钥类设置时，读命令只展示领域接口允许返回的配置状态，写入使用 stdin 或受保护文件。日志和导出文件不回显密钥，CLI 不另存一份明文设置。复用现有凭据保护及服务端权限，不为普通数值设置增加秘密管理步骤。

### 第一项交付：平台上限可以正常配置

先完成 Host 身份与设置命令的最小闭环。下列命令均为拟议接口：

```text
xrain-cli auth login --profile central-host --server <平台地址> --scope host --native --user <已有账号> --password-stdin
xrain-cli auth whoami --profile central-host --auth session --json
xrain-cli host settings get agent-definition-limit --profile central-host --auth session --json
xrain-cli host settings set agent-definition-limit --mib 16 --profile central-host --auth session --json
xrain-cli agent definition limits --profile <租户连接> --auth session --json
```

1. 扩展正常登录以显式选择 Host 作用域。复用现有原生登录的 `scope: host` 和已有账号。当前 `tenantSession()` 要求非空租户，不能直接接纳 Host 响应；需同时完善 profile、会话保存和目标匹配。已有 `whoami` 可以识别服务端返回的 Host 身份，直接复用。首轮不以新增 Host OAuth 流程为前提，也不根据“未填租户”推断 Host。
2. 将 `agent-definition-limit` 映射到既有 `GET/PUT /api/host/v1/settings/agent-definition-limit`。读取保留 `maxDefinitionBytes` 的 null 和 `defaultMaxDefinitionBytes` 的区别。未配置平台值时，不能宣称所有 Runtime 的实际值均等于默认值。
3. 设置接受互斥的 `--mib` 或 `--bytes`。MiB 转换与页面使用相同的字节舍入规则；拒绝非有限数、非正整数字节或超出服务端支持范围的输入。默认读取本命令开始时的旧值，随 PUT 传入 `expectedMaxDefinitionBytes`。脚本可用 `--expected-bytes` 指定此前观察值，字面值 `null` 表示平台尚未配置。
4. 旧值已经等于目标值时直接报告当前值，不再 PUT。409 保留原请求和观察值，不换基线重试。401、403、校验失败和服务不可用分别报告；不自动换身份、升权或回退到另一设置接口。
5. 写入响应丢失时沿用结果未知处理，回读同一目标，不重复 PUT。回读匹配只能证明当前值已满足要求，不能伪称已经追溯到本次写入。正常成功响应由已完成的服务端事务确定，不强制增加预览或逐次确认。
6. `agent definition limits` 读取既有 Runtime `/v1/dsh/agent-definitions/limits`。它报告目标 Runtime 的实际限额及启停能力，使用租户身份；Host 设置命令不依赖调用者同时配置 Runtime。首轮不增加恢复默认、删除设置或批量同步功能。

此项由 skills-hub 完成 CLI 和正常 Host 登录适配；XRain 继续拥有全局值和授权，xrain-harness 继续提供已有动态读取。现有设置存储和默认值不变，不需要迁移数据库。

### 第二项交付：定义配置与当前页面互通

优先接入 Runtime 已有的轻量启停能力。启停请求只包含 `agentId`、`revision` 和 `enabled`。新导入及整份保存仍读取当次上限；读取已有定义和轻量停用不受新写入上限阻断。版本冲突继续按现有明确版本处理，不能自动改用最新版本。

定义输入按实际 UTF-8 字节和序列化后的完整保存请求核验，覆盖文件、stdin 和内联输入。32 MiB 不能继续作为与平台无关的第二个定义业务上限；其他 CLI 命令的既有输入保护不因此整体放大。读取预算与写入限额分开，避免上限调小后无法读取已有的大定义。传输已发生后才发现响应超限、格式错误或断连，应保留写入可能已完成的事实。

xrain-harness 增加按 ID 读取单条定义的能力，并提供不含完整工作要求的列表表示；CLI 使用这两个入口。已有客户端仍可沿用原列表合同，Workforce 后续按需要采用轻量列表。定义读取不因另一个大定义而失败，导出也不需要先下载所有定义。

直接目录输入统一转换为 `workspaceChange`，保持工作方式与目录字段一致。未修改目录时明确保留；选择已有文件夹不登记额外目录或创建文件夹。原生工具继续区分省略、null 和空数组：分别表示保留、恢复继承和明确不使用。业务工具、对象、模型、侧栏和录入字段均通过同一 Runtime 校验，不在 CLI 复制业务授权。

增加明确的 `agent definition export` 和 `agent definition import`。文件格式由 [Workforce 定义设计](../../../xrain-workforce/文档/项目/项目_XRAIN_WORKFORCE/技术设计/DOC-0017-智能体定义与工作区.md)持有；CLI 消费现有版本 1，不另造格式。交换文件与 `update --values-json` 的补丁保持不同用途。导入新建默认停用；导入到已有 ID 时要求明确版本，并保留目标启用状态、订阅、应用选用和员工关系。目录和业务引用按目标环境核验。沿用页面“不强制预览”的取舍。

Workforce 提供公开格式约束和合成互通样本，CLI 与页面使用同组样本验证。首轮不为格式转换再引入独立 SDK 或复制 Runtime 存储目录。导出不包含凭据；导入不复制工作区文件、身份或权限。

旧服务按其已提供能力保留普通用法，新增能力缺失时明确说明。401、403、503 和无效响应不能当作旧版本降级依据。兼容路径不自动重试写入，不把版本诊断增加为所有旧命令的操作门槛。

### 后续设置的接入与责任

完成前两项后，再按实际页面和服务接口逐项补个人偏好及其他已确认设置。每项先明确所属作用域、写入身份、数据类型、单位和实际消费者，再增加对应命令。没有领域接口的设置先由事实所有者补接口，不能用 `data update` 写内部设置表。

设置数量增加后，`host settings list` 可以列出 CLI 已接入的项目；它不表示已经枚举整个平台全部配置。元数据先复用现有命令描述和领域 DTO，只有多项设置出现实际共享需求时才评估服务端描述接口，不预先建设设置注册表。启动参数的生效仍由对应运行合同决定，不能把所有配置宣称为即时生效。

| 责任方 | 有限交付结果 |
|---|---|
| skills-hub | Host 登录闭环、设置和定义命令、单位和大小处理、冲突及结果未知表达、构建后的完整 CLI Skill。 |
| XRain / all_in_one | 维护既有平台设置接口、Host 权限、旧值比较、事务和个人设置边界；只补已证实的接口缺口。 |
| xrain-harness | 维护定义及启停校验；提供单条读取和轻量列表，保持旧列表合同可用。 |
| Workforce | 维护定义交换文件和页面交互合同，提供互通样本，消费相同平台值和 Runtime 能力。 |

CLI 源码修改后，构建随附文件并交付完整 Skill，更新选定消费副本，再核对注册入口实际指向。不能只修改作者仓库代码，就称使用者已有新命令。

### 完成条件

第一项完成时，已有 Host 管理员通过正式 CLI 登录设置 16 MiB，页面读取同一值，运行中的租户 Runtime 在下次请求中读取 16,777,216 字节。反向修改页面后，CLI 能读取更新值。普通租户身份不能修改全局值；并发旧值冲突不覆盖他人更新；服务端已提交但回包丢失时不会重复写入。

第二项完成时，CLI 和页面双向交换代表性定义，覆盖模型、直接目录、继承工具、业务工具、推荐问题、业务操作、侧栏及录入字段。验证中文及 JSON 转义后的大小、动态提高和降低限额、多个大定义下的单条读取，以及降低上限后停用旧大定义。导入失败不改原定义，未指定字段和既有使用关系保持原状。

先用隔离服务验证输入、权限、冲突、断连和格式互通，再在获准目标用已有受管身份完成一条实际 CLI—页面—Runtime 链路。方案、隔离测试和构建结果分别报告；只有完成对应实际消费，才声明该项设置已稳定支持 CLI。独立系统测试和部署不由本方案自动建立。
