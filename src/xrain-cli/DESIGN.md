本文记录 CLI 的连接、智能体与设置管理合同。实际部署和已安装 Skill 是否包含某项能力，以所用源码、随附包及服务接口为准；构建或源码测试不证明其他消费者已更新。

CLI 的唯一实现位于本仓 `src/xrain-cli/`，交付物是完整 `shzw-xrain-cli` Skill 中的 Node.js 脚本。构建以依赖的仓库内路径生成脚本；即使依赖目录链接到其他位置，同一源码与依赖也应得到相同字节，不包含构建机路径。Workforce 持有团队当前消费副本，跨项目入口链接该副本。后续能力差距、责任项目和验收要求见[能力对齐待办](ALIGNMENT_TODO.md)。

普通HTTP请求不另设CLI默认总截止；未指定--timeout时沿调用方取消和原服务执行等待。显式--timeout仍限制单次请求，操作级--wait-timeout、真实凭据到期及协议校验保持原义。应用操作取显式请求时限和剩余操作预算中较早者；没有有限预算时不创建计时器。导入请求和对话流连接按同一可选时限处理，避免空值转换成零或一毫秒。邮箱、临时生成及语音不再需要单独退出通用截止的分支。

认证网络请求沿本次登录取消，不设缺省30秒截止；显式--timeout限制各次HTTP读取。浏览器回调不按3分钟淘汰，由用户取消、登录结束或关闭监听释放；发现与密钥读取完成后才打开回调端口。设备码的expires_in及服务端pending/slow_down语义保持，由一个按真实到期重设的计时器约束轮询和在途Token读取；超过单个原生计时器范围时分段重设，不提前到期。失败或取消不替换原连接及已保存登录，不自动重新交换授权码；签名、issuer、audience、nonce、PKCE、单次使用及租户核验保持。

认证、身份诊断及个人设置沿公共HTTP读取完整响应，不设独立1MiB准入。原生密码stdin保留完整UTF-8内容和末尾换行，由平台核验凭据；CLI仍拒绝交互终端、空输入及无效UTF-8。设备码显示值不另设128字符门槛，仍拒绝空值和终端控制字符。回调服务器保留10秒HTTP请求及头部接收设置，约束未收完的连接，不限制已接纳回调的登录处理；实际触发还受Node.js检查周期影响。完成、关闭和取消沿原监听释放，有限样本不标定长期连接容量或最优数值。

原邮箱连接检查、读取、草稿和 AI 目录/协助的默认执行预算归原邮箱服务或 Runtime，CLI 不叠加普通 HTTP 截止；用户显式指定的 --timeout 仍限制当前请求。原生草稿的连接、TLS、协议或 OAuth 配置失败属于追加前失败，保留原错误；APPEND 期间、追加后的复核或回执丢失保持结果未知，均不自动重试。AI 协助只生成文本，按读取失败报告，未取得结果不推断已保存或发送。

普通 JSON 文件、管道输入、HTTP 回执和对话事件不再叠加 CLI 的固定容量准入，导入发现和错误回执沿同一规则完整读取。具体字段、文件协议和显式调用参数的约束仍由对应操作持有；取消、超时、身份与结果未知不改变原义。读取、编码、缓冲和终端输出仍占用实际内存，不能据异步读取承诺常量内存或任意规模。

临时文本生成沿当前调用的取消和 Runtime、模型生命周期等待，不叠加独立HTTP默认截止。用户显式提供 --timeout 时仍按该值结束本次等待；中断或回执未知不自动再次生成。

## 用户结果与现状

平台扩展使用固定领域路由及原生请求 DTO，完整请求通过文件或 stdin 输入，保留服务端权限、版本、影响决定与集合事务。通用管理命令不接受任意 URL、身份 header 或自动授权。普通记录及安全管理写入与已有 Runtime 写入共用结果未知处理；上下文只保留目标、记录和请求标识，不复制写入内容或秘密，也不自动重放。

Runtime 会话的停止、问题取消、命令及模型操作沿公开工作台接口执行。Ctrl+C 继续只结束本地观察，取消不撤销外部效果。服务端 API Token 可保存为目标绑定的私有文件，通过显式 `--token-file` 或 `XRAIN_TOKEN_FILE` 消费；Windows 使用当前用户 DPAPI，其他系统要求 0600。文件保存采用排他创建，签发成功但本地保存失败时保留原服务结果并要求查询原 Token，不重新签发。

在线元数据写入保留原 ETag、创建请求键和删除影响令牌。应用包维护保留原安装、组件、策略与操作标识；Host 本地导入不安装或发布。编排、Routine、HTTP、投递、变量与地区设置使用各自原生合同，不新增调度或执行状态。文件及包服务决定传输大小规则，CLI 流式传递原文件，不复制固定业务限额。下载保留授权、长度和内容类型校验；独立市场另核对精确版本、包摘要和文件摘要，发布指针变更保留原值比较。

包构建与市场下载在临时文件中核验摘要和身份，通过后排他保存。包上传使用原文件 Blob，根清单通过 ZIP 元数据定位并受限解压读取，不把整个包载入内存或提取其他条目。清单解码保护不充当包传输上限；构建源继续校验 JSON 语法及源摘要。

二开项目通过 `project init/assemble/build` 按显式项目描述构建：读取并快照当前输入，冻结历史脚本原文，以项目声明的 esbuild 编译模块，分别输出平台包源码和独立租户函数输入。显式记录生成器使用静态项目模块和 `node:crypto`，从原始模块快照执行以保留历史函数文本，并核对重复运行与资源身份；生成器是受信任代码，导入检查不是沙箱。开发候选生成独立版本身份；正式模式检查实际项目输入与 Git 提交，编译环境由项目另行固定。`project build` 复用单文件构建实现，核对响应身份、摘要及构建器信息并排他保存原包。目标导入、安装、选版及运行分别验证。项目描述和目录合同见[项目标准](../../skills/shzw-workforce-business-development/references/project-structure.md)。

管理命令按操作声明分页默认值和关键回执校验。对象、字段及字段部署恢复校验原生版本与目标；结果未知时保留请求键、ETag 和安全的对象标识。元数据的 Idempotency-Key 使用原 Header 合同，不套用业务记录创建的 requestKey 长度规则。请求体中的 idempotencyKey、whatId 也进入安全恢复信息。原生 204 不要求 JSON 回执。HTTP 和 security API 调试的终端输出保留文本或 base64 编码；显式文件输出在请求前排他创建并流式写入，不采用 JSON 缓冲上限。完整错误响应仍保存，断流、取消或本地写入失败仅清理本次拥有的未完成文件。调试的 408、5xx、超时及断连保留写入结果未知，明确拒绝保留原错误。

执行动作按各自原生 DTO 声明结果判断：HTTP 与编排使用 isSuccess；账户和连接检查使用对应布尔值或状态；投递区分受理、失败、未知及跳过。Runtime 命令与 Workforce 转发使用 execution.result.kind。失败或未知返回非零退出码并停止 batch，保留原回执；历史和记录查询不据其业务失败状态改变退出码。Host 构建、组件与版本查询及时间解析沿原生允许范围执行。

Workforce 命令使用明确 `--workforce` 地址、原平台登录会话和实际 applicationId。宿主专用 `/api/cli/v1` 每次核验主体、租户及应用准入，再调用原 Task、消息、工作台和计划任务处理器；不把 Token 通用于网页路由。Task grant 由宿主内部准备并交给 Runtime，不交给 CLI。计划任务启用时宿主复验并保存同一主体的原凭据；CLI 不借管理员或浏览器会话，不持有第二套调度状态。

Task 写入保留原保存回执。挂载或 AI 接纳未完成时返回 partial_success 并停止 batch；回读仍是成功的查询，不重新触发任务执行。接待字段选项通过原应用的获权接口读取，保留每个 selected 值及分页；应用决定字段是否可见和可选。

导入能力查询返回原服务的当前能力及不可用原因。下载模板只调用原模板服务，不以分块作业资格、上传文件上限或分块 options 字节上限作为前提。提交作业继续按服务当前资格和上传协议判断，下载继续保护目标文件及完整长度。

应用发布使用原 `/api/application-messages` 和执行者凭据，不经 Workforce 成员别名。原服务核验发布应用及机器人目标资格；CLI 保留应用、目标和 clientMessageId，分别报告 accepted、saved、failed 与查询 unknown，结果不明不重发。本人回答反馈和语音经成员别名复用原会话权限、反馈存储及 speech Remote；语音输入能力由当前目录声明，CLI 传递原音频字节和选择，不自动准备模型或发送识别文字。

主业务对象对话使用原 `primaryObjectRef` 合同。受管单次执行和临时文本使用独立原生协议：前者由服务生成 runId，可按同一身份查询有界内存结果；后者只生成文本，没有 Session、工具或历史。丢失单次执行回执时没有客户端请求键可恢复，CLI 不重放。以上源码能力不表示所有部署已升级。

临时文本目录和生成复用 profile 或显式选择的应用上下文，也接受 --personal；应用 ID 使用原生请求头传递，由 Runtime 核验资格。

使用者安装完整 Skill 后，通过 CLI 配置目标并登录。使用者可以查询当前身份，再按实际权限管理智能体定义、个人订阅和应用选用，并发起、继续和回读对话。平台、租户、智能体入口与使用身份由同一连接配置表达。使用者不需要读取开发仓库或编写登录脚本。

`auth login` 的浏览器和设备方式从平台取得登录配置；原生账号方式直接使用平台原生登录接口。租户登录保存租户会话；显式 Host 原生登录保存独立绑定的 Host 会话。`auth whoami` 向平台查询实际用户和租户。profile 可保存平台地址、租户、Runtime 地址及默认应用 ID；智能体定义与对话也保留单次 `--runtime` 覆盖。CLI 将所选平台凭据发送到 Runtime。平台的智能体订阅和应用选用仍使用平台地址。

本机开发配置中的 `http://127.0.0.1:15380` 是该开发组合的统一宿主地址。它不是 CLI 登录的返回值，也不是其他使用者的默认地址。平台现有 CLI 登录配置和应用列表没有提供客户端可用的 Runtime 地址。平台的定义目录地址用于其自身目录读取，不能当作各客户端的执行入口。

租户管理员代理执行复用平台原生 `account/login-as`。`auth login-as --user <登录名> --save-profile <成员连接>` 从所选管理员profile读取已保存的租户会话，把目标成员会话保存到另一个profile；管理员凭据和活动连接保持。响应必须携带同租户的目标userId及proxyByUserId；后续命令使用成员会话及其原权限，不在业务请求中替换发送者。目标会话继续使用现有DPAPI或0600保护，失败不覆盖旧会话；不增加另一套代理身份或授权存储。

## 入口来源与连接配置

| 选择 | 用户操作 | 依据与影响 |
|---|---|---|
| 推荐：在 profile 中配置智能体入口 | 首次从实际服务所有者的接入信息取得可访问地址，并保存一次；后续命令复用 | 沿用现有 CLI 连接配置和登录；不引入平台地址登记服务。地址变化时由使用者更新相应 profile。 |
| 平台自动发现 | 登录后从平台取得与用户、应用和运行实例匹配的执行入口 | 当前平台合同未提供该信息。要实现此选项，需要另行确定公开地址的所有者、登记和多实例选择合同。不能将平台已有的内部目录地址直接暴露或当成执行地址。 |

推荐方案允许使用实际应用宿主对外提供的 Runtime 入口。只有该宿主确实开放所需接口时，应用网址才能用作该入口。CLI 不根据平台域名、应用名称或固定端口猜测地址，也不把本机开发地址设为通用默认值。缺少入口时，智能体运行命令提示配置；平台命令仍可使用。

profile 支持可选的 Runtime 地址和默认应用 ID。默认应用 ID 为空时使用个人上下文。多个环境或不同 Runtime 使用不同 profile。显式 `--runtime` 和 `--application-id` 保留单次覆盖能力。`--personal` 供适用命令在本次请求中选择个人上下文；`profile set --personal` 清除已保存的默认应用。`agent directory --mine` 始终使用个人上下文。

地址解析顺序为命令显式参数、当前 profile 中的对应字段。只有有效的平台地址与租户和该 profile 保存的目标一致时，才复用 profile 的 Runtime 和应用配置。若单次命令切换平台或租户，应显式提供对应 Runtime，或选择对应 profile；不能把原目标的地址静默用于新目标。订阅和订阅审批始终使用个人订阅语义。应用选用的管理命令继续使用明确的应用 ID。

`profile set`、`profile show/list`、`auth status` 和帮助文本处理并展示新的非秘密配置。当 `profile set` 修改平台或租户时，CLI 清除没有同时重新指定的旧 Runtime 和应用关联。成功登录同一平台与租户时，`auth login` 保留该 profile 的 Runtime 和应用配置；登录到不同平台或租户时，清除旧关联并提示重新配置。`auth logout` 继续保留 profile，`profile remove` 沿用现有删除语义。地址不是凭据，不存入登录会话；会话保护方式保持不变。

以下命令需要包含本次实现的 Skill 及支持身份检查的 Runtime：

```text
xrain-cli profile set --server <平台地址> --tenant <租户ID> --runtime <智能体入口地址>
xrain-cli auth login
xrain-cli auth whoami --agent
xrain-cli agent definition options
xrain-cli agent definition create --name <名称> --values-json <定义文件>
xrain-cli agent definition enable <agentId> --expected-revision <版本>
xrain-cli agent policy set <agentId> --visibility public
xrain-cli agent directory --mine
xrain-cli agent subscribe <agentId>
xrain-cli agent chat start <agentId> --message <问题>
xrain-cli agent chat send <sessionId> --message <后续问题>
```

应用场景可以通过 `profile set --application-id <应用ID>` 设置默认应用，也可以在适用命令上显式提供 `--application-id`。管理者按实际权限创建并启用定义、设置订阅策略或配置应用选用；这些动作不会自动为使用者订阅或批准申请。普通用户沿本人订阅资格使用个人入口。

## 登录与身份诊断

复用平台浏览器或设备登录，以及平台租户会话。对于平台原生租户账号，`auth login --native --user <账号> --password-stdin` 从标准输入读取密码，并通过平台原生登录接口取得同一种租户会话；不接受命令参数形式的密码。保持现有凭据选择顺序；`auth status` 和 `auth whoami` 展示实际凭据来源。如果环境变量中的凭据优先于已保存会话，使用者可以显式选择 `--auth session`。命令不输出凭据。

普通 `auth whoami` 继续查询平台实际用户和租户，并展示已配置的智能体入口和应用上下文。配置展示不表示 Runtime 已连接或应用已授权，不因 Runtime 不可用而改变平台身份查询结果。

`auth whoami --agent` 使用同一所选凭据分别查询平台与 Runtime，并展示两个服务各自确认的用户和租户。Runtime 的只读本人身份入口 `GET /v1/dsh/whoami` 返回服务端认证得到的 `userId` 和 `tenantId`，不返回令牌或权限全集。CLI 比较两个实际响应，标明一致、不同或未验证。一致仅表示两个响应中的用户和租户一致，不单独证明两个服务属于同一部署。已有 `/v1/dsh/agent-catalog` 只返回租户及目录，不能证明 Runtime 报告的用户 ID。

应用 ID 在身份结果中仅表示选定上下文。应用准入和智能体可用性仍由现有 `agent directory`、逐次使用判断及实际操作确认。身份查询成功不表示管理、订阅或数据权限已获授予。

Runtime 本人身份查询失败时，`whoami --agent` 保留平台身份结果并明确报告 Runtime 身份未验证。缺失接口、网络失败、登录失效和权限拒绝保留各自原因。诊断不是每次业务操作的前置门槛。Runtime 身份合同由 xrain-harness 持有。

## 智能体命令与会话

定义、工具、工作区、目录和对话使用所选 Runtime。订阅规则、本人订阅和应用选用使用平台。CLI 对适用命令传递显式或 profile 选定的应用上下文；Runtime 和平台分别按当前主体执行原有权限检查。

创建会话时保留实际 Runtime、应用上下文、sessionId 和 requestId 的可见结果。继续、等待和处理待答事项时使用同一 Runtime 与原应用上下文。更换 profile 后，不根据智能体名称、平台默认应用或同名会话猜测原目标；使用者可选回原 profile 或显式指定原入口和应用。现有会话历史由 Runtime 持有，CLI 不建立副本。

对话继续等待本轮完成，并区分接纳与完成。普通对话、单次运行和临时文本分别使用原服务的输入规则；CLI 不给前两者套用临时文本的字数限制。请求和响应编号原样传递，不能代用智能体名称格式。运行终态取自关联的 Runtime 事件，完成且没有文字回复时保留空 answer。toolCalls 的每项保留原 callId 和 tool/result 数据 result，包括正文、错误和元数据；history 使用相同回执，凭据仍脱敏。工具失败不改写已完成的轮次终态。提交结果未知时回读原会话或等待原 requestId，不自动重发。待处理审批或问题仍由使用者明确决定；登录、创建定义或订阅不隐式发起对话。

`--wait-timeout` 是从本地输入校验结束、首次网络动作前开始的总预算，覆盖会话创建、流连接、输入 POST 及本轮跟随；每个 HTTP 请求另受 `--timeout` 约束。流与输入提交并行观察，只有关联到本请求、输入及本轮终态的事件才能先于迟到回执完成。预算到期或断流时，已尝试提交的输入保留结果未知及原标识；本地中止连接不调用服务端取消入口。

## 实施归属与验收

skills-hub 修改 CLI 源码、构建结果及完整 Skill 的连接和智能体使用知识。xrain-harness 按本人身份合同增加只读入口并维护对应契约。平台继续负责登录、本人资格与应用准入；本方案不要求平台新增 Runtime 登记或执行转发。正式产品和运行事实仍由各责任项目持有。

交付需验证：

1. 在独立安装的 Skill 中，从 profile 配置、正式登录和 `whoami --agent` 进入智能体目录；不用开发配置文件或另写脚本取得凭据。
2. 使用有管理权限的身份完成定义创建、配置、启用及回读。使用有订阅权限的实际身份申请并按现有策略取得结果。应用选用和个人订阅分别验证，不互相代替。
3. 在选定 Runtime 和身份下发起真实对话、继续同一会话并回读历史。确认返回的 sessionId、requestId 和完成结果；一次普通文本成功不代替工具或业务写入结果。
4. 覆盖重新登录保留同目标配置、profile 切换、单次覆盖、个人与应用上下文、缺失接口、身份不一致、未配置入口和服务不可用。保留原有平台命令及既有 `--runtime` 用法。
5. 使用临时或已授权环境和既有受管身份验证。保留既有账号、定义、订阅、会话和工作区；需要写入时按实际授权与环境合同操作。

对话、登录及身份入口的源码测试只能证明对应实现；真实登录与实际 Runtime 消费证据另行记录。构建、方案或本机隔离测试不证明其他部署已经更新。

## 平台设置与定义配置管理

Runtime 持有定义、版本、目录、工具和保存校验。CLI 使用同一领域接口，取消定义输入、合并保存及文件导入的固定字节准入，不修改服务环境、内部表或身份。XRain 已移除定义大小设置页及对应 Host、租户接口；遗留 Setting 不再被新版 Runtime 查询。

### Host 身份

Host 使用显式 auth login --scope host --native 和已有账号。密码只从 stdin 读取；会话按服务器、作用域及空租户匹配。切换目标后不复用旧 Runtime 或应用关联。Host OAuth 未接入，身份诊断继续使用当前身份接口。已退役的 host settings agent-definition-limit 命令不发请求。

### 定义读取、保存与文件互通

agent definition limits 仅在明确查询时读取 Runtime 声明。maxDefinitionBytes: null 表示目标不设定义保存字节门槛，正数字保留旧版本声明；创建、更新、导入和启停均不依赖该查询。缺失接口、413、鉴权失败、服务故障或无效响应保留原错误，不猜默认值或重放写入。

摘要列表不下载完整工作要求，单条读取和导出不使用通用 32 MiB 响应门槛。保存回执仍核对原 ID、下一版本和启用状态。丢失或无效回执保持 outcome_unknown，要求读取同一 ID 和版本后决定下一步。启停只提交 agentId、revision、enabled。

直接目录选项转成 workspaceChange；不修改时提交 keep。更新省略字段保留原值，原生工具的省略、null、空数组分别表示保留、恢复继承、明确不使用。模型、工具、目录、对象、侧栏和字段资格仍由 Runtime 与业务提供者核验。

export/import 使用 [Workforce 版本 1 文件合同](../../../xrain-workforce/文档/项目/项目_XRAIN_WORKFORCE/技术设计/DOC-0017-智能体定义与工作区.md#定义与接口)，区别于更新补丁和 Runtime 存储。新建默认停用；更新要求明确版本并保留目标启用状态。目录跨环境无法确认时保留原值并提示。导入不复制目录、身份、订阅、应用选用或员工关系。完整工具说明、schema、推荐问题和有序字段均保留，结构、标识和当前授权继续校验。

`import --create --agent-id <ID>` 原子创建已核对的固定 ID，不先保存空定义；与 `--expected-revision` 互斥，已存在时返回冲突。`--workspace-path <目录> --preset <模式>` 在同一次导入中明确映射目标机器已有目录；省略时沿用交换文件的目录确认和保留语义。`--check` 只调用声明 `supportsDefinitionValidation` 的 Runtime `/validate`，按完整保存请求检查修订、授权、目录、模式、模型配置及当前工具目录，不保存定义、登记目录或创建会话。较旧 Runtime 缺能力时明确返回 `unsupported_runtime`，不尝试保存代替检查。检查通过不预留版本，也不证明模型答复或业务执行成功。

项目常用入口为 `agent definition prepare --file`。CLI 从当前应用资格中的默认或唯一选用解析稳定 ID，从 Runtime 读取当前 revision，并将文件的登记工作区引用映射到目标 Runtime 的实际目录，生成并完整校验请求，不要求成员抄写环境字段。应用上下文优先取所选连接，未配置时取 Runtime options 声明的应用。首次创建保持停用，明确 `--enable` 时在保存回执后启用；已有内容不同需明确 `--update`，内容相同保持版本。保存前重新读取平台选用，变化或版本冲突保留原状态，不创建新身份、改平台选用或自动重放。工作区文件继续由既有交付步骤准备，不引入文件自动合并或新准入机制。

文件中的 `nativeTools: null` 仅在 Runtime 声明恢复继承能力时转成明确重置请求，否则保留目标选择并提示，与页面语义一致。`resultReference` 等业务工具配置保留并按其类型检查，最终由 Runtime 与业务目录核对完整描述；不删字段来适配旧制品。

Workforce 持有交换格式和合成文件样本，完整 Skill 随附同一字节的样本。双方分别验证转换，不引入交换格式 SDK 或复制 Runtime 存储目录。

### 个人设置与交付

个人偏好使用现有 USER 接口，只操作当前租户中的本人发送快捷键和未读角标，不接受其他人或任意全局键。接口没有条件写入或跨设置事务；仅当接口明确返回 `platform.tenant_user_setting.not_found` 时记录未配置，普通 404 等接口失败直接报告。订阅、策略及应用选用沿原领域命令，profile 只保存连接，batch 失败不撤销此前写入。

定向验证覆盖完整 UTF-8 输入、文件和 stdin、长定义读取导出、显式版本、目录保留、无效输入不发请求、旧服务拒绝及未知结果不重发。skills-hub 维护源码、bundle 和完整 Skill，更新后比较选定消费目录。实际验收复用获准环境及原身份，保留定义、会话、工作区和使用关系；隔离检查不证明共享服务或模型已消费。

## 用户业务入口

本人企业切换使用原平台租户切换接口。CLI 先核对源会话，再验证返回会话仍是同一主体及目标租户。成功后选中目标 profile，只复用与目标绑定一致的 Runtime 和应用设置；指定其他目标 profile 时保留源登录。本人 Token 签发使用原账号接口及已保存登录，只接收原 endTimeUtc，并将凭据排他保存到受保护文件。该接口没有客户端请求键，回执丢失不重发。

普通成员资料查询消费平台窄目录，Host 成员列表保留原 isActive 筛选。员工关联选项和已知成员核验分别使用 Runtime 的专用窄读取，不以完整定义管理目录替代。应用包能力和提交候选消费原平台能力及审核目录。

Workforce 命令覆盖群治理、原消息及本人附件、个人在线组合、实际可用应用、Task 和计划任务。宿主固定 CLI 别名复用原处理器；成员身份和应用准入逐次验证。预期租户、本人和应用头只用于检测目标变化，不能选择执行人。附件不使用平台服务 Token 代替本人文件与消息权限。

Workforce 的助手目录、订阅和取消使用宿主原工作台处理器，执行地址由宿主持有。计划历史使用原 before 游标分页，单次运行可按原 scheduleId/runId 查询。顾客接待的订阅与取消复用原客户端适配和平台个人订阅，不复制应用选用状态。

Workforce 的无参数 POST 命令提交空 JSON 对象，满足原会话取消与计划运行取消处理器的请求格式。取消接收后仍按原会话或运行查询终态；已结束、无权限和回执未知保留原含义，未知结果不重发，也不继续 batch。

应用目录向 CLI 返回应用声明的普通打开入口；这些地址仍需要浏览器自己的登录和准入。CLI 不取得浏览器会话专用地址，导航和本人功能组合的准入检查也不构造页面地址。浏览器继续按当前会话取得自己的入口。

独立邮箱和顾客接待使用显式 `--app-url` 和各自真实 applicationId。CLI 将同一已保存的平台成员会话交给该应用，在应用内完成原邮件 AI 协助、明确保存新草稿，或实际顾客资料和关联对话操作。接待默认来源为 retail-assistant；复用与新建均由原记录对话入口决定。Runtime 地址由应用持有，不要求用户为这两个应用另行拼接通用聊天。

平台和独立邮箱的草稿入口共享回执检查。Saved 和非空 internetMessageId 确认已保存，reference 可空，提供时核对原账号。原服务明确的 `email_draft_outcome_unknown` 保留未知结果，即使其 HTTP 状态是 409；其他冲突和拒绝按原含义报告。未知结果停止 batch，沿原邮箱查询恢复，不自动再次保存。

平台个人邮箱和独立邮箱应用分别提供 capabilities 查询。CLI 读取各自实际服务的当前限额，不复制固定业务限额；独立邮箱的准入和预期身份校验仍由原应用完成。顾客接待助手目录只接受原 search、page，每页固定 20 项。

记录集合写入按原 allOrNone 区分记录数组、空删除回执与逐条结果。CLI 核对输入数量、索引和已知记录 ID；逐条结果还须确认 committed。回执缺失、错位或尚未提交时保留原结果为未知并停止 batch，不用缺少明确失败项推断全部成功。

`auth tenants` 读取平台的本人企业列表，不修改本地选择；Host 数据库浏览消费原受控数据源 API。独立市场公开读取可匿名进行，写入和本人发布历史仍需独立市场登录。账号绑定和企业代登录通过原浏览器页面完成；CLI 仅返回或打开页面及预期身份，不持有代登录凭据，不把页面打开当成操作完成。
