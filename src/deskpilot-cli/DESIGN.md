本文是 DeskPilot 新实现与迁移的唯一设计入口。Python 工具、安装入口与完整 Skill 已在本仓实现；Windows 10、Ubuntu 22.04 GNOME/X11 和下述 GitHub 托管 macOS 组合已有独立目录操作证据。Wayland Portal 未实现，首次人工授权、物理设备和未知消费者不能从托管桌面推断。实际进度由验收表区分；旧仓尚未退役，不在 window10GUI 建立另一套实现。

## 交付决定

| 用户结果 | 已核实的现状 | 本方案的改变 | 用户入口与责任 | 状态或数据影响 |
|---|---|---|---|---|
| 像 xrain-cli 一样由 Skills Hub 交付 | XRain 源码在 `src/xrain-cli/`，构建制品在完整 Skill 目录，独立复制测试不依赖源码仓 | 新源码放 `src/deskpilot-cli/`，完整交付目录放 `skills/shzw-deskpilot-cli/` | skills-hub 同时拥有源码、构建、使用知识和维护；宿主安装完整目录 | 不新增业务数据库 |
| 彻底移除 .NET | Windows 核心依赖 .NET 10、UIA、Win32、WinForms 和 Windows OCR | 已确定用 Python 重写核心，通过各系统原生接口执行；最终运行链路不调用旧 exe、CLR 或 .NET 自举程序 | CLI 提供统一命令与 JSON/NDJSON；Python 为用户已确认的实现语言 | 原会话引用本就短期有效，不迁移进程内 ID |
| Windows、macOS、Linux 使用同一 Skill | 现有实现只承诺 Windows 10 x64 | 一个入口按能力探测选择平台实现，浏览器与通用协议共用 | Agent 使用同一方法；平台后端负责真实系统差异 | 平台权限由系统持有；Chrome profile 和显式消息状态仍在用户侧 |
| 用户安装后可以独立使用 | 旧便携包引用包外 `bin/win-agent.exe`；新完整 Skill 已能在独立目录构建 | 完整 Skill 自带本项目源码、安装/构建脚本、固定依赖文件与模型；客户端从这些文件构建程序并注册命令 | 从安装后的 Skill 启动；安装脚本完成本地构建与用户级 PATH 接入，不调用包管理器 | 只新增构建缓存和安装归属记录；业务状态留在调用方目录 |
| 保留可用能力并修正职责 | 旧仓同时包含通用执行、使用方法、应用操作与具体群聊/演示业务规则 | 按职责重新组织：操作知识随 Skill，确定性工具维护为代码，具体业务策略不进入通用交付 | Agent 读取按需参考作判断，工具执行明确请求；业务规则归对应业务 Skill 或当前任务 | 通用工具不建立群聊业务状态；实际保留消费者的状态单独核对 |
| 完成后归档当前项目 | window10GUI 仍是现有实现来源，本机旧入口仍存在 | 在完整 Skill 独立使用和保留消费者切换通过后，将旧仓库设为只读历史来源 | 用户以后从 skills-hub 获取与更新 | 不删除用户 profile、消息状态或已安装环境来完成归档 |

已确认 Python、三平台、无 .NET、源码与用户交付均进入 skills-hub，以及迁移完成后归档旧项目。完整 Skill 包含用户端构建所需内容，客户端完成本地构建、初始化和 PATH 接入，不使用包管理器。用户已明确要求实施，并授权在原共享 dev 主机准备图形桌面完成 Linux 验证；这不授权删除保留数据或用未验证平台结果提前归档旧仓。

应用特定的机械步骤也可以是代码，例如在已经明确的窗口和消息上打开菜单、定位唯一“引用”项并回读预览；是否需要引用、选择哪条消息、是否允许发送和发送什么，由上层任务与授权决定。任何发送工具只执行调用方明确提供的目标与正文，不能自行从群聊参与规则生成发送意图。调用方要求的操作对象绑定、正文一致性、旧引用拒绝和结果不明时不重放，仍属于工具正确性。

## 对齐 xrain-cli 的具体做法

沿用 [Skills Hub 仓库入口](../../AGENTS.md) 的 `src/` 与 `skills/shzw-*` 分工。XRain 的 [构建入口](../../tools/build.mjs) 在维护端打包程序；[安装脚本](../../skills/shzw-xrain-cli/scripts/install-cli.mjs) 在客户端注册短命令，目录不在 PATH 时返回提示，目前不会自动构建程序或写入 PATH。[独立安装测试](../../tests/installed.test.mjs) 在无源码仓和 `node_modules` 的临时目录验证实际命令。

DeskPilot 复用完整目录交付和客户端命令注册方式，并按本次明确要求增加客户端本地构建及自动接入用户级 PATH。维护端交付可构建源码与完整资源，客户端使用自身 Python 解释器完成构建和初始化。使用者无需克隆源码仓库、手动安装 Python 包或编写构建命令。

桌面接口和 OCR 仍涉及原生库。完整交付必须同时满足“本项目源码齐全”和“当前平台运行依赖齐全”；项目 Python 源码不能替代缺失的原生库。固定第三方代码、对应平台二进制、必要模型与许可随 Skill 提供，客户端不得临时通过包管理器补装或查询最新版本。

Skill 从默认分支获取，主动更新时替换完整目录。不建立独立 Skill 版本目录、发布标签或版本目录服务。依赖文件清单、Python ABI 和模型版本属于构建输入，不改变此分发规则。

## 语言与运行方式

采用 **Python 核心与 Python 客户端安装脚本**。首次入口只依赖受支持的 CPython 标准库；Python 可由用户客户端提供，也可使用机器已有的官方解释器。缺少适配解释器时说明前置条件，不通过包管理器安装 Python。支持的 Python 版本、平台与 CPU 架构须与随包原生文件一起核定。

Windows 通过 UIA/Win32 绑定操作控件；macOS 通过系统辅助功能及图形接口执行；Linux 对接 AT-SPI、D-Bus 和桌面协议。优先使用系统接口及标准库能够完成的调用；需要 PyObjC、UIA 绑定或 OCR 引擎等第三方实现时，先证明其固定文件可以随 Skill 分发并独立加载，再纳入交付。

客户端安装脚本从随包源码构建应用。纯 Python 部分使用标准库 `zipapp` 生成应用归档；原生扩展及其共享库按平台和 Python ABI 选择，并放在可实际加载的文件目录。原生扩展不能直接从 `.pyz` 内加载。第三方原生二进制由维护端准备并随包交付，不要求使用者编译这些库。

客户端不安装或调用 pip、uv、conda、npm、brew、apt，也不连接软件包索引。本地安装脚本只处理随包的确定文件，不实现依赖解析器、下载器或另一个包管理器。完整 Skill 已取得且系统前置条件满足后，本地构建、初始化、命令注册和桌面/OCR 操作均可离线完成；访问目标网站所需网络另行处理。

现有 Python 辅助脚本按前述职责逐函数筛选，需要的确定性操作并入同一 Python 工具包。原 Node.js Flow 不作为另一套执行器随 Skill 迁入；批处理、等待、结果检查和向 Agent 返回偏差由 Python 工具统一提供。dsh 等宿主通过公开进程协议接入，适配在实际消费者的源码归属中完成，不成为 DeskPilot 的内置子项目。语言选择已确定。

核心不通过 `pythonnet`、PowerShell `Add-Type` 或旧 `win-agent.exe` 取得桌面能力。其他 Skills 的既有运行要求不属于本次移除范围，例如 XRain 应用包校验器的 .NET 依赖不由本方案变更。

## 源码与交付目录

仓库保留一个工具源码包和一个完整 Skill。前者维护代码，后者交付使用知识、生成的工具源码和实际运行资源。三平台差异在同一 Python 包内部处理。

```text
skills-hub/
  src/deskpilot-cli/                   代码唯一维护源
    DESIGN.md                         本方案，供维护者评审
    install.py                        唯一本机安装入口的源码
    deskpilot/                        一个可执行 Python 包
      __main__.py                     命令入口
      cli.py                          argv、NDJSON 与错误返回
      session.py                      会话、引用、批处理、等待和取消
      browser.py                      Chrome/CDP 操作
      screen.py                       截图、OCR 与定位证据
      platforms/                      Windows、macOS、Linux 系统实现
    tests/                            Python 定向测试和本地夹具

  skills/shzw-deskpilot-cli/           整体安装与交付的唯一边界
    SKILL.md                          简短方法与参考路由
    agents/openai.yaml                现有技能目录要求的展示信息
    references/                       安装、命令、桌面、浏览器等使用知识
    scripts/
      install.py                      从 src 生成；构建、注册与移除入口
      deskpilot/                      从 src 生成的完整 Python 包源码
    vendor/                           实际采用的第三方代码、原生文件和许可
      manifest.json                   一份依赖文件、平台/ABI、来源与摘要清单
    assets/                           实际采用的离线 OCR 模型

  tools/build.mjs                     扩展现有入口，同步上述两项代码副本
  tests/deskpilot-installed.test.mjs   接入现有检查，验证独立 Skill 的使用
```

维护关系只有两条：

1. 工具代码只改 `src/deskpilot-cli/install.py` 和 `src/deskpilot-cli/deskpilot/`；维护端将它们确定性同步到 Skill 的 `scripts/`。后者是交付副本，不是第二个编写源。维护端不为 Python 再建立独立打包工程，也不生成用户机器的运行环境。
2. 使用知识直接改 Skill 的 `SKILL.md`、`references/`；第三方文件、模型和许可直接在完整 Skill 中维护。它们不再在 `src/` 放第二套。参考按实际使用需要增加专题，不预建业务目录或复制旧项目文档树。

源码包内先按上述少量模块组织；文件过大或存在独立平台职责时再拆分。不预设 `operations/`、业务 adapters、Flow 执行子项目或 dsh 插件子项目。具体应用的操作知识可以成为参考专题，确定性函数按实际职责进入现有模块。

客户端只需取得 `skills/shzw-deskpilot-cli/`。`scripts/install.py` 从同目录下的 `deskpilot/` 构建本机应用归档，按 `vendor/manifest.json` 选择随包原生文件，并注册用户命令和 PATH；更新及 `--uninstall` 也复用此入口。构建是安装过程中的函数，不另设 `build.py`；后续执行使用已返回的命令路径，不另设 `run.py`。CLI 直接由包内 `__main__.py` 启动。

本机应用归档、原生文件准备结果、安装记录和命令入口放在用户可写目录；原 Skill 可以只读。它们属于客户端派生结果，不加入源码或 Skill 目录。浏览器 profile、业务文件与聊天状态继续属于调用方。

`vendor/manifest.json` 只维护一份，列出实际随包依赖及其传递依赖的文件、来源、许可、平台、架构、Python ABI 和摘要。代码同步检查与它共用实际输入，不再维护另一份依赖清单。没有匹配原生文件或许可不允许交付时，该组合不能标为可用；客户端不依靠开发机器已有包或联网补装。

独立安装验证只复制完整 Skill，从另一个工作目录完成构建与调用，不提供 `src/`、旧仓库或维护者固定路径。对应的 [独立安装测试](../../tests/deskpilot-installed.test.mjs) 已接入仓库检查；原生交互验证按平台显式执行。

skills-hub 没有 `文档/WORKSPACE_STRUCTURE.md`，本文以 `Kind: Decision` 放在目标源码旁，由根 AGENTS 和 README 路由。可恢复的实施进度按仓库入口在 Workforce 同一个活动登记，不复制旧仓控制面。

## 用户如何使用

### Android 模拟器输入与确认

Windows 上，已选择的本机 Android Emulator 窗口可通过其端口和 AVD 名称与本机已有的 ADB 交叉核对。`android.observe` 读取设备辅助功能树，`android.click` 按当前节点范围派发点击；其他无关的可操作节点与点击中心重叠时保守拒绝，不推断前后层次。树未暴露的覆盖仍须结合画面判断，点击是否产生预期效果由调用方观察确认。`android.swipe` 以当前可滚动节点和该节点内明确的设备坐标派发手势，拒绝与其他可操作节点重叠的端点；需重新观察滚动结果。`android.set_value` 只操作已聚焦的非密码编辑框，派发后回读完整值。当前按键通道支持最多 128 个可打印 ASCII 字符，不支持的文本在输入前返回明确错误；不能把这项限制外推为原生桌面中文输入不可用。

已授权的本机测试可用 `input.secret` 和本地凭据引用对焦中的 Android 密码框输入，不读取密码值、不自动提交，也不把明文放进请求或子进程参数。密码输入结果须通过后续登录状态判断。窗口、设备或控件身份变化时拒绝派发；派发后焦点变化、取消或确认失败时返回结果未知，调用方先观察再决定下一步。此能力依赖设备可访问的辅助功能节点和兼容的 Android 输入命令，不安装 SDK、重启设备或修改设备配置。

使用者取得 `skills/shzw-deskpilot-cli/` 的完整目录后，由宿主发现 `$shzw-deskpilot-cli`。发现描述应覆盖桌面与浏览器 GUI 目标，不要求用户先说“CLI”，也不把固定微信场景作为普通网页请求的默认流程。

首次使用由客户端调用 Skill 自带的 `install.py`，完成本机环境识别、本地构建、无桌面副作用的启动检查、命令注册和用户级 PATH 接入。系统辅助功能、屏幕访问等权限按平台实际要求由用户授予。构建或启动失败时保留原可用安装，不发送桌面业务请求，也不通过重放业务请求恢复。

以下命令已经实现；平台是否可用仍以实际诊断和验收为准。`<skill目录>` 由宿主提供的安装路径或 `resourceBase.path` 解析：

```text
python "<skill目录>/scripts/install.py" --json
deskpilot --help
deskpilot doctor --format json
deskpilot exec --stdin --format ndjson
```

示例中的 `python` 表示客户端已识别的受支持解释器，实际启动记录其绝对路径。安装脚本返回构建结果、短命令绝对路径、PATH 登记结果和当前进程是否能解析该命令。当前宿主尚未继承新 PATH 时，直接使用返回的命令绝对路径；不能要求每轮任务重装工具。

### 客户端构建与 PATH 行为

1. 从安装脚本自身路径解析完整 Skill，核对 Python 版本、平台、架构及随包文件。安装器自身仅使用标准库，不能先导入尚未就绪的桌面/OCR 库。
2. 在当前用户可写目录，从随包源码生成应用归档并准备当前平台的原生文件与模型路径。执行无桌面副作用的协议启动检查，成功后才注册新入口；失败时保留旧构建和错误信息。
3. 在当前用户命令目录生成 `deskpilot.cmd`（Windows）或 `deskpilot`（macOS/Linux）。启动脚本使用已核实的解释器与运行目录，不依赖调用时的工作目录。
4. 将命令目录加入用户级 PATH，保留原有项并去重。Windows 使用用户环境注册表与系统通知；macOS/Linux 更新已识别、受支持 shell 的用户配置，以带归属标记的片段管理。不得覆盖其他配置或写入系统级 PATH。
5. 返回明确结果。持久 PATH 写入成功不等于已运行的父进程或终端已获得新环境；客户端可立即用绝对路径调用，新终端或重新启动的客户端应能直接执行 `deskpilot`。

安装记录只保存 Skill 来源目录、解释器、构建输入摘要、运行目录、命令入口及 PATH 片段归属。重复安装复用未变化的构建，不重复添加 PATH；源文件更新后重新构建并更新本工具拥有的入口。已有无关同名命令不得覆盖，安装器须返回冲突位置和可用的直接调用路径。

`install.py --uninstall` 只删除本工具拥有的命令、安装记录和所加 PATH 片段；若同一命令目录仍被其他工具使用，则保留该目录的 PATH 项。用户 Chrome profile、消息状态和其他应用配置不属于卸载对象。PATH 写入失败与构建失败分别报告，不能因为程序可由绝对路径运行就宣称 PATH 已配置。

Agent 默认保持一个进程会话，执行“观察 → 已知动作与检查组成短批次 → 读取结果 → 根据新状态继续”。需要重复操作时，由调用方保存参数和步骤并调用同一公开协议；完整场景文件不是首次操作前置条件，Skill 不再额外交付 Node.js Flow 执行器。

Agent 按当前任务读取 `references/` 中对应的使用专题。微信的窗口、引用菜单和语音入口知识限定 Windows 及实际验证过的布局；群聊参与、人设和审批规则由具体业务入口按授权提供。通用安装和启动只准备工具，不打开群聊、创建草稿、发言、启动监控或更新技能。语音转写接受应用原生能力或调用方显式提供的 ASR 工具；没有转写来源时返回不可用，工具不依据转写内容决定回复。

## 保留的行为与平台实现

### 通用协议和执行

保留现有 JSON/NDJSON 请求和响应的关键语义，包括 `id`/`request_id` 配对、session、观察与截图引用、`actions.batch`/`workflow.run`、等待预算和并发取消。旧方法名可先保持，内部实现与平台专有字段分开。新增能力诊断必须能够区分“不支持”“缺少依赖”“缺少权限”“桌面不可交互”，不能统一返回成功或空结果。

元素、窗口和坐标引用继续绑定当前观察。过期引用、窗口身份变化与截图归属无法确认时拒绝执行。批次不是事务，已发出的动作不回滚；`BATCH_OUTCOME_UNKNOWN` 后先观察已发生效果。应用鉴权和高影响动作仍遵循调用方的明确授权，不用控件文字猜测授权。

CLI 不新增模型规划、后台调度服务、MCP Server 或业务数据库。桌面提示、操作轨迹、取消和前台恢复属于现有用户体验，需要逐项迁移；系统无法提供同等行为时返回明确能力状态，不隐瞒为完全对齐。

Windows 状态面板提供可访问的关闭按钮；收起面板也隐藏动作边框，但不取消操作。用户关闭后当前进程不自动重现提示；调用方明确要求必须显示提示时，后续动作报告不可用。提示其余区域与动作边框继续穿透输入，临时截图隐藏与恢复不能撤销用户的关闭选择。

### 浏览器与桌面

继续使用 CDP 处理 Chrome 页面导航、查询、填值、点击与等待。浏览器路径、profile 位置、窗口激活和 target 与系统窗口的绑定转为平台适配，不能只移植 WebSocket 代码就宣称浏览器迁移完成。保留已连接 target、精确 endpoint 失败处理、浏览器与 helper 独立生命周期，以及结果回读。

当前随包 ABI 是 64 位、标准 GIL 的 CPython 3.13，资源清单覆盖 Windows x64、macOS arm64/x64 和 Linux x64。下表分别记录已有证据和未验证组合；建议版本不构成已经完成的兼容声明。

|---|---|---|---|
| Windows | Windows 10 build 19045 x64 已有证据；Windows 11 尚未验证 | comtypes/UIA 与 ctypes/Win32；原生键鼠、截图和窗口管理 | DPI、多屏、瞬态弹层、管理员窗口边界和真实应用仍按实际证据判断 |

Windows 优先使用核对遮挡后的屏幕截图；外来窗口覆盖时，可退回 Windows Graphics Capture 取得单个已核对窗口的帧，并明确标记该帧不包含独立弹窗与覆盖层。按此截图操作时重新检查动作点上方的窗口边界和实际命中，鼠标可穿透的外来覆盖也不自动放行；系统截图保护与无法确认的窗口身份仍阻止截图。仅暴露可编辑 UIA 文本模式的控件在赋值模式不可用且尚未派发时可使用单次键盘替换、焦点检查和回读；多行按键方式须由调用方根据控件行为明确选择，未知结果不重发。

不能用 X11 结果代表 Wayland，也不能把 Ubuntu 一种桌面环境的结果外推为所有 Linux 发行版。未验证组合显示为未验证；缺少真实桌面证据时，该平台不能计入“完成后三平台可用”的归档条件。锁屏、服务会话和安全桌面不在原产品能力内，也不因迁移变成承诺。

### OCR、可见文本与调用方状态

使用可在目标平台交付的离线引擎和固定模型，维护模型来源、版本与许可。先以现有 Tiny 模型行为、文字几何和身份匹配测试比较效果；模型替换必须有相同输入的结果证据，不能仅凭引擎可以启动认定对齐。`Windows.Media.Ocr` 的辅助词框属于平台实现，其他平台没有经过验证的词框时保持空结果及明确来源状态。

区域观察返回可核对来源的文字候选。分组、分页重叠和语音处理如果复用，作为可选确定性辅助工具返回候选与证据，不能把 OCR 的左右位置直接当作真实发送人或完整会话。选择相关内容、拼接一个人的完整意思、决定是否回复、措辞与节奏属于 Agent 和业务 Skill。

通用 CLI 不保存聊天历史、草稿审批、人设、连续发言计数或参与进度。已获授权的操作仍需绑定明确对象和输入，记录是否派发、是否已观察到效果；未知结果先读取现状，不能自动重发。确需跨次操作去重的调用方可显式维护操作标识及结果，不因此引入旧草稿业务状态机。用户内容不进入 Skill、源码、构建输出或测试 fixture。

复用已有 Chrome profile 时核对位置与对应用户。旧消息状态留在原调用方；只有明确保留的消费者需要读取时，才在该消费者侧定义兼容、备份和迁移，不让通用 GUI 接口依赖整套旧格式。退出的业务工作流保留其用户数据，不能通过清空状态冒充迁移成功。跨平台不自动搬运浏览器认证目录，也不自动授予操作系统权限。

## 搜索与观察的消费性能

Windows 默认控件搜索保留按深度和遍历节点上限读取的语义；已观察到准确 `automation_id` 时，可显式选用系统子树精确搜索，避免为无关控件逐项读取属性。该模式的上限约束匹配 ID 的控件，返回截断状态而不猜测唯一性；不提供树的深度或父节点。普通树搜索仍保留原有范围。`require_unique` 可让短批次在匹配缺失、重复或搜索截断时于输入前停止；等待控件消失也不能把截断视为已消失。`observe(include_screenshot=true)` 在一次响应返回树与可信截图，树与画面依次读取，不承诺原子状态。

2026-10-29 在同一个含 240 个额外原生控件的自有窗口交错测量六次，精确查找中位数为修复前 Python 1,033ms、旧 .NET 216ms、本次 Python 436ms。离线 Electron/React 的定位、输入和回读各测五次，分别为 156ms、76ms、94ms，所有样本均核对了页面状态；一次拒绝输入的反例中，旧 .NET 返回已派发但未自动验证，本次实现报告未知且不重发。计时不含模型决策和首次探索，不能代表跨应用成功率。系统 UIA 搜索耗时仍受目标提供程序影响，复杂窗口与旧版仍有差距；模型是否会正确选择新入口也没有独立测量。完整回执在忽略目录 `.local-validation/deskpilot-performance-20261029/`。

## 本机测试凭据与模拟器输入

普通密码输入继续默认拦截。Windows 单独提供 `input.secret`，只在调用方已确认本机开发/测试授权、当前窗口与焦点后，从指定本地 JSON 文件读取受管值；请求、响应和错误不包含该值，也不回读密码控件。原生控件要求系统确认密码焦点；Android 等不透明画面需调用方基于输入前截图确认，系统不能替它证明访客焦点。可选的完整公开键盘映射用于屏幕键盘，不把秘密拆成逐键请求；可选提交点必须来自同一输入前截图。输入或提交均不等于业务成功，失焦及中途失败保留未知结果，不自动重发。

2026-10-29 自有 Windows 原生窗口用随机合成值验证默认拦截、授权输入、未回读和应用侧匹配；自有 Android API 36 模拟器用随机合成值验证屏幕键盘输入和应用侧哈希匹配，没有读取实际凭据。该模拟器在 `hw.keyboard=no` 时普通文本与按键未进入，启用后重新启动实例，两者进入；这不代表所有模拟器均如此，也不授权修改或重启其他实例。自动化反例覆盖缺授权、旧截图、失焦、布局不完整、异常脱敏和不可批量执行。当前只验证 Windows 交互后端；未取得独立模型技能行为测量。

## 构建、检查与完成条件

维护端沿用 skills-hub 的 `npm run build`、`build:check`、`index` 和 `check` 入口。扩展现有代码同步入口，校验完整 Skill 中的固定第三方文件、模型与许可，不改变 XRain 的既有打包结果。这些维护命令不进入用户客户端安装流程。

客户端构建由 Skill 的 `install.py` 内部使用 CPython 标准库完成，不使用打包前端、依赖解析或在线安装。维护端检查 `scripts/install.py`、`scripts/deskpilot/` 与唯一维护源一致，校验 `vendor/manifest.json` 对应文件，并在独立目录实际执行安装脚本。随包文件过期、缺文件、引用逃逸、缺少传递依赖或依赖旧仓库时检查失败。

现有 CI 已覆盖 Ubuntu、Windows、macOS 的 Node 检查。实施时为新核心补 Python 契约与独立安装验证；普通 CI 通过不证明屏幕权限、原生控件和交互桌面可用。真实平台检查属于交付该迁移所需的 Development 验证，本方案不自动建立另一项 SystemTest 或部署任务。

[macOS 桌面工作流](../../.github/workflows/deskpilot-macos.yml)在代码、固定资源或验证入口变化的提交和 PR 上运行，也支持手动执行。仅 Markdown 变化不启动桌面检查。它分别使用 `macos-14`、`macos-15`、`macos-26` 的 arm64 桌面及 `macos-15-intel` 的 x64 桌面；各组合必须独立通过，缺少权限、资源或必要场景时失败。

[验证入口](../../tools/verify-deskpilot-macos.py)复制完整只读 Skill，在隔离用户目录通过安装后的公开进程协议操作真实 AppKit 夹具和独立 Chrome 表单。夹具记录实际文本、按钮结果和滚动视口；测试核对这些结果，不能只按派发回执判定成功。测试同时检查中文、多行、密码和只读拒绝、旧引用、截图与离线 OCR、外来悬浮窗口、可见提示、取消和清理，以及新 zsh 解析、重复安装和卸载。Swift 编译只用于维护端合成夹具，不进入客户端安装。

独立未授权应用使用另一项系统权限身份，验证辅助功能、输入和截图的真实拒绝；测试不修改系统权限数据库。结果、协议及合成画面由 Actions 保留 7 天，结果绑定源码提交、安装摘要和运行镜像。预授权进程的成功不证明普通用户完成首次人工授权；物理外设、多屏、其他缩放及实际业务应用仍按独立证据判断。

## 实施顺序与归档条件

1. 按上述迁移表完成职责取舍和实际消费者核对，移除旧业务策略的默认承诺。在 skills-hub 建立 Python 工具及完整 Skill，固定公开协议与随包依赖。先证明客户端仅凭受支持 Python 和随包文件，能完成本地构建、命令注册与 PATH 接入；同时验证三平台/ABI 文件能独立加载。
2. 在同一 Python 包实现通用协议与 Chrome、Windows 控件、OCR、提示和取消能力；同步整理 Skill 主入口与按需参考。提取必要机械算法，核对实际宿主的新协议接入；不新建 Flow、dsh 或消息业务子项目。
3. 实现并验证 macOS 与 Linux 的平台后端。分别处理 X11、Wayland 和系统权限；证据不足的组合不标成支持。
4. 在实际保留的消费者中验证完整 Skill，补齐安装、PATH、更新/卸载、恢复和模型许可说明。验证工具无需旧人设/审批状态或演示站即可使用；需要应用知识时可由新 Skill 完成任务。更新对应完整目录，由客户端重建并更新命令入口。
5. 核对保留消费者完成、退出项有明确归属、文档与运行资源独立后，在旧仓入口注明新维护地址与使用入口，保留 Git 历史，再归档旧仓。用户数据不随归档删除。

归档条件是迁移实施与消费验证完成，不是本方案完成。当前任务不会设置 GitHub 归档状态、归档聊天、删除 checkout、覆盖 `D:\win-agent`、发布包或修改用户宿主配置。

Python、客户端不使用包管理器、完整源码与依赖随 Skill 交付、客户端本地构建及 PATH 接入均已确认。当前固定资源约 186 MB，来源、原生 ABI、逐文件 SHA-256 与许可位于 `vendor/manifest.json`。Windows、Linux 和托管 macOS 的实际证据按上述范围保留；Wayland、物理设备或其他未验证组合不能用模拟测试或在线补依赖代替。
