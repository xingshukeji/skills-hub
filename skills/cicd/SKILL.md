# CICD

本 skill 是已有 Jenkins 流水线的使用入口。负责确定触发哪个作业、填写其参数、提交一次运行、跟踪并回答结果；获取源码、检查、构建、发布和部署由 Jenkins 流水线完成。

用户只说“触发一下”且上下文没有目标时，询问缺少的项目、操作（仅检查、构建发布或发布部署）和目标环境。已经明确的信息直接使用，不重复确认。用户询问现状或结果时只查询；要求执行时再触发。

## 确定触发什么

从上下文和项目说明找到 Jenkins 入口，查询实际作业及参数，将用户的项目、操作和环境对应到作业。按本次问题需要查询近期构建、归档制品或部署记录；Jenkins 作业列表不能代替目标运行现状。

复用流水线已配置的环境和部署入口。作业接入、源码获取策略、流水线维护及域名证书配置由所属项目负责，使用本 skill 不包含这些改造。

优先使用项目已有、适合本次任务的自动化入口。需要直接调用 Jenkins 时，使用本 skill 的 [jenkins.mjs](scripts/jenkins.mjs)，支持列作业、查看参数、触发和查询。只需 Node.js 22.12+；复制整个 skill 目录即可运行，无需安装 npm 依赖。脚本路径按本次加载的 skill 目录解析为绝对路径：

```text
node "<skill目录>/scripts/jenkins.mjs" jobs --url <Jenkins地址>
node "<skill目录>/scripts/jenkins.mjs" inspect --job <作业名> --url <Jenkins地址>
```

连接地址也可通过 `JENKINS_URL` 提供。凭据由现有凭据管理方式注入进程环境 `JENKINS_USER`、`JENKINS_TOKEN`；不在命令、输出、参数文件或回执中放入秘密。原 PowerShell 的 `CredentialRef` 不由此脚本读取，已有加密凭据仍通过其管理方式取用，勿转换为明文凭据文件。脚本使用 HTTPS，仅本机回环测试允许 HTTP。完整参数见 `--help`；目录下的作业可用 `jobs --job <目录>` 查询。

## 触发并跟踪

用户说“源码已提交，发布新版本”时，按该作业的新版本入口触发，让 Jenkins 获取源码并完成所请求的 CI/CD 流程。仅在作业提供且本次需要时传入分支、提交或版本参数；其余沿用作业约定，不要求用户自行准备构建候选。

如果现场作业固定旧源码且没有采用新版本的入口，应明确告知能力缺口及所属 CI/CD 项目。不要将重跑旧版本描述为发布新版本，也不在本 skill 中用本地 Git 操作、改写 Job 或更新服务器候选补齐流水线。

按用户目标填写作业实际提供的阶段与环境参数；不要把“只检查”的默认参数用于完整发布部署。一个作业已经串联的阶段通过一次触发完成。将非敏感参数保存为 JSON 对象，使用字符串、数值或布尔值：

```text
node "<skill目录>/scripts/jenkins.mjs" trigger --job <作业名> --parameters-file <参数.json> --run-file <回执.json> --url <Jenkins地址>
node "<skill目录>/scripts/jenkins.mjs" status --run-file <回执.json>
```

无参数作业省略 `--parameters-file`。回执放在 skill 目录之外的工作区私有位置，每次触发使用新文件。按同一回执查询直到取得最终结果；查询已有构建可用 `status --job <作业名> --build <构建号> --url <Jenkins地址>`。不要用最新构建代替本次构建。

发送后超时、断线或返回未知状态时，先核对原作业队列和构建记录，再判断是否需要重新触发。脚本不会自动重发请求；队列记录过期时按队列 ID 从近期构建中恢复关联，找不到则保留未知状态。

## 核实结果

从本次运行结果和流水线回执回答：触发了什么、当前状态、实际源码版本、发布制品和部署结果，并提供构建入口。用户要求指定版本或目标时核对是否匹配；需要确认实际运行状态时使用项目已有查询方式。证据缺失或不一致时明确说明。

查询命令成功仅表示查询完成，流水线结果看 `result`。未执行的验证如实说明。

失败时依据现有日志和报告说明失败阶段与原因。触发参数或连接使用问题可在本任务内纠正；流水线和产品缺陷交对应项目处理，不扩展成重建 CI/CD 的任务。
