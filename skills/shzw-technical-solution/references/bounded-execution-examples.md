# Bounded execution examples

- A cross-layer feature with an old UI evaluator still active is split only after the actual path is traced; the evaluator gap belongs to one unit and has an observable acceptance assertion. Parallel consumers do not each patch the common compiler.
- A one-file label fix proceeds directly with proportionate verification; this method does not require a new task, plan, dependency graph or consumer rebuild.
- A failed consumer contract check returns to its owner with a reproducible case; it does not authorize an execution task to create another task or repair unrelated services.
- A verified candidate remains usable when only documentation changes. A changed query contract requires only the affected evidence to be renewed; old results are not silently relabelled as current.
- An actual live build or a newly discovered defect is meaningful progress or waiting. Repeating passed checks without new evidence triggers reassessment, not more tests or premature completion.
