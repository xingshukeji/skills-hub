# 从完整历史提取可复用判断

用于用户明确要求系统回溯项目历史或吸收多次校准的任务。普通局部修复只恢复相关前文，不为每个任务扫描全部聊天。

## 确定范围和读取边界

先从当前项目入口、产品职责、实际依赖与既有交付确定相关项目。区分直接责任项目、承接旧模型或代码的历史项目、仅被随口提到的无关项目。使用保存的 Local 路径；不要因为聊天发生在某仓库，就把其中所有判断都归该产品。

分别枚举可访问的活动与归档聊天，翻完目录分页，记录检索时间和范围。标题和摘要只帮助定位；读取消息正文中的用户决定及必要前后文。工具只能返回近期内容时继续翻页或使用获准的本机历史来源；无法取得的部分明确列出。自动任务输入、转交指令、复贴的助手报告和用户本人确认分别标识，不能混算为独立用户决定。

全量目录检索、正文全文检索、命中上下文精读与逐张图像核验是不同覆盖程度。报告各自范围，不因索引包含所有聊天，就声称已逐条精读所有消息；也不因某个关键词没有命中就认定不存在判断。沿业务动作、身份、状态、消费者和失败原因交叉检索，复用已有专题后继续查相关专业技能。

## 恢复决定而不是复制结论

对采用的条目保留项目、聊天 ID、用户消息日期或可定位标识、业务对象、适用范围和确认状态。精读被引用的原问题、实际选择及后续是否改口。区分：

| 用户行为 | 可作出的判断 |
|---|---|
| 要求修复或继续修复 | 在原范围延续修复授权；不能推导全部旧发现均已确认或已修好 |
| 要求复审、质疑或校准 | 重新核实真实入口和反例，允许撤回误报；不自动取得产品修改权限 |
| 明确确认不是问题或撤回建议 | 在该对象、环境和范围撤回对应结论；独立问题仍单独判断 |
| 提问、假设或要求先理解 | 保持待确认；助手后续同意不能替用户完成决策 |
| 明确改变目标 | 较新的决定替换相同范围中冲突的部分；相邻范围与未冲突要求继续有效 |

发现明显反常的决定时，查其具体对象和后续上下文。若仍有实质疑点，列出原话出处、当前事实、影响和需要核对的选择；不得默默把旧决定“改正确”，也不要把已经解释清楚的局部取舍重新升级成全局疑问。

## 附件、截图和缺失来源

临时文件路径失效不等于原图已经不可恢复。按当前工具允许的来源核对原消息附件、原会话记录或已有保存副本；发现内嵌原始数据时可恢复到忽略的临时目录，并保留原消息关联和内容摘要。不要寻找无关个人资料，也不修改原始历史。能恢复与已经阅读分别记录，重复附件按出现次数与不同内容分别计数。

图像只能证明当时可见状态。标注框表示关注点，不能单独证明用户作了何种业务决定；演示数据、Mock 页面和助手文字不能证明后端持久行为。截图中的口令、客户信息和原始附件不随通用技能提交。非图片附件、外部链接和需要另外身份才能读取的内容分别列出覆盖缺口；没有读取时不根据标题还原内容。

## 放回责任来源并验证

把重复出现的错误决策追到实际规则：是方法缺项、知识过期、入口失配，还是原规则正确但执行未遵循。通用提取方法留在本技能；建模、认证、运行、客户端、测试等判断回到各专业技能。索引只指路，项目契约继续持有当前产品事实。明确可复用条件和反例，不复制客户字段、整段聊天或把历史例外变成普遍规则。

有并行任务时先核对其进度、实际编辑文件及已得证据，避开同文件覆盖；完整目录同步也应保留其他已核实修改。保存本次实际改动前基线，按[行为验证](behavior-verification.md)验证选择、判断和实际结果。作者重放已见案例、运行原项目测试和独立盲测分别说明，不用目录一致、检查数量或一次成功宣称未来稳定。
