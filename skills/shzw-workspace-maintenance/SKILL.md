# 工作空间维护

把工作空间规则放回唯一所有者，使下一次任务从正确入口直接执行。规则、结构契约与命令从用户目标仓库定位，不能从技能安装位置推断。

先恢复这次纠正针对的具体行为和已有授权。讨论、评估与“先理解”保持只读；“请调整”“以后按这个执行”等明确要求覆盖对应治理修改。单次产品验收条件留在产品任务，不因出现“必须”就扩成全局规则。

从产生错误行为的入口追到实际所有者：路由归 AGENTS，授权与任务生命周期归 WorkflowContract，文档位置归 StructureContract，专业执行方法归 skill。技能效果诊断与内容重写交给 `shzw-skill-evolution`；本入口只处理其中确实需要改变的治理关系。

在当前工作空间，Workforce 拥有统一任务入口和共同工作流，skills-hub 拥有技能源码，产品行为、模型、运行命令和 Git 历史仍在责任项目。维护时核对这一分工是否被实际路由消费；不通过复制领域模型、挂载相邻目录或给程序增加文档检查来“统一”。公共使用知识可随技能交付，不能让使用平台能力必须取得私有源码或个人授权文件。

替换冲突规则，不附加一份同义补丁。只追踪这条规则的直接消费者；只有任务分类、登记或恢复确实受影响时才调整活动与工作流。跨项目改动仍归各自仓库，不增加知识注册服务或运行时准入。

用一个应执行和一个不应扩张的相邻场景检查新规则；修复直接引用，运行目标项目文档检查及受影响脚本测试。报告实际改变的默认行为与验证边界，不把结构通过称为后续执行已经改善。
