# 将长期纠偏落实到工作空间规则

本模式处理 AGENTS、文档归属、工作流和任务恢复中的错误默认行为。技能为什么没有起作用、如何改写或合并，由 `shzw-skill-evolution` 负责；产品缺陷留在原业务任务。

## 识别需要改变的规则

从当前要求与必要前文恢复被纠正的行为、已有约定、期望结果和适用范围。用户说“以后”“统一”可能建立长期规则；产品功能里的“必须”通常只是该功能要求，不能扩成全局流程。

只讨论、评估或明确不修改时保持只读。明确要求调整流程，且规则与范围已清楚时，在原授权中完成修改和验证。已有方案后说“请执行”承接该方案；不用再次交付同一建议。只有实质方向或权限未定时才暂停对应部分。

先查旧规则是否已经正确。没有执行好时查入口、冲突与加载；不能靠追加同义句代替修复。一次有依据的反例足以修正规则，不要求用户重复受挫。

## 在唯一所有者修改

| 改变的事实 | 所有者 |
|---|---|
| 进入哪个项目或专业方法 | AGENTS |
| 授权、任务类型、恢复和收口 | WorkflowContract 与对应 Workflow |
| 文档种类、位置和生命周期 | StructureContract |
| 专业任务的判断和执行方法 | 技能源；使用技能进化方法 |
| 产品规则、源码行为或服务操作 | 责任项目的契约、源码与测试或 Runbook |

沿当前例子选择能成立的最小范围：具体场景、同类任务、项目或工作空间。用户明确的长期规则按其范围落实；不能仅凭几个例子生成个人画像或全局偏好库。

替换产生错误行为的规则，移除已被吸收的重复表述。只检查直接依赖；任务分类、登记或恢复未改变时，不改活动与工作流。只有真实可恢复工作才沿现有机制登记，同一结果不新增第二项。

治理入口改变时，按目标工作流确定控制强度和当前计划，不能因治理审查另建审批阶段。普通实现选择与可查事实由执行者处理。跨项目仍由原结果责任人完成，写入归各责任仓库。

## 验证并返回原工作

选择一个应继续执行的场景与一个不应被扩张的相邻场景，检查默认动作、边界和恢复结果。修复直接引用，运行目标项目的文档检查与受影响校验器测试。技能正文实质变化再按技能进化的行为验证处理，不用关键词检查证明模型已改善。

按 WF-0004 收口实际治理结果；仅保留当前规则，不保存每次纠偏过程。若本次是在业务任务中修正方法，随后继续原任务的剩余授权范围。
