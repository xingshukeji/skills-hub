# 建模与数据开发

产品事实：XRain；公共基础设施由 AiInfra 维护，业务差异由目标项目维护。
维护与适用：本专题由 skills-hub 维护，面向公开能力的业务使用；接口、示例与历史实测的原有适用条件继续有效。内部修改由目标项目入口定位源码与测试。

## 从材料确定业务模型

先确定本轮产物：现状盘点按指定源码、包或已安装版本还原；新模型按当前需求设计；只读评审给出差异。三者不能混用。用户只要求另画评审稿时保留原模型和业务实现。

从用户指定的需求、建模表、答疑、展示模板及已确认决定中确定依据。用户指定某份资料优先时，逐项核对它覆盖的范围；不按文件修改时间或示例新旧自行决定优先级。旧实现和上一稿图只证明现状或旧建议，不能反过来替新需求补对象。

用户引用旧稿的对象或字段时，先判断是在确认、质疑、否定还是要求替换。提到旧名称不等于认可旧结构；同一段包含旧建议和纠正时，按纠正后的业务含义与保存粒度重建对应项，不能把被批评的结构标成“已确认”。

对有改动或争议的对象、字段和关系，在当前草稿或工作记录中保留“业务含义 → 原文位置/已确认决定 → 模型位置”的对应。区分直接来源、平台自带能力、必要实现选择与新增业务建议。新增建议须说明谁用、何时产生、如何维护及为何不能复用；未采纳的建议单列，不混入已确认模型。无需为此再建一份长期台账。

先给每个对象写清“一条记录代表什么”。按独立业务事实、查询和维护需要决定是否拆分；页面、功能名称、流程步骤和 AI 理解结果不自动成为对象。同义业务名称可指同一对象；不同对象也可能共享显示名称。先核对含义，再决定合并。新增状态、历史层次或版本维度须有当前业务动作及维护责任，不能从行业惯例补齐。

## 区分三种关系

| 业务含义 | 建模方法 | 需要核对的行为 |
| --- | --- | --- |
| 资料通过业务编码匹配 | 保留材料规定的代码字段；已有关系表继续承载其关系 | 编号作用域、唯一性、批量导入和人工改号后的匹配。不为画连线再加一套 Lookup；需要转换为平台关联时说明收益及单一维护入口 |
| 记录要关联平台中的另一条现有记录 | 使用有真实目标的 Lookup；人员使用适用的 UserRef | 关联是否可空、何时建立、授权和归档/删除后的查询。按实际导航、约束及查询需求判断，不能只凭字段名称选择无约束文本或关联 |
| 保存某一时点实际使用的值 | 按历史保存需求记录当时值 | 区分读取当前资料与还原当时内容；分别判断身份关联和可变属性的历史值是否需要保存 |

图中明确代码匹配与平台关联的区别，并按实际证据标注基数、可空性和包外对象。每条关系分别依据业务需求判断；局部排除某种关联，不代表其他关系也要排除。平台目标和包安装的支持分别按下文核实。

## 保存当时的字段、过程和结果

区分原始输入与系统派生值。需要追溯原始输入时保留其原貌；实际提取、转换或计算的值另按当前消费需求处理。新增派生字段应有本期用途，不能仅因将来可能分析而预先拆分。需要记录执行事实时，保存本次实际使用的值，不用后来的推断补写。

逐项核对已有表单、计算表和展示模板：源列、业务含义、输入/派生/结果、类型、单位、精度和用途。先确定哪些值需要持久保存、哪些可按当前规则派生，再确定保存单元和字段类型。用户已要求独立保存的属性按该粒度建字段，不能仅拆出少量展示项后，把其余属性重新装入内容或快照字段。整体原文和需原样保存的复杂结构可用长文本；视觉分组本身不构成新对象或保存单元。

字段较多或跨材料合并时，用当前草稿中的映射核对“要求保存的属性 → 实际字段及类型 → 读取用途”，再反查无依据的新增项。能提取表头、模型和源码字段集合时，用短脚本比较，语义仍逐项判断。多个要求独立保存的属性指向同一内容字段，不算逐项覆盖；只证明基础表有这些列，也不能证明业务记录保存了当时值。

跨材料合并字段时同时核对含义、单位和用途。列名不同不代表业务含义不同；含义相同的统一映射，不同事实明确命名。核对整块快照与拆分字段是否承担不同的消费或恢复职责；职责重复时合并，确需冗余时明确权威来源、更新时机和一致性处理。

需要保留历史展示时，按要求保存实际使用的配置、必要中间值、结果及解释。展示需求也参与保存决策，不能仅因“不用于筛选”就省略。明确哪些值冻结、哪些仍可修改；创建时间、所有者和变更历史先复用平台能力。独立业务时间或版本有真实语义时再增加。

## 核对公式与待确认问题

按依赖顺序核对输入方向、公式、单位、存储精度和显示精度。用指定依据的完整样例复算，再核对可选项、空值或边界值中与本次改动有关的情况。名称相近但口径不同的中间值与结果分别核对；输入与倒算结果不能互换。显示舍入不自动成为后续计算的输入。

资料有问题时区分影响：错值、漏说明可单列给资料维护者，已明确的模型继续；冲突确实改变输入、字段含义或计算结果时只暂停相关部分。用户改了依据优先级，要重查此前已确认及待确认的受影响项，并修正图、字段映射、公式和实际消费者中的旧结论。

提问前先用材料、已确认决定和平台事实消除可查明的问题。字段同义映射、单位补齐等有充分依据的普通选择直接处理并说明；计数粒度、数据归属或资料无法裁决的公式等实质选择合并呈现。给出证据、推荐项与影响，不把每个字段都变成一次审批，也不能为了少问而猜关键业务规则。

对新建或调整的模型，首次交付前沿一条完整业务记录，按涉及环节核对输入、匹配、计算、保存和后续读取。检查来源字段与展示项有无遗漏、同义项有无重复、关系有无变义、建议有无冒充已确认要求。语法检查和图能打开仅证明表达有效；视觉分组不改变对象或保存粒度。

## 把业务含义变成平台字段

先按[对象自带能力](object-foundation.md)确定平台已有实现，只为独立业务事实新增模型。受保护 User、默认选项和派生权限见[初始化基础](initialized-platform.md)；ERP/CRM 已维护的事实直接[接入原 API](integration.md)。混合模型明确来源系统、租户、记录 ID 和可编辑方。

例如设备、维修申请和处理记录是否拆分，取决于独立查询、多次处理与追溯需求。下面是常见类型；完整能力与传输格式以目标设计标准和字段描述为准。

| 业务数据 | 字段选择与语义 |
| --- | --- |
| 名称、编号 | `Text`，明确长度；业务号与标准 id 分开，编号生成与唯一性按目标实际支持的合同实现 |
| 说明、原文、复杂结构快照 | `LongText`；按实际录入、显示、计算、筛选、关联或授权需求判断属性是否需要独立字段 |
| 数量、度量、金额 | `Number`、`Decimal`、`Money`；单位、精度与舍入属于业务含义，读取目标字段描述确定传输方式 |
| 日期或发生时刻 | `Date` 表达日历日期；`DateTime` 按目标时间格式约定表达时刻，不把日期自动补成某时区午夜 |
| 开关 | `Boolean`，区分 false 与未知/未填写 |
| 固定业务选项 | `Picklist`、`MultiPicklist`，绑定选项集；显示 label，保存 value |
| 关联另一业务对象 | `Lookup`，声明真实目标对象；一对多通常由子对象引用父对象表达 |
| 关联人员 | `UserRef` 指向平台受保护 User；选择目标租户的合法候选，人员档案与登录身份可以有不同用途 |

Number/Decimal/Money 按当前协议传精确文本；算法或外部接口另行转换，避免浮点精度损失。Date 保存日历日期，DateTime 按[时间合同](regional-context.md)传时刻。选项保存 value、展示 label。

`presentation` 只控制 editor/cell/detail，不改变值或授权；记录类型范围还需业务端消费与校验，见[元数据与前端](metadata-and-ui.md)。多对多有独立属性或历史时可建中间对象；跨包/跨应用引用按目标支持范围处理。

## 元数据、记录与资源包

`BizObject/BizField` 声明模型，记录 API 保存实例。模型通过设计入口或资源包维护；包内 values 不是管理 HTTP 请求。包管理的模型沿用包源码或受支持扩展方式。

包源码的基本结构是：

```text
packageId, namespace, label, versionId, version, records
records 中每项：{ id, kind, values }
```

以下资源关系说明字段如何引用对象或选项集：

```text
BizObject ← BizField.entityDefinitionId
BizPicklist ← BizPicklistItem.refPicklistId
BizField.valuePicklistId → BizPicklist
BizField.targetEntityDefinitionId → 目标 BizObject
```

对象 API 名如 `service__request__c`，字段如 `subject__c`；标签只用于显示。新资源由受支持生成入口分配身份和前缀，已有资源保留稳定身份；元数据 ID 与业务记录前缀分别使用。

字段资源的 values 示例；对象 ID 替换为实际稳定身份：

```json
{
  "entityDefinitionId": "<本应用对象ID>",
  "fieldApiName": "subject__c",
  "label": "申请事项",
  "type": "Text",
  "length": 160,
  "nullable": true
}
```

对象关联由 Lookup 字段元数据表达：设计接口使用 `targetEntityApiName`，包资源使用目标对象的稳定 `targetEntityDefinitionId`；选项字段使用 `valuePicklistId`，无需另建关系表。UserRef 可引用固定 User `00457d0cb59a8281762b`，见[初始化基础](initialized-platform.md)。包外 Lookup 须分别核对目标身份、租户有效定义和包安装预检；不能把包预检限制说成平台没有元数据关联能力。实际限制与离线检查见[应用包编写说明](https://github.com/xingshukeji/skills-hub/blob/main/skills/shzw-xrain-app-package/modes/authoring/references/authoring.md)。

跨环境交付沿用包资源身份，改标签不换 API 名。类型、关联目标或必填等约束变化需处理存量值；新增字段明确 nullable 与补数据方式。以实际 effectiveDefinition/deployment 判断生效，结构删除与恢复见[生命周期](lifecycle.md)。

已有 CLI 可用 `app init --namespace <命名空间> --label <名称> --dir <目录>` 生成基础 source.json，`app build --source <source.json> --output <应用.appkg>` 调目标服务构建并校验。HTTP 为 `POST /api/application/v1/packages:build`，body 是原始 source JSON，返回包字节。构建、发布、安装按任务分别执行，无需平台源码或 .NET。

## 读取、查询与保存

复用已认证的 `XRainRuntimeClient`：`query(entityCode, query)`、`get(entityCode, recordId)`、`create(entityCode, values)`、`update(entityCode, recordId, values, options)`、`delete(entityCode, recordId)`。SDK 负责 HTTP 外层封装；方法、返回与错误见[业务 API](business-api.md)。entityCode 取实际对象目录，User 使用 `runtime.User`，不猜别名。

例如查询已存在的维修申请对象：

```json
{
  "page": 1,
  "pageSize": 25,
  "includeTotalCount": true,
  "fields": ["subject__c", "status__c"],
  "filter": {"field": "status__c", "op": "eq", "value": "open"}
}
```

示例字段和 `open` 必须已定义。`businessQueryCapabilities()` 描述类型、运算符与值模式；条件用 `{field, op, value}` 和非空 and/or 组，关联路径也受目标对象/字段授权。

列表取 records 和请求的 totalCount；统计、批量和导出见[数据操作](data-operations.md)。选项、引用候选与视图使用[元数据与前端](metadata-and-ui.md)的消费方式，页面追加条件应与原视图条件组合。

多查询 queryBatch 最多 8 项，按请求顺序返回；任一失败则整体失败。HTTP 包装与 SDK 解包差异见业务 API；它不提供跨系统 join。

条件更新使用 `client.update(entityCode, recordId, values, {expectedValues})`。HTTP 示例表示仅在状态仍为 open 时关闭：

```json
{
  "values": {"status__c": "closed"},
  "expectedValues": {"status__c": "open"}
}
```

旧值不符返回 409、`platform.data.concurrency_conflict`；保留输入并重读。把本次决策依赖的字段都纳入条件，仅检查状态不能检测所有修改。业务权限与状态规则仍由对应入口执行。

创建超时先按稳定业务身份确认结果再重试。字段变更以目标 describe、相应角色的读写和旧记录表现确认；例如新增功率字段需同时落实单位、有效模型、展示和字段授权。
