# 从平台已有能力开始建模

产品事实：XRain；公共基础设施由 AiInfra 维护，业务差异由目标项目维护。
维护与适用：本专题由 skills-hub 维护，面向公开能力的业务使用；接口、示例与历史实测的原有适用条件继续有效。内部修改由目标项目入口定位源码与测试。

建模前区分平台默认行为、需配置/接入的能力和新增业务逻辑，避免重建已有身份、授权、审计、查询与生命周期机制。

以下普通自定义对象行为已实测；已有对象、受保护对象和包资源仍读有效描述。详见[验证范围](api-verification.md)。

## 新建对象已有的 11 个系统字段

| 标准字段 | 已承担的含义 | 业务建模时如何使用 |
| --- | --- | --- |
| `id` | 平台分配的稳定记录身份 | 关联与接口用 recordId；业务单号含独立规则时另设字段 |
| `ownerId` | 标准记录所有者，参与记录范围和交接 | 普通创建按实际执行者初始化；语义一致的“归谁所有”直接复用，交接走 Owner 转移 |
| `createdById`、`createdAt` | 谁在何时创建 | 平台自动维护；代客户提交时，客户申请人是另一个业务事实 |
| `updatedById`、`updatedAt` | 最后修改者与修改时刻 | 平台自动更新；不把最后修改时间当作审批时间或完成时间 |
| `isDeleted`、`deletedById`、`deletedAt` | 软删除状态及操作者、时刻 | 普通查询排除已删记录；支持的对象使用回收站恢复 |
| `externalId`、`externalSource` | 平台保留的外部来源标识 | 本次返回只读，普通 Runtime 写入被拒绝；接入 ERP 前先确认受支持的写入入口 |

实测这 11 项的 `systemManaged`、`isSystemGenerated` 均为 true，`allowRuntimeCreate`、`allowRuntimeUpdate` 均为 false；值可为空，不在 values 中写入，也无需重复建字段。

租户由可信上下文和服务端隔离，普通对象没有可写 `tenantId`，页面不手写租户筛选。实测标准 Owner/操作者字段为 Text，人员资料用受控成员接口解析，不改为自建 UserRef。

## 将需求映射为配置、接入与业务增量

已有能力仍需相应配置与主体权限：

| 业务需求 | 平台已有实现 | 需要配置或接入 | 仍由业务决定 |
| --- | --- | --- | --- |
| 录入、编辑、列表和详情 | 稳定 ID、CRUD、字段描述及有效访问 | 建业务字段，页面/工具消费描述与记录 API | 业务事实、跨字段规则与操作流程 |
| 本人记录、部门可见、分工授权 | Owner、对象/字段权限、角色与共享规则 | 把实际职责和数据范围配置到平台授权 | 业务负责人是否与 Owner 同义；特殊动作资格 |
| 临时让同事查看或编辑一条记录 | 人工分享、接收人资格及可授予动作 | 消费 capability/recipients/eligibility，按结果提交分享 | 哪个业务动作触发协作；对象 Read 等前提仍须满足 |
| 离岗或职责交接 | 专用 Owner 转移及相应历史 | 选择合格接收人，调用转移入口 | 业务负责人、相关记录和外部系统如何一起交接 |
| 查看谁改了什么 | 创建/更新审计字段、记录变更历史 | 接入历史分页与字段差异展示 | 审批意见、履约结果等独立业务事实另建模型 |
| 联系方式等敏感信息只显示部分 | 字段敏感声明、遮罩、按需读取原值及读取审计 | 配置 isSensitive/maskingPolicy，消费 maskedDisplayValues 和原值入口 | 哪个业务动作确需原值；不另存一份明文供列表使用 |
| 误删后找回 | 普通记录软删除、回收站恢复及删除/恢复历史 | 核对对象支持范围和管理资格，接入恢复入口 | “归档/作废”业务状态，以及恢复后的业务补偿 |
| 必填、选项和引用有效性 | 字段类型、必填/可空、长度精度、选项及目标引用约束 | 声明真实模型，处理服务端校验结果 | 审批前必填、额度关系、跨记录一致性等业务规则 |
| 关联对象及关联列展示 | Lookup/UserRef、引用校验、受支持的关系路径查询 | 声明目标，按权限选择字段与候选 | 多对多关系是否有独立属性；跨系统关联规则 |
| 多人编辑避免覆盖 | expectedValues 条件更新；同次批量请求的事务边界 | 提交本次决策依赖的旧值，处理冲突 | 状态机、请求重入和跨请求/跨系统一致性 |
| 搜索、筛选、排序、总数与汇总 | 授权查询、分页、count/distinct/聚合/导出 | 使用查询能力目录与实际全范围结果 | 指标口径、报表布局；导出 JSON 后的文件生成 |
| 不同岗位的列表和录入呈现 | 类型默认控件、字段呈现、选项、命名视图及条件样式 | 配置视图/覆盖，页面实际消费有效描述 | 专用交互、记录类型选择及流程；视图不代替授权 |
| 保存后执行规则、到期处理 | 对象 Trigger 接入点、编排与 Routine | 定义绑定、执行身份和调度，验证运行链路 | 规则本身、外部副作用、重试及幂等 |
| 金额精度、日期和跨时区协作 | 精确数值协议、时间合同、地区上下文与日期边界解析 | 按字段协议读写并消费用户/业务时区 | 币种、舍入口径、业务日及截止时间的含义 |

配置见[组织协作](organization-and-collaboration.md)、[元数据与前端](metadata-and-ui.md)、[数据操作](data-operations.md)、[自动化](automation.md)和[时间上下文](regional-context.md)；方法与响应查[业务 API](business-api.md)。

## 默认开关不代表业务已经完成

新对象实测 `manualSharingEnabled: true`、`triggersEnabled: true`、`share2AllRoles: false`，视图列表为空。创建/更新自动产生历史；分享仍需资格与操作，Trigger 需定义与绑定，视图需配置，普通成员仍需对象 Read。

敏感配置作用于返回、历史和查询，维护者普通读取也被遮罩；原值按需单独读取，见[元数据与前端](metadata-and-ui.md)。

必填、选项和引用校验直接复用；描述属性不证明公开字段创建入口支持自动编号、任意默认值、唯一约束或公式/汇总引擎，缺少的能力需明确实现。实测超长 Text 被拒绝但返回 500，不能统一按 400 处理。

## 例：员工报修实际需要新增什么

报修单复用 ID、Owner、审计、历史、分享、恢复和分页；新增设备引用、故障、状态及业务时间。维修负责人不同于 Owner 时才增设 UserRef；代报修申请人也不等于 createdById。

配置岗位的动作、字段和记录范围并接入表单/视图。新增逻辑负责状态转换、完工条件和耗材规则；审批或维修明细需要独立查询、授权或结果语义时才另建对象。通知与附件复用[公共服务](shared-services.md)，接好发送资格、文件关系和触发时机。

交付时标明各需求由默认行为、配置/接入还是新增逻辑满足，并验证业务角色的结果。
