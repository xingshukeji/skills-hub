# 二开项目开发与产品职责

项目开发者维护业务内容，并消费产品提供的版本和公开能力。统一目录不表示每个项目都要实现平台构建器、公共宿主或 Runtime。涉及多个产品时，先核对其已交付版本、公开入口和实际消费者，再判断是业务接入、产品能力缺口还是版本尚未交付。

## 修复先确定来源与交付

实施前先判断改变的是项目交付内容、租户配置还是业务记录。项目预置的智能体定义、工作要求、工具清单、默认配置和初始资源，即使通过页面或 CLI 修改，也要定位其源文件或生成器。真实租户绑定、个人设置、凭据和业务数据继续由原环境持有，不因这条要求写进共享默认值。

先查目标实际采用的定义、文件和依赖来源，再决定修改位置。获准的现场调整可以验证假设；验证有效的项目修复须在同次交付中补齐源码、生成或同步逻辑、实际消费依赖及安装升级入口。回读在线定义、重启成功或本机回归通过，只证明各自范围，不能将“以后再固化源码”列为已完成。

以下两例来自销售助手修复中已经发生的遗漏，不将当时的工具数量、包版本或部署方式固定为其他项目的要求。

### 在线定义已改，项目仍会丢失提醒

演示环境通过 CLI 给销售助手加入五个提醒工具，提醒能正常执行；项目的定义文件却仍只选用五个报价工具，同步脚本也只生成这些报价工具。在该实例重复验证可以通过，全新安装却仍没有提醒，后续同步或升级还可能把在线补选的工具删掉。

应把项目确认采用的工具写入源定义，并修正生成、同步和完整导入的处理：业务生成器只更新自己的服务项，保留已选公共工具及既有消息能力。工作要求、侧栏等项目交付定义发生变化时，也沿各自源文件处理。使用标准定义准备或完整发布入口沿原稳定身份更新，保留未要求改变的名称、启停、权限、会话和工作区。分别从空实例和保留旧状态的实例安装或升级，在下一轮实际会话中核对工具可用，再读提醒到期与消息交付回执；已经手工补过的演示实例不能独自证明这两条路径。

### 源码已修，正式依赖仍没有修复

公共组件源码已有修复，本机安装过源码候选包，验证通过；业务项目的正式锁却仍引用不含修复的旧原包。同一版本号也可能对应不同的预览字节，因此只看源码提交、版本号或当前 node_modules 都会漏掉新环境的问题。

正式交付时核对包含修复的原包、来源提交与完整性摘要，并更新消费方依赖锁及构建输入。按该锁在干净目录安装，从生成的交付制品复验；离开构建机后仍须能取得同一原包，不能依赖未随制品提供的本机目录。使用旧版本建立的状态验证正常升级，不能清空状态后把重装称为升级。源码联调仍沿产品支持的开发入口，不因此要求每次本地修改先发布公共包。

仅为本人切换工具、维护租户自有定义或修改业务记录时，沿该资源的管理合同完成；不据此改变项目共享默认配置或扩大其他人的能力。纯审查只指出来源与消费缺口，不取得修复或部署授权。

## 各方职责与开发入口

| 责任方 | 应持有的内容 |
| --- | --- |
| skills-hub | 项目开发知识、CLI 入口、通用源码组装和对现有产品构建及管理接口的调用。平台协议和运行语义由产品定义。 |
| XRain | 平台元数据、包格式、构建、安装、资源引用及目标校验。包间依赖使用实际受支持的协议；项目描述不能自行增加平台未实现的安装保证。 |
| Workforce | 公共宿主、会话接入、插件和客户端 SDK，以及需要复用的宿主应用构建能力。通用能力应由产品提供并验证，业务项目只接入已公开的能力。 |
| Agent Runtime | 智能体定义、工具调用、结果引用、会话及工作区的运行能力。Workforce 和业务应用按已交付版本使用。 |
| 业务项目 | 对象及权限定义、业务函数和其输入输出、智能体业务配置、业务服务、页面及实际装配声明。通用产品实现不因被业务使用而转移到业务项目。 |

业务项目中的构建脚本可能同时包含通用文件处理和项目特有输入。迁移前分别识别公共机制、业务声明及已交付消费者。将可复用机制归产品或共用工具所有者；保留业务逻辑和历史资源身份。只有公共能力具备承接入口并通过原消费者验证后，才移除业务侧原实现。

Workforce 与 Runtime 负责提供可解析的兼容版本组合及其使用条件。业务项目按受支持方式选择组合，并由包管理器锁定实际依赖；不要求每个项目自行推断两个产品的内部协议。

产品能力由产品负责公开接口、兼容版本及行为验证。业务项目验证自己的配置、接入兼容和业务结果；不应为每个项目复制公共宿主或 Runtime 的整套协议模拟测试。已有检查在对应能力及兼容版本得到验证前继续保护真实业务，不能仅为使构建通过而删除。

`project build` 当前只构建平台 `.appkg` 和声明的独立函数输入。智能体定义、工作区文件、宿主扩展和客户端按各自交付入口处理。平台包构建成功不证明宿主依赖、智能体加载或业务操作成功；项目完整交付按实际目标分别验证这些消费者。

业务项目默认消费产品已交付的公开能力；只有当前任务选择从产品源码开发时，才接入产品受支持的源码准备入口。统一开发入口负责串起必要的依赖安装、编译、中间打包、本机依赖安装和启动，继续使用包管理器与产品原有构建器，不要求开发者手工构建或配对公共包。入口每次采用当前选定源码及其兼容声明，不依赖某台电脑的绝对路径、旧临时包或另一次构建的成功记录；安装后核对实际消费的来源。目录布局和命令由责任项目的 Runbook 持有，不把相邻产品源码作为所有业务使用者的前提。

本地依赖准备与向目标平台导入或安装业务资源分别判断授权。源码准备可以在已授权开发任务内完成，不能因为内部生成了 npm 包就要求发布后才能验证；正式制品仍固定已交付依赖，不把同版本预览包当作正式包。
