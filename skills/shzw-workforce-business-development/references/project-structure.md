本文持有统一项目结构、源码与制品边界，以及 skills-hub 的共用工具合同。CLI 已提供项目初始化、组装和平台构建；已有项目的迁移和目标生效按实际项目与授权分别核对。

## 目标与现状

二开项目用一套固定结构维护平台元数据、平台脚本、智能体、业务服务及各端源码。开发者从当前源码按需构建平台应用包，取得项目内被 Git 忽略的待导入原包；同一来源可形成正式交付候选。项目业务差异归项目，通用初始化和组装逻辑归 skills-hub。XRain 的应用包协议、服务端构建、导入和租户安装由 XRain 持有。Workforce 持有公共宿主和客户端；智能体 Runtime 持有定义、会话及运行工作区。skills-hub 维护 CLI 和业务开发技能，不代替这些产品实现或认证。

CLI `project init/assemble/build` 使用本文的项目描述组装并构建；`app init`、`app build` 和 `app import-file` 保留原单文件及已交付原包工作流。构建不等于导入、安装或发布。产品职责和源码开发准备见[项目开发与产品职责](project-development-ownership.md)。

## 统一源码结构

```text
<project>/
├── xrain-project.json                  # 项目与平台包的统一描述
├── platform/                           # 平台元数据和平台脚本源码
│   ├── metadata/
│   │   ├── objects/                    # 对象、字段、视图和选项
│   │   ├── permissions/                # 权限集、权限项和共享规则
│   │   ├── triggers/                   # 对象事件触发定义
│   │   └── integrations/               # 平台连接器、请求和接口
│   ├── functions/<function>/           # 函数定义、代码和适用合同
│   └── orchestrations/<orchestration>/ # 编排定义及版本源码
├── agents/<agent>/                     # 定义、指令和待交付工作区文件
├── backend/                            # 业务服务源码
│   ├── host/                           # 本项目宿主装配和插件注册
│   ├── http/                           # 业务 HTTP 入口
│   ├── tools/                          # 智能体业务工具处理器
│   ├── services/                       # 业务流程和应用服务
│   └── integrations/                  # 平台与外部系统调用
├── clients/                            # 本项目自有客户端
│   ├── web/
│   ├── desktop/
│   ├── android/
│   ├── ios/
│   └── miniprogram/
├── shared/                             # 实际跨组件使用的源码
├── data/
│   ├── seeds/                          # 明确需要交付的初始记录
│   ├── samples/                        # 合成示例和测试数据
│   └── import-templates/               # 空模板及映射说明
├── config/                             # 非秘密配置示例
├── scripts/                            # 项目专有辅助入口
├── tests/
├── README.md
├── .gitignore
├── .artifacts/appkg/                   # 生成的待导入平台包，忽略提交
├── .artifacts/functions/               # 单独交付函数的构建输出，忽略提交
└── .local/                             # 本机配置与临时状态，忽略提交
```

路径含义对所有新二开项目统一。不存在的能力不创建空内容；项目自有 Android 和 iOS 直接位于 `clients/`，共用工程入口按实际构建工具放置，不强制增加 `mobile/`。公共桌面、移动外壳及 Runtime 继续由原产品维护，业务项目只保存自身业务和接入。单项目默认表达一个业务应用；确有多个独立应用时按真实交付关系扩展，不把页面入口或客户端当成多个应用。

已有项目在获准迁移时归入同一结构。迁移保持对象及字段身份、引用、脚本历史、配置和运行数据。不能因套用目录影响并行工作或覆盖在途修改。

## 内容和制品归属

源码是可编辑的项目输入；元数据是其中描述平台资源的一部分。业务数据是用户维护或业务执行产生的记录，和对象、字段定义分别管理。生成文件和运行状态不是第二份源码。

| 内容 | 可编辑来源 | 交付与生效 |
| --- | --- | --- |
| 对象、字段、权限、Trigger、平台连接器等定义 | `platform/metadata/` | 按项目描述生成平台资源记录，构建 `.appkg`，经安装及实际授权生效 |
| 包受管函数与编排 | `platform/functions/`、`platform/orchestrations/` | 将代码及合同组装成平台支持的资源记录；包源码不能在租户应用入口原地编辑 |
| 租户可维护函数 | 同一 `platform/functions/` 结构 | 生成单独函数输入；按受支持管理入口建立来源、创建版本、试算及选版，不假定安装包自动完成 |
| 智能体定义、指令、项目工作区文件 | `agents/` | 通过定义管理和文件交付入口分别提供；文件进入企业制品不等于 Runtime 已加载 |
| 业务服务、工具处理器、页面及客户端 | `backend/`、`clients/` | 分别进入宿主、Web 或原生客户端制品，不作为任意文件放入 `.appkg` |
| 应用预置记录 | `data/seeds/` | 仅项目明确声明且平台协议支持的记录进入包；安装后的业务值按原合同维护 |
| 真实资料和历史业务记录 | 目标业务系统 | 通过获准导入、同步或业务操作维护；不默认进入 Git、源码或应用包 |
| 样例、测试、模板 | `data/samples/`、`tests/`、`data/import-templates/` | 按相应用途使用，默认不进入正式平台包 |
| 非秘密配置示例 | `config/` | 随源码说明配置形状，不冒充实际目标或授予访问权限 |
| 实际租户绑定、凭据与运行状态 | 目标环境或受支持的配置入口 | 不放入项目描述、平台包或可提交源码；本机临时内容留在忽略目录 |

现行 `.appkg` 包含平台合同定义的 manifest 和资源记录，不接收任意源码目录、宿主、客户端或工作区文件。函数与编排进入包时，构建器将可执行源码嵌入对应记录字段，而不是把项目模块作为包内文件。包受管与租户可维护函数可由同一函数源码产生，但各自定义、版本和应用选择分别生效。

## 项目描述与组装合同

`xrain-project.json` 是项目侧编写合同，不是平台包 manifest 或平台 API 输入。第一版由 skills-hub 提供版本化解析器及初始化模板，包含项目描述格式版本、平台包身份与基准版本、明确的包资源条目和需单独交付的租户函数条目。条目显式引用相对于项目根的源码文件；不递归扫描整个仓库猜测包内容。

普通包资源以平台支持的 `{id, kind, values}` 记录为输入。对包含脚本的条目，项目描述同时指定脚本入口、导出名称和适用函数合同；组装器把这些内容写入该记录的 `source` 和 `contractJson`。记录与脚本不能各自维护同一份可编辑源码。租户函数条目使用平台函数管理合同生成独立输入，不伪装成已安装的包资源。平台仍只接收其原有完整源码格式。

第一版项目描述结构如下；尖括号内容由项目替换为符合平台合同的实际值：

```json
{
  "schemaVersion": 1,
  "package": { "packageId": "<稳定包ID>", "namespace": "<命名空间>",
    "label": "<名称>", "baseVersion": "1.0.0", "releaseVersionId": "<正式版本ID>" },
  "records": [
    { "file": "platform/metadata/objects/product.json" },
    {
      "file": "platform/orchestrations/protect/record.json",
      "script": { "mode": "module",
        "file": "platform/orchestrations/protect/index.mjs", "export": "execute" }
    }
  ],
  "recordGenerators": [{ "file": "platform/metadata/resources.mjs", "export": "records", "options": {} }],
  "tenantFunctions": [
    {
      "definition": "platform/functions/quotation/definition.json",
      "script": { "mode": "module",
        "file": "platform/functions/quotation/index.mjs", "export": "execute" },
      "contract": "platform/functions/quotation/contract.json"
    }
  ]
}
```

`records` 的每项引用一个包资源记录；业务对象、字段、Trigger、权限及明确采用的 `data/seeds/` 记录均以此方式声明。版本化源码需要生成一组记录时，可在 `recordGenerators` 显式指定项目内 JavaScript 文件和导出函数；函数接收 `{package, options}` 并返回稳定的记录数组，使用静态项目依赖及 `node:crypto`。构建快照原始模块后执行，不重新编译历史函数文本；不得在生成器中读取环境、网络或运行数据。生成器按受信任项目代码执行，静态导入检查不隔离 Node 全局能力。脚本字段可省略；提供时由 `script` 生成记录的 `values.source`，函数合同由 `contract` 写入 `values.contractJson`。这些字段由外部文件提供时，记录文件不再内嵌同一内容。租户函数的 `definition` 使用管理合同的 `key`、`label`、`isActive` 及可选说明和签名；组装结果补入 `source` 和 `contractJson`。它不携带凭据、租户身份或应用选版，也不是包资源记录；目标函数 ID 由实际管理入口返回。需要随包交付的函数使用 `records` 中的包资源条目和同一脚本结构。

`script.mode=module` 将项目锁定的模块依赖编译为目标资源要求的函数源码。`mode=frozen` 从 JSON 字符串文件恢复已交付版本的完整平台源码，不执行模块编译；冻结条目不需要导出名。JSON 字符串保留原换行和源码字符，避免检出时行尾转换改变旧版本。组装器按资源 kind 输出平台函数表达式或 `execute(ctx)` 入口，不把 Node.js、文件系统或 npm 模块作为平台运行依赖。组装器检查项目描述、文件、重复资源 ID 和同一源码的重复声明；未知条目按实际诊断返回，不静默漏掉资源。平台资源语义和目标执行继续由现有平台校验，不复制一套包协议。项目描述本身不进入最终平台包。

对象、字段、包和其他已交付资源保持原稳定身份。不可变编排版本必须保留已交付的原版本内容；修改产生新的版本记录及身份。旧版本脚本文本可以作为冻结源码直接组装，不能因更新模块打包器而改写其字节。新增版本的编写辅助应更新项目源码，不在普通构建时静默改写历史。

跨包 Lookup 依赖应引用实际公共依赖的稳定对象身份。项目从已交付依赖保留并核实该身份；本地组装不因此要求连接目标租户。目标依赖是否有效由目标安装预检验证。若目标依赖身份不能跨环境稳定表达，由平台或依赖包所有者处理，不为每个租户悄悄重建不同身份的同版本包。

## 从源码构建到导入

统一项目构建入口按以下顺序工作：

1. 读取项目描述和本次工作目录中的源码，包括未提交的修改。
2. 按显式条目组装元数据、适用初始化记录及平台脚本，生成含 `packageId,namespace,label,versionId,version,records` 的完整平台 `source.json`。模块代码使用受支持的构建工具生成平台可执行源码；普通函数、编排和受保护纯函数各自保持原执行合同。
3. 用现有 XRain 服务端构建能力生成原始 `.appkg`，校验返回身份和摘要，并输出到 `.artifacts/appkg/`。构建结果给出本次准确文件路径、版本和源码、文件摘要。
4. 需要单独维护的函数生成对应源码及合同输出。函数管理、创建版本和应用选版沿现有目标入口执行。
5. 用户请求导入时，使用明确的本次原包或指定已交付原包。导入、租户安装、业务开通和原用户使用分别核验；导入既有包时不因存在源码而重建。

`.gitignore` 包含 `/.artifacts/` 和 `/.local/`。每次构建都从当前源码组装；输出采用不覆盖已有文件的名称，命令返回本次路径。失败时报告失败，不将旧包当成本次新包。正式交付的输入快照、原包及构建元信息交由项目的受管制品入口保管，不依赖被忽略的本机目录。本地开发候选应能在源码改变后继续构建。构建工具为新的开发候选生成符合平台合同的候选包版本身份，不修改项目中的正式版本声明、稳定包 ID 或资源 ID。已发布的包版本不可用不同内容覆盖；已发布的编排版本也不可改写。正式版本使用项目明确维护的版本及版本 ID。候选生成规则须覆盖合法 SemVer、重复构建、并行构建和已有版本冲突；冲突时保留平台结果，不能覆盖现有版本或声称已通过目标安装预检。

开发候选以项目的 `baseVersion` 为基础生成合法预发布版本。基准版本没有预发布段时添加 `-dev.<候选标识>`；已有预发布段时追加 `.dev.<候选标识>`，构建元信息保留在末尾。候选标识包含随机值并以字母开头，避免纯数字段的前导零问题；同时生成平台格式的新 `versionId`。生成结果仍须满足平台 SemVer、长度及身份合同。正式构建使用项目明确维护的 `baseVersion` 和 `releaseVersionId`；二者对应已发布内容时不可覆盖不同内容。候选身份只进入本次生成的完整平台源码，不回写项目描述。候选版本不替代包内不可变编排版本：改变已交付编排时仍须在项目源码中新增其版本和身份。

同一次构建以返回的 `versionId` 区分 `.artifacts/appkg/` 中的完整源码、原始包及构建元信息。元信息记录包身份、版本、源码 SHA-256、包 digest、文件 SHA-256、构建服务版本及程序集摘要；可取得 Git 版本时标明提交及是否存在未提交输入。构建过程只清理自己尚未完成的临时输出，保留其他构建及已交付原包。正式交付构建固定全部输入的提交和快照，使用同一原包在不同目标安装，不为每个租户重写包源码。

## skills-hub 共用能力设计

| 能力 | 责任与行为 | 当前状态 |
| --- | --- | --- |
| 项目标准与采用 | 业务开发技能持有本结构、内容归属和迁移方法 | 本文定义目标 |
| 初始化项目 | XRain CLI 创建项目描述、基础目录和忽略规则；不生成假业务资源或覆盖已有文件 | 已实现；其他目录按需创建 |
| 组装源码 | CLI 的共用项目构建模块解析显式条目，组装完整平台源码及独立函数输入 | 已实现 |
| 编译平台脚本 | 共用组装模块调用 esbuild 处理模块依赖；项目包管理器负责安装锁定的构建依赖 | 已实现；须另验目标执行器及函数合同 |
| 平台包构建和导入 | 复用现有 `app build`、`app import-file` 及平台服务；新项目入口调用同一实现，不重写 ZIP、摘要或协议 | 已实现；导入和安装须另获授权 |
| 团队交付 | CLI 源码、构建后的完整 CLI Skill 和本标准由 skills-hub 分发；消费副本按来源同步 | 延续现有机制 |

项目初始化和构建使用同一项目描述。项目不复制通用组装器或平台包实现；仅业务专有处理留在项目。平台函数涉及模块打包时使用项目锁定的构建依赖；现有仅靠 Node 即可运行的 CLI 查询、已有包构建和安装不能因此新增 npm 安装或 .NET 前提。

项目命令如下：

```text
xrain-cli project init --dir <项目目录> --namespace <命名空间> --label <名称>
xrain-cli project assemble --project <项目目录>
xrain-cli project build --project <项目目录> --profile <平台连接>
xrain-cli project build --project <项目目录> --profile <平台连接> --release
```

`project init` 生成项目描述与忽略规则；`project assemble` 在构建依赖已就绪时离线组装并输出候选源码；`project build` 每次重新读取当前源码，组装后调用现有平台构建实现。默认生成开发候选；`--release` 使用项目声明的正式版本并固定项目源码输入。两次独立命令各自产生候选身份，不能把之前 assemble 的输出冒充之后 build 的输入。已有 `app build` 仍可消费明确指定的完整源码；已有 `app import-file` 继续消费明确指定的原包。

模块模式要求项目 `package.json` 直接声明精确的 esbuild 版本，并存在包管理器锁文件；先使用项目自己的包管理器安装锁定依赖。CLI 检查声明的版本与加载的 esbuild 版本一致并保存实际读取的源码与锁文件快照，不代替包管理器检查全部已安装组件。正式构建要求项目输入与 Git 提交一致；构建回执及 `build.json` 记录输入、Git 状态、源码与包摘要和平台构建器信息。编译器版本单独记录，其程序文件不保存在输入快照中，正式归档还须固定和保管编译环境。历史版本内容和已发布包版本的冲突仍须与原制品及目标预检核对，CLI 不以 `--release` 自动判定它们可安装。

平台包中只能使用目标执行器和 callable 合同允许的能力。受保护纯函数不使用 SDK、网络、记录、环境时间或随机数；普通编排按其实际合同使用平台能力。模块能在本机运行不证明目标 Jint 或函数合同接受。

## 实施与验证

1. skills-hub 固定项目描述的字段、资源条目与生成输入；扩展 CLI 初始化、组装及项目构建，保留原单文件命令。明确模块打包依赖、冻结脚本和候选版本规则。
2. 使用合成项目验证统一结构：对象、字段、Trigger、编排、包函数和单独交付函数分别进入对应输出；业务数据、客户端和运行状态不混入包。
3. 两次构建之间修改一项源码，核对新包来源和资源内容确实变化；重复构建、输出同名、失败及并发不能覆盖既有原包或报告旧包为本次结果。检查 `.gitignore` 实际忽略输出。
4. 对照 XRain 现有包读取、服务端构建和安装预检验证完整输入、资源引用及不可变版本。验证没有网络或无构建资格时本地组装可用，平台包构建如实报告未完成。
5. 铵帮先完成现有报价功能。迁移时将 `foundation-schema.mjs`、`solution-schema.mjs` 和权限资源归入平台元数据，将 `solution-guard.mjs`、导入编排和报价函数按定义与脚本拆分；`agent-definition` 和工作区归入 `agents/`，业务工具与服务归入 `backend/`，Web 和小程序归入 `clients/`。从铵帮项目入口定位这些原文件，保留既有资源 ID、公共顾客引用、历史编排版本、目标租户资料和并行工作；验证新旧包源码的语义差异、函数实际执行以及页面和智能体消费。
6. 按真实影响验证 Web、桌面、Android、iOS 和小程序的实际源码、加载与制品关系；公共客户端不复制到业务项目。源代码、安装版本及当前服务组合分别核对。
