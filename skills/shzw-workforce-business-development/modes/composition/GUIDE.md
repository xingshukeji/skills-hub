# Workforce 装配与裁剪验证

## 适用与完成标准

本模式用于已选定的装配、组合、重组、模块增删或裁剪范围。相关实现按受影响消费者选择必要行，不因方法列有完整组合就扩大任务。修复及其验证保持 Development；只有用户明确要求独立测试结论时使用 SystemTest。技能不新增部署、共享环境授权或独立测试任务。

先读取 TASK_CONTROL、项目 AGENTS、装配设计入口、当前 Runbook，以及当前 profile、bundle manifest、Host/Client 注册、源码和既有测试。以当前依赖和消费者推导组合，不把此处的模块名称当作永不变化的产品清单。

**本次选定范围通过必须同时具备：组合断言、内置浏览器真实登录、实际业务操作、异常恢复、清理证据。** 仅有页面截图、导航出现、HTTP 200、构建成功或若干单元测试，均不足以判定功能通过。

## 组合矩阵

先生成带预期结果的矩阵，为每行记录选中模块、依赖、保留功能、禁止出现的功能和验证方式。对无法满足依赖的组合，记录应有的失败及恢复行为，不把它混入正常组合，也不替管理员补装模块或新增配置限制。

下表是完整装配验证的覆盖选项。公共加载、依赖或生命周期合同变化，或用户明确要求整体装配结论时，据真实依赖选择完整范围。局部接入只选择受影响应用、真实依赖、相邻裁剪及恢复行；未受影响模块不进入本次完成条件。模块名称按当前项目更新。

| 覆盖类别 | 组合与目的 |
|---|---|
| 默认 | 源码默认完整组合，核对所有实际导航和模块功能 |
| Task 裁剪 | 去掉 tasks 与 messaging-tasks，保留聊天 |
| 桥接独立 | 仅去掉 messaging-tasks，分别操作聊天和任务 |
| 单项裁剪 | 分别去掉 contacts、schedules、workbench、mail、context-demo |
| 消息反向裁剪 | 去掉 messaging 与 messaging-tasks，保留 tasks 和其他业务，检查对消息服务的隐含依赖 |
| 独立业务 | portal/account 加各独立业务：messaging、tasks、contacts、schedules、workbench、mail；只加入已验证的必需依赖 |
| 多项裁剪 | 对业务模块及桥接建立合法的两两启用/禁用覆盖；记录未覆盖的状态对和原因，不能只重复单项删除 |
| 最小与空组合 | 最小消息组合；只有门户/账户而无业务时，检查明确空状态或契约规定的结果，不把错误页当成功 |
| 依赖异常 | 消费者保留、必需 provider 缺失；验证失败可见、不会误启用或越权，补回后恢复 |
| 生命周期 | 默认→裁剪→恢复；同页重新装配、进程重启、刷新、退出/重新登录及开发热更新 |

分层执行，明确每层覆盖：

1. **自动化**：小规模模块集合优先枚举所有满足依赖的组合；若成本过高，说明成本并使用有可计算覆盖率的两两覆盖，加关键高阶组合。至少断言 Host handler、Client 页面/插槽、初始化请求、禁止请求、清理和恢复；请求成功必须核对响应语义。
2. **真实内置浏览器**：本次矩阵选中的基线、裁剪、独立业务或多项裁剪代表必须逐行登录并操作。自动化枚举不代替浏览器行；无法操作的行保留“未验证/失败”，不得用别的行代替。
3. **故障注入**：覆盖慢请求、失败后重试、选中模块加载失败、加载中退出、重复登录/重组。仍须验证错误消失后的业务功能和资源数量。

## 浏览器操作清单

使用 Codex 内置浏览器和当前可用的浏览器工具。按工具文档操作，不用直接调用页面内部状态、手工写 cookie、注入成功结果或 API 登录代替 UI 登录。

每个浏览器组合均应：

1. 打开该组合的真实入口；必要时按 Runbook 启动依赖。通过当前产品支持的登录入口，使用已登记固定测试身份登录，确认显示真实用户及对应组合；不增设快捷登录按钮或伪造会话。
2. 核对导航、默认页面、隐藏能力、旧深链接、刷新及返回。打开弹层、菜单、侧栏；检查隐藏模块的按钮、徽标、来源跳转、覆盖层是否残留。
3. 对保留业务执行下表适用操作，检查可观察结果及刷新后的状态。使用授权的开发测试数据，标记数据归属；无授权的外部发送、人员权限变更、真实邮件投递等不得从“测试”推断授权。缺必要数据或权限就记录具体缺口，不伪造成功。
4. 对移除业务检查页面、请求、订阅及资源加载均符合预期；Host 路由用真实已认证 HTTP 请求另行断言。导航隐藏不能替代服务端裁剪证据。
5. 在宽屏、窄屏核对主要操作及账户入口，完成退出，再重新登录确认功能恢复。网页窄屏不等于 Android/iOS 实机验证。

| 保留业务 | 必须覆盖的用户动作与结果 |
|---|---|
| 账户/门户 | UI 登录、资料/设置打开、退出、重新登录；无业务时的可理解状态 |
| 消息 | 会话列表→打开会话→读取消息→搜索/清除→侧栏/菜单→返回/刷新；发送与实时接收需获准测试会话，并验证持久化和无重复显示 |
| Task | 列表/筛选→打开详情→创建授权测试草稿→编辑/保存→刷新读取；删除消息/桥接后来源内容可读且无失效跳转；涉及交办/执行需具备相应授权 |
| 通讯录 | 查询/清除、资料详情、返回；无消息模块时不得提供无效发消息入口 |
| 定时任务 | 列表/详情、合法表单与错误恢复；创建/修改仅限不会触发真实外部执行的获准数据 |
| 工作台 | 工作区/会话读取、选择合法运行环境、授权测试会话的可见回答及返回/刷新；缺运行条件不能算业务通过 |
| 邮箱 | 入口/返回/重复打开、已授权邮箱列表/检索/阅读及错误重试；实际发送和真实数据变更遵循用户授权 |
| 扩展 context-demo | 有合法位置时打开扩展，核对派生身份、无位置/无权限状态、移除后贡献消失 |

## 频道成员与目录隔离回归

涉及频道成员、目录隔离或成员资料的消息变更，使用至少两位已授权测试成员的频道；目录策略可能只返回本人，不能据此跳过成员功能或改变租户可见范围。分别验证群人数与名单、提及候选、发送后的提及正文、消息作者、发送者搜索、刷新后的历史展示。已知频道成员资料须先经过频道访问校验，并使用当前用户支持的资料契约；资料只供所属频道使用，不能混入通讯录、全局找人、新建私聊或其他频道。资料不可读取时保留真实人数并明确缺失，不编造身份。

覆盖成员移除、频道撤权、退出及释放后过期请求不能重新写入资料。裁掉 contacts 后实际操作“发起新对话”，确认仍可选择合法联系人并进入会话，或明确显示无可选对象；不得留下跳向已裁页面的按钮。测试输入经 API 夹具产生时，只将浏览器实际收到与操作的结果计入 UI 证据。

桥接恢复后使用包含提及或富文本的测试消息实际创建未交办草稿，检查正文、来源摘要、保存后读取及返回原消息；再裁剪桥接或消息，确认任务仍可读且不保留失效来源跳转。普通文本用例不能替代富文本覆盖。

## 环境与证据

- 固定当前工作树/制品和服务身份，检查并行改动。工作树变化时指出受影响证据，重新验证相关路径，不能把滚动代码叫固定候选。
- 优先用独立 profile、端口、数据目录。SQLite 用一致性备份；不要热拷贝数据库文件冒充一致快照。临时路径在 Windows 保持足够短。
- 浏览器 cookie 按主机而非端口隔离。多实例使用独立浏览器会话或不同主机名，避免测试实例覆盖默认实例登录态。
- 记录实际请求的路径/状态/次数和实时连接开闭，不保存 Token、cookie、消息正文或客户文件。区分开发源码下载与生产 chunk 下载，运行时禁用不代表产物物理删除。
- 清理只关闭核实属于本次的服务和标签页；保留默认服务及用户数据。恢复临时视口；退出后验证连接、定时器、监听和页面贡献无残留、重登后不重复。
- 优先扩展现有测试；可复用探针归测试基础设施，单次结果与日志放仓库外，不把过程报告写进技能。

## 结论门禁

输出逐组合的“自动化、浏览器、业务闭环、异常恢复”结果和具体证据，区分通过、失败、未验证、不适用。报告的是完成的操作，不是准备执行的清单。

- 本次选定的任一必检行缺登录、关键业务操作、异常恢复或清理证据：整体不通过/未完成，只能报告已验证子集。
- 前端与后端测试总数必须与组合数分开，禁止用大量既有用例夸大组合覆盖。
- 接口/环境失败归因须有证据；重试偶然通过不能替代根因修复；自动化 mock 不能代替真实登录及业务数据。
- Development 中按已有授权修复并复验；独立 SystemTest 遵循其只读边界。不得因本技能扩大权限、部署范围或测试任务类型。
- Skill 的规则验证至少包括正例“实际登录操作与矩阵齐全”以及反例“测试全绿但未登录或有未测组合”，后者不得判整体通过。
