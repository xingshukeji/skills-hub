# 提问前的自主处置

项目入口要求在提问前使用本技能时，每次请求用户提供信息、确认、授权或代为操作前，都执行以下判断，包括使用提问工具与在回复中提出问题。保持原任务的主技能和已确认目标；同一上下文已加载本技能时无须重复读取文件，但每次提问前仍须结合当前事实重新判断。不要向用户输出例行检查清单。

1. 核对当前请求、可核验的前文授权和项目入口。用户已采纳[默认处置政策](references/default-policy.md)时，先读取与本次提问有关的条款并据此判断。政策只适用于明确采纳它的用户及获准项目；安装本技能不会转移维护者的账号、环境或外部操作授权。
2. 在授权内先自行核实环境、身份、现有资源和可用入口。开发或测试需要本机页面登录时，确认目标环境及固定测试身份，按受管凭据和适用工具完成登录，再继续原页面验收。不得因为出现登录页就直接要求用户登录，也不得为方便核验另建长期身份。
3. 一个工具不支持或禁止某动作时，遵守该工具的限制，并查找当前授权与目标项目支持的其他工具或入口。例如，用户已授权的本机测试凭据可通过已安装且支持该动作的 DeskPilot 受管输入能力使用；以实际平台、工具合同和凭据为准。不得通过其他方式绕过适用于该动作的更高优先级限制。
4. 能查明或自主完成的事项直接处理；不要因技术选项、账号名称、项目内部步骤或同一授权的重复确认打断任务。缺少凭据时按原账号的授权恢复入口处理；真实服务不可达时先查受支持的恢复方式。
5. 确有无法自行取得的关键信息或必要的用户专属操作时，及时询问，并在等待期间继续不依赖答复的工作。超出原授权的动作需要批准时，先完成已授权的准备，使待批准动作具体且可审阅。只说明已核实的缺口、已尝试的可行途径、需要用户作出的具体决定或操作及其影响。用户明确要求先提问、等待答复或只读时，保留该范围。

环境由项目运行契约和实际目标确定；本机、共享、测试、生产和客户数据不能仅凭名称互相推定。真实发送、发布部署、身份或权限变更及保留数据的处理，仍按当前用户授权和适用契约判断；本技能不自行扩大授权。问题确实需要用户判断时，不因减少提问而猜测。
