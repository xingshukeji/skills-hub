# 快速登录验证

本流程用于用户已发起的开发或测试验证。目标是让固定测试身份进入原应用并完成当前需要的业务检查。账号创建、凭据保存和登录由 agent 在已有授权内连续完成。

CLI 命令只管理平台用户和平台/市场浏览器会话。认证中心的建号、激活和接入登记使用其管理网页；已安装 `xrain-auth` 时按该 skill 执行。中心管理员网页不依赖 `xrain-cli` 客户端，不能把 CLI 授权失败当作中心建号的阻断。

## 先确认身份归属

1. 从当前页面、项目运行配置或已有 profile 确认原应用、认证中心、平台和目标租户。使用实际地址，不用默认地址覆盖已指定的环境。
2. 核对目标的账号规则。受服务台账管理时，先查固定账号约定、生产账号规划、账号清单和使用规则。区分认证目录中的身份、租户成员关系与应用准入。
3. 复用相同认证目录中已登记的维护者或固定测试人物。需要普通测试人物时，优先使用目标约定的张三、李四等身份。仅在所需身份确实不存在且创建属于本次授权时创建；不按任务、日期或随机后缀重复建人。
4. 从目标指定的秘密存储读取密码。账号存在但凭据缺失时，使用原账号已授权的恢复流程；不新建另一个身份绕过。没有恢复授权时，只询问缺失的恢复决定。

新建合成账号尚无密码时，由 agent 使用系统随机源生成并保存，不要求用户先提供新账号密码。已有获准管理员凭据按目标规则复用。只有确实需要本人验证码、第三方授权或尚未获准的身份变更时，才请求用户完成具体一步。

| 实际登录入口 | 账号准备方式 | 完成依据 |
| --- | --- | --- |
| 原应用跳转统一认证中心 | 复用认证中心已有身份；缺失时创建普通本地账号并激活，见下节 | 原应用接受统一登录，当前身份及租户正确 |
| 目标明确提供平台账号密码登录 | 使用 `security user ensure` 复用或创建平台用户 | 使用该用户通过目标实际提供的密码入口登录 |
| CLI 管理操作 | 使用 `auth login` 获取浏览器会话，管理请求选择 `--auth session` | 目标管理操作接受该会话及其权限 |

平台业务用户与认证中心身份不是同一张账号表。仅创建平台用户不能证明原应用的统一登录可用。CLI 的本地 admin/guest token 也不能替代浏览器管理会话。

## 统一认证：创建后直接完成激活与登录

使用当前可用的浏览器操作工具执行以下步骤。保留网页的 Cookie、反伪造字段、一次性授权及原应用返回地址。

已有固定身份和可用凭据时直接完成原应用登录，无需先取得中心管理员会话。下面的管理员步骤只用于需要查重、创建、设置本地凭据或已获准恢复的情况。

1. 使用已有且获准的认证中心管理员打开 `/admin/local-accounts`，确认页面仍是管理列表。先搜索固定登录名，查完匹配结果的分页，核对完整名称及账号类型。再到 `/admin/users` 核对已登记身份及其登录渠道。重定向到登录页或查询失败不代表账号不存在。普通用户不能代替认证中心管理员。
2. 已登记普通身份仅缺本地凭据且本次获准设置时，从该用户行选择“设置本地登录”，保留原用户。身份确实不存在且本次允许创建时，选择“创建本地账号”。填写固定登录名，保持普通用户类型，提交“创建并生成激活码”。不要为业务测试勾选管理员或最高管理员。
3. 将页面当次显示的激活码只保留在受保护的操作上下文。打开 `/login/activate`，输入激活码并继续。该流程不依赖邮件送达，也不要求先开通第三方登录渠道。
4. 为合成测试账号生成符合页面规则的密码，填写“新密码”及“确认新密码”。按页面要求完成验证器绑定、验证码和恢复码确认；只对本次获准管理的合成身份自动创建恢复材料。需要本人验证码或授权时，只将该步交给本人，不修改安全策略来跳过验证。
5. 将合成身份的密码及必要恢复材料保存到目标指定的秘密存储。保存用户名、固定用途、角色、范围和创建入口到目标规定的非秘密登记处。默认保留固定测试账号供下次复用。
6. 平台已有对应业务用户时，先核对实际 `issuer/sub` 与既有 `userId` 的关联。同名不能证明关联成立。需要关联时，使用目标现有的受管关联入口和对应授权，保留原用户、成员及数据；不直接写库或新建第二个业务身份。入口或授权缺失时，报告具体关联缺口。
7. 回到原应用重新发起统一登录，使用该测试账号，完成正常授权及回跳。核对实际用户标识、租户成员与应用准入；只配置本次验证已授权的范围。

自助邮箱注册已可用且本次确实要验证该路径时，可以使用它。邮件未就绪时，普通登录准备优先走管理员建号与激活，不为此配置邮箱或启用新的登录渠道。

已有账号处于待激活、停用、到期、锁定或缺少凭据状态时，先辨明状态，再走原身份的获准激活或恢复入口。不得再次创建同名账号，不得自动改密、改权或停用。需要真实人员验证码或尚无可用管理员时，保留已有操作结果，说明唯一缺失条件及原入口。

待激活账号的原码仍可用时继续使用原码。码丢失或到期后，中心的“恢复密码与验证器”会撤销旧登录并清除原验证器，须属于该身份的恢复授权，不能当作无影响的重发。

## 平台账号：快速复用或创建

先使用已有获准管理员完成 `auth login`。`$cli` 为 skill 脚本绝对路径，`$profile` 为已经确认的目标 profile。下面的 `zhangsan` 与显示名须采用目标已经约定的固定测试人物。

```powershell
node $cli security user ensure --user zhangsan --profile $profile --auth session --json
```

账号存在时，返回 `created: false` 与当前 user，不要求提供密码，也不写入任何账号变更。账号缺失时，该命令提示提供创建数据。从秘密存储读取密码或为新身份生成密码，将其放入当前进程的 `XRAIN_TEST_PASSWORD` 后，通过标准输入传递：

```powershell
$account = @{ name = '张三'; password = $env:XRAIN_TEST_PASSWORD }
$account | ConvertTo-Json -Compress | node $cli security user ensure --user zhangsan --values-json - --profile $profile --auth session --json
```

新建成功返回 `created: true` 与 user。即使提交了新密码或显示名，已存在的身份仍保持原样。密码不得写入命令参数、聊天或仓库；凭据文件只能放在目标允许的秘密目录。

CLI 仅在查询明确返回 `404 / platform.authen.user_not_found` 时尝试创建。其他 404、401、403、网络失败及超时均不会触发创建。创建不授予额外角色；按当前验证已经授权的角色或权限集单独配置并读取复核。

若创建报告全局同名身份已存在，由获准的 Host 管理员把原身份加入目标租户。不要更换用户名创建另一个人。创建响应不确定或返回冲突时，先 `security user show` 核对当前状态，不自动重放创建。

## 定位登录失败并完成原验证

- 页面或回调错误：从原应用重新发起当次登录，核对实际 client、返回地址和认证中心；不伪造 state、Token、Cookie 或绑定数据。
- CLI 报 `client_id` 无效：读取当前平台 `/api/application/v1/cli-config`，核对中心 `/admin/clients` 的实际登记；已授权修复时补齐准确的本机客户端、回调和所需业务 scope，再发起新一轮 CLI 登录。该问题不需要重置账号，也不阻止通过中心网页准备账号及使用原应用自己的客户端登录。
- CLI 401：用 `auth status --json` 查看凭据来源。管理请求明确选择 `--auth session`，排除环境中的旧 API Token；本地有效状态不是远端登录证据。
- 登录成功后 403：核对当前身份、租户成员、业务权限及应用准入。负向权限用例保留拒绝结果；不得切管理员或自动提权让用例通过。
- 同一错误没有新证据：切换到对应账号、认证或应用配置的检查，不重复建号、重试密码或重启共享服务。

准备账号后继续用户原来的验证。浏览器任务必须实际回到原应用，核对当前用户、目标租户及所需业务操作；CLI 任务须执行当前需要的接口。`doctor` 成功仅证明探测接口接受凭据，不能代替业务登录结论。

结束时报告创建或复用了哪个固定测试人物、实际入口和验证结果。密码、激活码、验证器种子、恢复码和会话令牌均不得出现在输出或证据中。

需要验证密码时，先完成原应用与认证中心的正常退出及确认，看到密码表单后再登录；重新打开应用可能复用旧中心会话。浏览器及 HTTP 异常只输出步骤、类型、状态和已核对的错误码，不输出可能带 Cookie、请求头或授权码 URL 的原始异常。截图使用回跳完成后的业务页面。
