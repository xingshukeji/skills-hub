# Jenkins 流水线

查现状只查询；执行请求沿用已确定的项目、操作和环境。

1. 从目标登记找到 Jenkins，查询真实作业和参数；按[调用与参数](references/jenkins.md)使用项目入口或自带脚本。
2. 按所需阶段触发一次，保存新回执；源码获取与构建由 Jenkins 完成。缺少目标能力时交付缺口，不改 Job 或本地上传源码替代。
3. 沿同一 queue/build 跟踪终态，读取 `status/result`。提交未知先查原记录，不能用“最新构建”或重新触发代替。
4. 从本次构建的来源和发布报告取得提交、制品摘要，再与目标操作回执及实际运行版本对应。作业链接或 SUCCESS 不能单独证明发布、目标切换及业务可用；缺失的阶段证据保留未验证。

涉及目标变化时按[部署模式](../deployment/GUIDE.md)先选择目标合同，沿用当前已授权的完整操作；仅查询或不改变命名目标的构建不加载目标部署门禁，制品发布仍核对原授权。产品迁移、整版升级等专属阶段还须核对该项目 Runbook 与实际 Job，通用参数表不替代这些合同。

脚本从本模式目录（Workforce 的 `resourceBase.path + "/modes/pipeline"`）运行，需要命令工具和 Node.js 22.12+；凭据仅经现有秘密入口注入。
