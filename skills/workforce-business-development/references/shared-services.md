# 公共服务与应用交付

## 消息、通知与人员协作

根据业务目的区分三类结果：Workforce 内的沟通消息、需要有人承担的 Task，以及邮件/短信/飞书等外部投递。更新一条业务记录或完成一次智能体运行，不会自动产生这三类结果。

| 目的 | 接入方式与需要明确的内容 |
| --- | --- |
| 在当前业务会话中呈现消息 | 使用 Workforce 已有消息服务和会话上下文，保存实际消息结果 |
| 交给人员或 AI 员工继续处理 | 使用目标版本的 Task 能力，明确责任人、业务目标与当前状态 |
| 向外发送模板通知 | 已配置的通道、账户与模板，以及实际发送身份和权限 |
| 查询投递结果或处理重试 | 使用投递记录、业务幂等键及对应通道提供的状态 |

编排可发现的投递 callable 包括 `delivery.sms.send`、`delivery.email.sendByTemplate`、`delivery.email.findByIdempotencyKey` 和 `delivery.feishu.sendByTemplate`。实测这些条目的 `signature` 均为 null，参数说明在 `helpText`；以下是目录给出的输入，尚不表示对应通道完成过实际投递验证：

| callable | 目录描述的输入 |
| --- | --- |
| `delivery.sms.send` | `{phoneNumber, templateKey, templateParams, originalText, idempotencyKey}`；未启用可返回 ignored，不产生发送事实 |
| `delivery.email.sendByTemplate` | `{templateName, recipient?, preference?, data, whatId?, idempotencyKey?, triggerPermission?}`；recipient 可为 `{kind: "User", userId}`，triggerPermission 仅用于 Trigger |
| `delivery.email.findByIdempotencyKey` | `{templateName, whatId, idempotencyKey, triggerPermission?}`；需发送权限及关联记录读取权，未找到可返回 null |
| `delivery.feishu.sendByTemplate` | `{templateName, recipient, data, whatId?, idempotencyKey}`；recipient 为 `{kind: "User", userId}` 或 `{kind: "Chat", chatId}` |

不要把短信手机号参数套给飞书接收人。通道、发送账户、模板、启用状态和执行权限分别配置；更改模板与实际发送分别处理。

应用消息能力可通过 `XRainRuntimeClient.applicationMessageAuthorization(applicationId)` 读取授权结果。显示的机器人名称是消息作者呈现，不代表它持有可随意替代当前用户的登录凭据；执行仍核对实际主体及应用发送能力。外部通道的“已受理”也不保证送达，例如 SMTP accepted 与收件人收到邮件不是同一状态。

本次同一普通成员的应用 admission 返回 allowed，而 message-authorization 返回 403、`application_management_forbidden`，说明缺少应用消息发送权限。该检查未发送消息，不能把“应用可进入”当作“通知链路可用”。

发送可能已经成功但响应丢失。需要避免重复发送时，按业务通知事件形成稳定幂等标识，并查询已有投递结果；不要每次重试生成新标识。没有对应通道的送达回执时，结果只承诺实际可确认的状态。

Task 是协作责任与进度的载体，原生 Session/Run 是智能体的执行过程，ERP 订单或 XRain 工单是业务事实。把它们通过目标标识关联即可，不用多个系统的同名 `completed` 相互覆盖。目标版本支持草稿、确认或人员验收时按其公开 Task 合同接入；一次 Runtime 结束不自动证明业务 Task 完成。原系统已拥有完整审批流程时，Workforce 可以发起原流程、跟踪状态或组织协作，不另造一个与原流程冲突的审批结果。

从个人来信取得业务上下文、读取正文并保存回复草稿，使用[个人邮箱](personal-email.md)的真实用户链路；它与组织模板投递有不同身份和结果。给应用选择助手、处理订阅以及判断能否启动，使用[智能体订阅与应用选用](agent-access.md)，不只检查定义文件是否存在。

## 文件与附件

文件字节、业务附件关系和读取资格分别有责任方：平台文件服务保存稳定 `fileId` 及文件内容；Workforce 或企业应用维护“哪个会话、消息或业务记录使用该文件”以及访问资格。文件上传成功后，保存业务关系时复用返回的 `fileId`。

平台文件 HTTP 能力位于 `/api/service/files/v1/files` 一组接口。当前服务入口使用允许的服务主体 API Token，并检查 `platform.files.invoke` 等条件；它不是普通用户可直接当成记录 CRUD 使用的上传口。企业页面优先使用已交付的 Workforce/应用附件入口，由宿主传递可信上传者和业务上下文。

已核对的 `@xrain/workforce-application/server` 0.3.5 导出 `XRainRuntimeClient`，没有从该入口导出 `XRainFileClient`。不能因为包内某个类型文件出现该类就导入内部路径。目标新增公开文件客户端时按其实际导出接入；已有企业宿主文件 API 可直接复用。

附件接入通常包括：取得上传结果，在业务消息或记录中保存附件引用，读取时根据当前用户和关联资源授权，再提供下载或预览。`uploaderId` 来自真实会话，不接受页面随意填入。稳定文件 URL 仍可能需要认证，知道 `fileId` 不等于有权下载。

消息提交失败后重试可复用已上传文件，避免重复上传；删除消息或业务记录也不自动证明平台文件应立即删除。沿用目标已有引用与保留规则。Office 内容提取、文件预览和知识库索引是不同能力，上传附件不自动形成可检索的企业知识。

## 应用与资源的生效

XRain 应用按租户和应用身份管理。包内资源、应用当前选择、用户授权与宿主装配共同组成可用业务，分别观察其结果：

| 内容 | 实际改变什么 | 如何确认本次结果 |
| --- | --- | --- |
| 模型和集成资源源码 | 可交付的对象、字段、权限、连接器/请求/接口、函数等受支持资源 | 源码结构及引用有效，按目标规范生成 |
| `.appkg` 构建 | 形成服务端构建的可安装制品 | 构建结果与包完整性通过；尚不表示已安装 |
| 包导入与安装 | 在目标环境维护相应平台资源 | 目标元数据或资源目录出现预期定义 |
| 应用资源关联和版本选择 | 该应用采用哪些对象、接口或函数版本 | 应用资源与修订显示预期选择 |
| 应用启用、准入与权限 | 哪些成员可以进入、执行什么能力 | 以对应成员读取准入并执行相关动作 |
| 环境地址、凭据、投递通道与执行人 | 资源在当前企业环境如何连接和运行 | 目标绑定正确，实际操作有对应结果 |
| Host/Client 插件和页面 | Workforce 装入企业代码及界面 | 入口与处理器加载，页面能完成业务 |
| 在线智能体定义 | 指令和工具声明生效 | 定义已更新，工具可由宿主路由并完成动作 |

应用中选择资源不自动授予其所有数据权限。应用停用、撤销成员权限与删除模型或业务数据也不是同一个动作；按本次需求修改对应层，不用删记录实现“隐藏应用”。对象模型保存通常直接影响生效模型，不假设必有草稿/发布双态；破坏性字段变更需结合现有数据处理。

升级时的发布者与租户属性边界、预览/绑定/冲突、operationId 状态跟踪、卸载和中断恢复，见[模型与应用生命周期](lifecycle.md)。变量、个人设置和 Token 维护见[运行配置](configuration-and-api.md)。包安装受理后，应按操作终态和当前组件判断是否真正生效，不能只看资源目录里是否出现名称。

不同入口支持的认证类型不同。当前应用正式函数等入口要求登录 JWT；记录和集成运行 API 可按其对外目录支持 API Token。API 中心列出了路由，也不意味着所有路由都接受任意 Token。已有业务服务沿用目标明确支持的认证方式。

公共宿主与资源包各自交付。`.appkg` 不承载企业的任意 Node/React 应用文件，加载宿主也不会自动创建平台字段；按项目已有方式把此次变化落到相应制品与配置。只改页面就交付页面改动，新增集成则补齐所需接口资源及环境绑定，不强制每个需求更新所有层。

## 定位业务结果

从实际操作继续追踪：记录写入看返回 ID 和条件冲突，HTTP 接口看内部远端状态，编排看输出与失败码，Routine/Trigger 看对应运行，投递看通道结果，附件看上传与业务引用，工具看服务处理器返回。健康检查或“启动成功”只能证明对应入口已运行。

页面搜索、消息搜索、业务记录筛选和跨系统检索使用不同数据范围。需要统一搜索时明确每个来源、可见范围、分页和索引时效，复用已有搜索服务；不能因公共门户有搜索框就承诺搜索所有企业系统。
