# 文件消费职责边界

用于新增、修改或审计文件读取、解析、转换及写回。局部任务只追受影响链路；用户明确要求全面调查时，再覆盖相应源码根、构建与测试入口及外部工具。搜索命中是调查入口，不是缺陷结论。

## 先确定消费关系

沿实际入口记录 `文件职责 → 生产者 → 消费者与执行时机 → 解释接口 → 写入与恢复责任`。一条简短记录即可，不要求建立长期文件台账。文件包含多种内容时分别判断；同一扩展名或目录可以承载不同职责。

同时检查直接文件读取、模块导入、构建 glob、资源复制、生成器和外部命令。核对当前入口是否真的调用该消费者，区分开发、构建、测试、交付和正常运行，不能把离线维护脚本误报成启动依赖。动态路径无法确认时，给出证据缺口。

## 按职责选择接口

| 文件职责 | 合理消费方式 | 需要纠正的越界 |
|---|---|---|
| 配置 | 所有者通过命名字段、类型或既有 schema 承诺输入；组合入口解析优先级，再传给消费者 | 从其他产品的私有初始化结构寻找运行凭据；根据环境名称隐式改业务规则 |
| 可执行或声明式源码 | 编译、模块公开导出、公开资源模型；静态分析按语言结构或明确的文本规则检查 | 截取导出语句来冒充数据接口；替换私有源码的偶然字符串来传递构建选项 |
| 文档与治理规则 | 人或智能体读取说明；文档工具校验链接、元数据或显式声明的机器规则 | 依赖正文句式、箭头或排版推导程序配置；把审阅状态作为普通运行资格 |
| 业务数据与实例状态 | 经业务接口读取用户文件或持久记录；资源所有者持有写入、并发及恢复语义 | 将交付默认定义当实例状态写回；把缓存当唯一事实源；清空数据掩盖失败 |
| 素材、模板及静态资源 | 按声明格式和用途复制、转换或打包，保留必要许可与来源 | 因素材位于文档目录而误删；把素材说明文字当行为配置 |
| 生成物、依赖及证据 | 构建链消费声明的产物；验证工具消费匹配版本的制品与必要证据 | 手工维护可重新生成的第二份事实；普通启动依赖 CI 回执或猜测的源码路径 |

配置路径显式给出只解决“在哪里”，不自动证明结构是公共接口。核对字段与版本由谁承诺。程序读取源码文件也不必然越界：编译器、构建工具、源码分析器、生成器与源码查看功能本就可能消费源码；按实际用途判断。

## 纠正常见的隐含接口

**源码被当作配置或数据。** 构建选择通过已有配置或模块接口传递，让构建工具负责模块发现及依赖跟踪。测试需要模块数据时，在合适的测试环境读取导出；检查语法规则时使用现有解析器。仅当被检查的契约本身是文本时使用文本断言。改成 AST 可以减少语法脆弱性，但不能消除未经承诺的私有结构依赖。

**文档正文被当作机器协议。** 先确定规则的唯一所有者。可以使用独立配置，也可以保留文档内明确声明、格式可校验的机器区块；按现有消费者选择较小改动，不要求统一拆文件。对影响解析的结构给出格式或版本约定，并验证缺失、重复与无效输入。只改普通正文表达应不改变机器结果。普通链接、拼写、元数据及明确的文本规则检查仍属文档工具职责。

**默认定义被当作可写状态。** 运行中的业务选项更新不得写回交付默认定义；由调用方显式选择需要维护的实例文件或已有状态接口。只有真实的可变状态需求才引入该路径。涉及持久写入时，确认失败能否保留原状态，并按实际并发、关闭和重启路径验证；不用增加锁、队列或自动复制来处理不存在的写入场景。

**私有路径被当作依赖入口。** 外部工具通过已安装的公开命令、包导出或显式配置的工具目录接入。技能可以指导操作，也可以提供执行脚本；脚本成为构建依赖时，须明确依赖来源、适用版本或接口、缺失时的处理和调用方。显式目录可以指向技能提供的工具，但不能靠隐含的个人技能目录、猜测的相邻仓库或说明文档排版定位程序。依赖安装继续交给既有包管理或工具维护入口。

**必要兼容补丁缺少约束。** 优先使用公开扩展点或既有依赖补丁机制。确需转换第三方分发文本时，限定目标版本或输入身份、预期匹配及变更结果；失配必须明确失败，不能静默生成未修复制品。输入散列、匹配断言或标准补丁检查按实际失配风险选择，不要求同时建立多套校验。验证实际修复行为，并记录可核实的上游替代或移除条件；不把补丁模式推广为普通源码配置接口。

## 让验证对应消费者

同时验证原错误和保留的合理消费关系。按改动选择证据，不把下面的示例变成固定测试清单：

- 模块选择验证默认、指定和空选择的实际构建结果；涉及开发监听时检查新增或移除模块能否被发现。只改引号、空白或内部位置不应改变对外结果。
- 模块数据验证实际导出、消费者约束及发现范围；真实需要自动发现时，检查新增模块是否进入覆盖。资源总数不能代替完整性判断。
- 布局验证使用实际组件和生效样式观察尺寸、比例或交互；断言 CSS 字符串存在不能证明布局正确。
- 文档规则验证正文改写不影响机器区块，同时拒绝无效规则；合法文档检查和素材读取继续工作。
- 可写状态验证只修改调用方选定的实例状态，保留交付定义；有证据支持并发或关闭风险时，再覆盖更新顺序、失败重试和关闭后的行为。
- 工具输入验证缺失或结构不符时的实际失败结果，避免泄露凭据；依赖补丁验证约定之外的输入漂移会明确失败，并用公开入口或实际产物验证兼容行为。

删除旧消费方式时，同步处理真实调用方、类型、测试和运行说明。保留业务鉴权、租户隔离、数据并发与制品完整性约束；不能借修正文件职责绕过这些独立责任。结果报告区分已核实问题、合理读取和未核实范围，不新增运行门禁或要求每次重复全面审计。
