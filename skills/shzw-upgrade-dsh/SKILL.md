# DSH 升级

Resolve project entrypoints, source, documents and command working directories from the user's target project. Resolve this skill's `references/`, `scripts/` and `assets/` from its installed directory. Locate other responsible repositories through the target project's entrypoint; never infer the target from the skill installation path.

## 先定动作

仅在用户调用 `$shzw-upgrade-dsh` 或明确要求使用本技能时启动；发现新版本、CI、普通开发或准备上线均不触发。保持 `allow_implicit_invocation: false`。

| 用户要求 | 行动 |
|---|---|
| 检查、评估，或只调用技能未给动作 | 只读调查，输出建议，不修改依赖 |
| 明确升级或回移修复 | 在授权项目和目标内完成修改、验证；不重复确认已授权动作 |

升级不以发布制品为前提。按项目既有规则工作；不自行建 worktree，不动无关修改。部署、灰度、线上监控、自动回滚和定时任务不在范围内。

## 查事实，定目标

从项目入口找到实际依赖、源码与测试；区分声明/锁定版本、复制来源和实际运行版本。按需盘点四类：**包及相关传递依赖、复制源码/资源、装配协议、外部 Runtime**。每类记录本地消费者、基线与上游位置；无来源写未知。

Workforce 的 DSH 消费同时可能包含前端包、复制的 UI/资源和 Cordis 插件接缝；Harness 拥有 Runtime 执行侧，业务应用还通过公共包及自己的根锁文件消费。按 RUN-0002 的当前索引逐项定位，不能只更新 Workforce 的依赖就声称铵帮或外部 Runtime 已升级。先证明包导出和实际应用消费，再更新命中的复制来源与兼容说明；不在技能内保存版本快照。

用户给了目标就验证它，包括明确指定的预发布版本；未给目标则核对官方发布及 npm 可得性后推荐，不擅自选择预发布。固定包版本、目标完整 SHA、包完整性及 peer/engine 约束；Git tag 存在不证明包已发布。

按各自基线比较完整区间的说明、源码/类型、依赖和相关测试，沿真实消费者扩展。每项只保留：

`上游证据 → 消费位置 → 用户影响/兼容差异 → 采用、回移或暂缓 → 必要验证`

新增功能不自动接入；未使用项须有不适用依据。相邻 Runtime 可只读核对，修改仍需在本次授权范围；本地包升级不能证明外部服务升级。

## 实施并验证

动手前固定基线→目标、修改范围和匹配风险的验证。包更新其所属锁；共享 React/Cordis 的实例和协议一起核对，不强求同版本号。复制代码三方比较，保留本地 API、身份、草稿、主题和存储接缝及许可；单修复回移记“原基线 + 修复提交”，不伪称整包升级。

**按影响选择验证，不强制每次跑全部场景或连真实 Runtime。**

- 本地接缝跑定向测试、类型/构建；Bug 用同一输入证明旧版复现、新版消除。
- 涉及 Runtime/远程合同的改动验证真实目标依赖及业务结果；mock 或健康检查不能代替实际回复、审批与工具交付。与此次改动无关的 Runtime 缺失不阻断局部升级。
- 按命中风险测试草稿/中文输入/迟到响应、身份切换、重试/重复执行、断流/超时/重启、历史数据和实际新旧组合。故障只在隔离环境注入，不重放生产副作用；性能有影响才按同条件与预定预算对照。

未知公共合同、不可逆数据变化或超出授权时停住对应路径，只继续同一授权目标内可独立验证的部分；发现其他 UI/功能可修不等于获准顺手修改；关键验证失败在已授权范围修复复验，不扩大权限或用上线观察替代。数据格式受影响时先确认兼容与隔离恢复方式。

## 收口

输出实际基线→目标、动作/范围、验证结果和剩余缺口。每个适用项为通过、失败、未验证或有依据的不适用；区分旧问题、环境不足和新回归，不用重跑成功掩盖未解释失败。关键路径未验证不能宣称该升级通过；局部成功不得冒充全体依赖升级成功。

更新锁、复制来源和唯一项目事实；不把版本快照或过程报告写进技能。升级及其必要验证完成即收口，不自动转成发布验收。独立 SystemTest 仅随用户明确要求建立。
