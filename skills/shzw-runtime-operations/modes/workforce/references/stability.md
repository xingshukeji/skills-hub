# 实例采样与恢复

用于已明确实例上的内存、连接、队列和退出释放问题。项目提供 `shzw-testing` 时，按需使用其场景与技术栈参考；没有该技能时，本参考仍可完成有界诊断。操作沿当前任务授权，采样不自动授权负载生成、故障注入、重启或部署。

## 识别对象与窗口

1. 从项目 Runbook 和现有连接入口确认实际主机/容器、PID、启动时间、制品标识、运行时及资源限额。开发宿主、共享平台、认证和模型服务分别识别，不能用本机空闲证明远端正常。
2. 固定原用户业务、数据规模、活跃会话、后台任务和观察时长。优先读取既有监控与低开销指标；使用当前工具帮助确认命令、单位和支持范围，不猜接口。
3. 在业务操作前、进行中、取消/离开后及恢复窗口保留同口径样本。为自然回收、背景流量、重启和采样开销标注时间；前后实例年龄或负载不同只报告各自趋势。

## 选择相关指标

| 现象 | 采样与判断 |
|---|---|
| 内存增长 | 并列堆、进程和容器内存、分配/回收、缓存条数及字节；比较重复业务循环后的低谷基线。只看 RSS 或 GC 已提交量不能确定泄漏或释放 |
| 请求慢、CPU 低 | 查同请求的连接池获取、锁、队列和依赖等待；区分服务器与负载端，保留超时和失败 |
| 消费变慢 | 记录产生/消费速率、缓冲条数及字节、最老项年龄、取消与排空；只有当前任务允许时才主动降速复现 |
| 离开或卸载后保留 | 检查旧 SSE/WebSocket、订阅、计时器、后台任务及历史缓存，重新进入后复验；新路由不可达不代表旧连接已结束 |
| 主机或容器压力 | 同窗查 CPU 使用和节流、内存压力/OOM、线程/句柄/连接、磁盘容量与 inode、I/O 等待及错误；缺少指标标明未测 |

.NET 使用目标进程的既有指标或兼容版本诊断工具；Node.js 复用目标宿主已有的内存与事件循环观测。另起一个 Node.js 进程所报告的自身内存不是宿主证据。诊断工具并非消费本技能的安装前置条件，缺工具时报告覆盖缺口。

堆转储、堆快照及高频跟踪可能暂停进程并增加内存或磁盘占用；先核对现有授权和余量，不能当作无影响的只读检查。方法及工具限制见 [.NET 诊断文档](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/)和 [Node.js 堆快照说明](https://nodejs.org/en/learn/diagnostics/memory/using-heap-snapshot)。

## 恢复与结果

在当前授权范围内验证原操作、取消和退出后资源；若本次改变依赖条件，恢复后核对原固定身份、业务回读、旧连接、重试及在途终态。健康检查正常或队列变短不能替代业务结果。

确需重启或切换包时，按[启动与连接](startup.md)保留即将丢失的相关现场，复用已有进程和包来源信息。

达到时限、输出预算或业务影响界限时停止采样。关闭本次临时诊断连接，恢复本次改动的参数或注入，清理可归属的临时文件；保留 Runtime、定义、会话、工作区和原业务数据。原始证据按目标项目受控位置保存，不提交令牌、转储或请求正文。

报告实例/版本、业务和数据规模、时间窗、指标口径、预算来源、恢复与清理状态。无明确预算时可给趋势与原因判断，不判容量达标；短时下降或无 OOM 不证明长期稳定。已授权的最小部署核对继续按[部署核对](release.md)执行；更广的验证范围由当前用户目标确定。
