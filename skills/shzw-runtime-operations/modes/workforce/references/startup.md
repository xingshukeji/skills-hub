# 启动与连接

`<模式目录>` 指本技能目录下的 `modes/workforce`，不是目标项目目录。

Workforce 根入口是 `npm start` → `scripts/start-development.mjs`；dev、preview、serve、debug、start:development、start:local、start:ui 转交同一入口。开发宿主要求 Node.js 24，Windows 可用 Start.cmd。

启动参数由目标项目的 `scripts/development-configuration.mjs` 解释。当前 Workforce 使用 `config/development.json` 提供公共配置，`config/development.local.json` 提供可选本机覆盖；显式配置路径替代默认本机覆盖，进程环境变量优先。`connectionScript` 仅在实例确需连接器时配置，支持接收 `start` 参数的 Node.js 或 Python 脚本。默认共享测试地址无需连接器或本机代理。

应用、Runtime、定义、会话与工作区在本机；共享平台、认证及模型按配置连接。参数缺失时恢复原接入配置，不创建新身份或清空状态。

新电脑先核对目标项目和相邻 Local checkout、Node.js 24 与 npm；发行包按目标 Runbook 的锁文件安装，公共源码联调使用该 Runbook 的源码准备入口。普通启动用根 `npm start`，不要复制另一台电脑的绝对路径、Runtime 状态或凭据；仅在目标确有差异时建立本机覆盖。分别核对入口输出的应用目录、包版本和摘要、实际监听地址，以及所连平台和租户。`ready` 只证明宿主就绪，不证明定义、资格或业务操作可用。

遇到 `XRAIN_HOST_STATE_BUSY`，先按实际启动配置定位状态路径及其写者，保留定义、绑定、会话和工作区。按 Runtime Runbook 核实标记身份、所属进程和全部部署写者均已停止，再精确处理对应残留；不能仅凭端口空闲、PID 不存在或固定标记数量批量删除。端口被占时先确认监听者和状态目录，不终止未知进程。应用目录为空、显示无智能体时接续[员工与会话配置](../../agents/references/agent-session.md)，区分平台资格和本机 Runtime 定义。

仅在排查配置与入口时调用文件检查：

```text
node "<模式目录>/scripts/inspect-launch.mjs" "<项目根>" ["<已有配置路径>"]
```

检查器调用目标项目的 `developmentConfiguration` 导出，复用正常启动的字段、默认值和覆盖顺序。它检查已解析的路径及 package.json 启动别名，不执行启动脚本，不读取业务应用配置正文，不输出环境变量值。`readyToInvoke` 只表示入口文件存在、别名一致及已配置连接器的脚本类型受支持；不表示 Node 版本、连接器系统兼容、应用配置语义、服务健康或业务验收已通过。检查器是显式排障工具；启动程序不调用它，也不读取本说明。

运行 `npm start -- --check` 先调用应用自身的配置检查，再检查当前配置的共享平台健康与认证发现；该命令会调用已配置连接器，不启动宿主，检查通过仍需验证原业务动作。用 `npm start -- <配置 JSON 路径>` 启动显式配置。默认启动入口、检查合同与实例参数以目标项目当前 Runbook 为准。

| 失败处 | 检查 |
| --- | --- |
| 配置 | 原配置路径、必需字段及进程环境覆盖；空字符串会覆盖文件值 |
| 连接 | 已配置连接器、实际共享服务地址及远端健康；本地监听不证明远端可达 |
| 宿主 | 原终端、应用配置与 `/health/ready` 的 `status:ready` |
| 宿主就绪仍失败 | 原用户登录、业务请求或模型调用；转对应排障 |

入口在当前进程启动业务应用。本次确需重启或切换包、且会丢失相关故障现场时，先从已有记录保留原请求错误/关联 ID、进程与启动时间及包来源；涉及执行时保留本轮历史水位和已知状态。无法留存的部分注明缺口，不延误必要恢复。重启前在原终端正常停止对应进程；端口冲突先核对归属。保留 Runtime、定义、会话与工作区。只修本机连接时，不重启共享依赖。

普通启动使用应用目录中实际安装的公共包；相邻 Workforce/Harness 源码修改不会自行生效。先区分发行包消费与本机源码开发：前者按应用锁文件安装，后者按目标 RUN-0011 的“源码准备”入口，在本机构建 Workforce 与 Harness、核对兼容关系并一起安装原包，不要求先上传或发布。首次准备、后续源码生效和恢复锁定版本分别沿 Runbook 执行；不从目录里挑最高版本，也不通过修改版本号或跳过 peer 检查掩盖配置不匹配。

从启动输出核对业务源码目录、实际解析的公共包路径、版本和来源摘要；版本号相同不证明源码相同。配置检查和包安装通过后，仍从当前入口复测原动作及持久结果。2026-10-28 用户先接受 Runtime 的必要本地打包，2026-10-30 又明确三仓源码可在本机准备并运行、日常改动不依赖发布（聊天 `01a181d0-2cd5-7ca3-9be0-56d3a410c082`、`01a18b4c-b2c7-7193-8775-298e04f41d5f`）；后者扩大了开发闭环，不等于取消包兼容或改变正式发布方式。
