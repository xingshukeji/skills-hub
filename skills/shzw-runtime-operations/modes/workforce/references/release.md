# 部署后效果不一致

沿同一次发布核对：期望提交 → Jenkins 来源/阶段 → 不可变制品 → 实例实际摘要与配置 → 浏览器入口和业务行为。版本接口未提供时读现有部署回执或容器信息，不猜 /version。

| 证据差异 | 处理 |
| --- | --- |
| 只检查、构建成功 | 查本次是否实际发布/部署，按已有作业能力补所需阶段 |
| 实例摘要旧 | 查目标选择、部署阶段和运行态回执 |
| 实例新、页面旧 | 查入口、代理、静态资源及缓存 |
| 源码相同、行为不同 | 查实际加载配置、应用安装、装配及原用户准入 |

XRain 当前部署边界：
- 日常研发在本人本机；V2 公共入口和 V3 铵帮入口面向演示，Job 的 test 名称不是环境用途证明。
- 公共核心作业仅准入 v2-public，更新全部已启用核心角色；Runtime 中间镜像不作为独立运维版本。
- 铵帮新交付为单一企业宿主；旧三服务和合成预览仅作历史排查。新制品不能直接交旧 Web 部署单元。核对实例实际 runtimeMode，不凭产品名推断拓扑。
- 日常 CD 保留状态，不重放初始化、导入定义或数据库迁移。修改环境文件不保证重载，核对受保护的已渲染 Compose、摘要及容器实际配置。
- 当前铵帮及已迁移的 V2 后台复用目标租户既有管理员，内部函数用该身份原生登录；按实际配置引用恢复，不照抄旧 service-token 配置。终端用户仍以本人身份验证。
- 相邻源码变化须经固定公共包与消费者锁进入制品；本地检查、历史验收或一次豁免不替代本次准入。

只触发已有 Jenkins 时用 shzw-delivery（若可用）；实际目标、权限与开放范围仍以当前 Job 和受管策略为准。回滚程序不等于回滚数据，恢复限于已有兼容与授权边界。最后从原用户入口复测。
