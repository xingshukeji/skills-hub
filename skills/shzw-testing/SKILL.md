# 验证与测试

从用户主要结果判定任务类型。实现或修复及其验收仍是 Development；用户明确对已有实现要求独立测试结论才是 SystemTest。测试数量、浏览器、真实库和 CI 不决定任务类型。

固定原动作、预期结果、当前源码或制品、环境及必要身份用途。先找已有测试与 Runbook，选择能直接证明风险的最小层。断言响应与持久副作用，拒绝路径还须证明无禁止写入；不把记录响应当测试。

按改动选择平台断言，不默认执行整张表：

| 受影响行为 | 需要证明的结果 |
|---|---|
| XRain 记录、授权、批量或导出 | 固定人物在目标租户完成真实对象操作；验证字段、记录范围和拒绝写入，按该服务的批量模式检查事务或逐项结果，导出仍受 export 权限控制 |
| Workforce 页面、工具及应用组合 | 同一业务事实经页面保存、API/工具读取及再次进入后保持一致；只测命中的组合、端和切换/迟到响应分支，编译通过不代替原入口 |
| Harness 执行与协作 | 沿原 Task/Session 观察工具结果、业务副作用及消息交付；暂停、取消、改派与重试不恢复旧权限或重复外部动作 |
| 应用包安装或升级 | 固定 package/version/operation 与安装 revision，原操作终态和当前安装一致；结构校验、安装成功与普通成员业务可用分别断言 |

公共消费者通过目标实际接口和包测试；只有维护事务、provider 或平台内部行为才进入对应源码与数据库。纳管环境复用已登记固定账号，不按测试场景或每轮验收新增长期身份。

用户要求完整范围时，先从当前产品入口和功能清单列出本次应验证的业务动作，再映射已有证据。先确定分母，不能从已运行测试反推范围。定时执行要观察真实到期、领取、业务副作用和下次状态；接口存在或手动调用成功只证明对应路径。产品不支持的动作与支持但未测的动作分别说明。

按实际问题选择正常与相邻失败分支。资源问题记录实例、代表性业务、实际完成量、观察窗口、预算来源和恢复；短时健康或内存下降不能证明长期容量。环境失败、测试实现问题和产品断言失败分别归因。

首次报告前逐项核对用户范围与证据，区分通过、失败、未执行和不适用；“未发现失败”不等于已覆盖。复用版本和环境仍适用的证据，新改动、失败或具体疑点才扩大检查。只清理可归属的隔离资源。独立测试保持被测代码只读；修复授权已覆盖同目标时，在原授权中继续并重新固定验证对象。
