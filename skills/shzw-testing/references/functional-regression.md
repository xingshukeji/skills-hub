# 功能回归与性能验证

用于会改变数据流、状态、资源或调用合同的修复与优化，也用于检查“修好 A 后破坏 B”的风险。沿原任务选择必要范围；普通局部修改不要求执行所有场景，修复附带验证仍是 Development。

## 先固定应该成立的功能

从原要求、产品合同、现有数据和真实消费者确定期望。记录原故障的触发与后置状态，再列同一机制支撑的合法业务动作。实现、当前返回或新结构都不是业务期望的来源；只有确认规则改变后才同步改变对应断言。

把正常、拒绝、失败、取消、恢复和多次执行中受影响的状态画成简短顺序或表，明确谁能改变谁。并发问题固定可控交错；时间相关问题控制事件顺序或时钟。需要真实依赖才能成立的行为，不能由更复杂的 fake 代替。

多个参与者或等待点使手写案例容易漏交错时，按[有界状态探索与真实回放](state-exploration.md)建立动作前提、枚举本次边界内的合法顺序，并把反例逐步回放到真实实现。模型与源码映射失效时先校正映射，不能用旧模型通过代替当前代码验证。

| 改变了什么 | 功能证据 | 容易遗漏的相邻行为 |
|---|---|---|
| 解析、映射、编码或摘要 | 固定样例、冻结旧协议或独立参考，比较字段、精度、顺序和字节 | Unicode/转义、空与清空、重复字段、旧版本读取；新实现更快但语义变化 |
| 批量、流式或分页 | 所有项的稳定身份、覆盖、唯一性、次序及持久结果 | 空集、边界页、宽行、末页、修改中的游标语义；限制内存后丢数据或只显示首段 |
| 并行、缓存或复用 | 同输入得到合法结果，作用域、修订、在途量与资源归属正确 | 其他入口、租户/成员切换、撤权、失效与 miss；快路径跳过原检查 |
| 保存、提交或重试 | 完成时回执与存储一致，拒绝时没有禁止副作用 | 保存失败保留旧状态、已提交后响应丢失、重复确认；只改返回而重复写入 |
| 页面、媒体或异步加载 | 原用户动作、可见反馈、保存回读、关闭及再次进入 | 迟到结果污染新页面、草稿或选择丢失、资源提前释放与退出后继续更新 |
| 生命周期与清理 | 原持有者和操作自然结束，恢复后仍能完成业务 | 取消只返回但后台仍写入、关闭错误订阅、回收共享资源或清除未完成状态 |

选择与当前因果链有关的行，形成“触发 → 动作 → 可观察结果 → 允许/禁止副作用”。拒绝测试配合法成功，防止全部拒绝也通过；修复测试配合法相邻场景，防止删掉功能才消除故障。断言具体值、完整结果与持久后置条件，不止检查状态码、无异常或某个方法被调用。

## 让测试能否定错误修复

保留能复现原问题的回归用例，同时检查同一状态、公开接口或算法的其他消费者。对容易出现的替代错误，选择最小有辨别力的反例，例如晚到结果、另一个合法租户、取消前已提交的一项或最后一页。测试按功能组织；不要从新实现的 if 分支逐条复制期望，也不把修改 fake 或 snapshot 当成产品已正确。

适合时用差分或性质检查增加覆盖：编码旧新结果相同，分页合并与完整结果一致，批次大小变化不改变业务结果，合法重试不重复副作用。参考与被测实现避免共用同一错误算法；随机数据只作为补充，保留稳定种子、最小反例及独立样例。

需要证明用例有辨别力时，可在隔离副本中做一个有针对性的错误变体，确认测试会拒绝它，再恢复被测候选。根据具体风险选择，不把变异测试、全组合或固定覆盖率变成所有任务的门禁。

修复反复导致相邻回退时，回查职责、状态所有者、重复分支和隐含调用顺序。先简化相同事实的维护方式，再检查测试是否从业务约束取期望；不要仅继续给每个补丁加例外测试。

## 同时验证资源收益

组件对照回答算法、分配或复制是否改善；原业务入口回答用户是否完成了相同工作。性能样本与功能断言使用同一有效结果，保留失败、超时及未发出的工作，不用少处理数据换取更好指标。

比较时固定有影响的代码/包、数据形状、资源、并发、冷/热状态和计时边界。诊断跟踪与正式计时分开说明；波动或回退有疑点时补同环境旧版本对照。组件分配下降不能证明峰值内存下降，局部更快不能证明端到端更快。不要拼接不同候选的最好分段。

公共接口、打包或共享状态改变后，复验实际消费者。局部测试、真实依赖、实际包和可见页面各自证明自己的范围；已有仍适用证据继续复用。只有新改动、失败或明确疑点才扩大检查，用户未要求的独立系统测试与部署不由测试规模推导。

报告原故障、相关合法业务、失败恢复、资源指标及证据缺口。能证明部分正确时明确其边界，不用测试数或源码字符串检查代替功能结论。
