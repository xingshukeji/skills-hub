# 运行稳定性

把“稳定”落实为指定业务、数据规模、负载和观察周期内可核验的结果。沿用当前任务的目标与授权；本技能提供检查方法，不改变任务类型，也不自行增加压测、故障注入、部署或账号变更。

## 选择入口

先从用户问题选择相关维度，再按实际技术栈读取参考。未涉及的维度不成为本次固定门禁。

- 设计验证或调查覆盖缺口：读[场景与判定](references/scenarios.md)。真实数据规模、登录慢、完整生命周期和依赖恢复分别有独立入口。
- .NET 的分配、GC、线程池、连接及保留对象：读[.NET 诊断](references/dotnet.md)。
- Node.js 的堆外内存、事件循环、流连接及资源释放：读[Node.js 诊断](references/node.md)。
- 主机、容器资源与等待：读[操作系统诊断](references/os.md)。
- 修改本技能或相关路由：用[行为案例](references/behavior-cases.md)走查决定；自查与独立评测分别报告。

## 固定一次检查

复用任务或 Runbook 中已有的值，只补缺项：

| 输入 | 需要固定的事实 |
|---|---|
| 对象 | 源码或制品标识、实例/PID、启动时间、运行时与工具版本、主机或容器限额；前后实例分别记录 |
| 业务 | 原用户动作、固定身份用途、租户与权限、数据量及分布、有效结果断言；凭据只记录配置引用 |
| 负载 | 读写及登录比例、并发或到达率、思考时间、有效载荷、长连接与后台任务；区分计划量和实际完成量 |
| 时间 | 冷启动、首次使用、预热、稳定负载、积压、排空、静置、退出中的相关窗口；记录持续时间、间隔和自然回收事件 |
| 判定 | 业务延迟和错误预算、吞吐需求、资源限额及余量、释放和恢复期限、可接受波动；注明来源和适用范围 |
| 停止与恢复 | 负载或采样上限、停止条件、影响对象、原配置、数据清理范围和恢复检查 |

没有预算时，可以采样定位并报告趋势，不能据此宣称容量达标。没有代表性数据、实际业务断言或足够周期时，明确该结论的覆盖缺口。观察期限由缓存过期、令牌续期、定时任务和业务峰谷等实际周期决定，不统一规定“跑几分钟即稳定”。

## 执行与判断

1. 核对实际运行对象和现有观测入口。从低开销指标开始；采样命令、目标连接与配置仍由目标 Runbook 和现场工具帮助确定。已有监控足够时不新增采集器或常驻服务。
2. 在可比较条件下完成“业务循环 → 释放或取消 → 恢复观察”。把预热、自然 GC、重启、共享流量和采样开销标到时间线上。实例年龄或工作量不同的结果只能描述各自趋势。
3. 对齐业务结果、应用等待、运行时和系统资源。保留失败、超时、取消、慢样本及负载工具未发出的请求；按业务与冷/热状态分组，不用成功请求平均数替代错误率与尾延迟。
4. 对增长资源追踪数量、字节、保留者和释放条件。结合回收后基线、对象种类、连接或队列数量定位；RSS、GC 已提交内存、托管存活对象和容器内存不能互相替代。强制 GC、重启或清缓存会改变现场，不能代替自然释放证据。
5. 达到停止条件时结束本次负载或采样，保留停止原因。恢复本次改变的依赖条件和配置，核对在途工作、持久结果及资源基线；只清理可归属的测试数据、临时采样和注入设置。原业务数据及待处理业务不能为达标被清空。

堆转储、堆快照及高频跟踪可能暂停进程或增加内存和磁盘占用。执行前核对现有授权、资源余量和影响；不具备条件时使用已有指标并说明缺口。原始证据可能含秘密或业务数据，存放在目标项目允许的受控位置；报告只引用脱敏摘要，不提交原始转储、令牌或请求正文。

## 职责衔接

| 责任 | 消费本方法的方式 |
|---|---|
| `shzw-code-review` | 审查谁持有资源、保留多少、何时结束；用相关场景验证真实释放，不为所有状态统一加缓存或队列框架 |
| `shzw-runtime-operations` | 连接实际实例并执行有界采样、慢链路定位和恢复核对；开发、共享测试与部署实例分别识别 |
| `本入口的 system 方法` | 在用户明确要求的独立测试中组织负载、长时间运行和故障恢复；开发修复附带验证仍沿原 Development 任务 |
| `shzw-delivery` | 选择与本次制品、目标和风险相符的最小部署后检查；短期观察结论不扩大为长期或生产负载结论 |

这些技能是否可用由当前项目入口决定。本方法不要求安装外部 skill，也不代替它们各自的授权与操作契约。

## 输出

对选定范围给出“通过、失败、证据不足或未执行”，并写明对象、业务与负载、窗口、指标及预算来源、结果、恢复与清理状态。部分场景通过不覆盖未测场景；无 OOM、无重启或健康接口正常，只证明对应观察窗口内的事实。修复效果需要可比较的前后证据；根因需要保留关系、调用链或可复现实验支持。
