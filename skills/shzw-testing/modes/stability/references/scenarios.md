# 场景与判定

只选与本次业务、变更或故障相关的场景。每项检查先填实际预算、期限和规模；下文给出判断关系，不提供通用生产阈值。清理之后再次观察业务与资源，不能把清理动作本身当作恢复成功。

## 内存与释放

- **触发**：内存逐轮增长、资源退出后保留，或改动引入缓存、会话、订阅、锁、池和后台工作。
- **场景**：按同一数据规模重复“进入 → 操作 → 切换 → 取消/关闭 → 静置”；同时覆盖已有键反复访问与新键持续进入，区分有界缓存预热和随历史种类增长的保留。完整记录自然 GC；受控实验中的强制 GC 单独标注。
- **指标与判定**：比较峰值、单位时间及每完成业务循环的增长、释放后基线和持续增加的对象种类；同时观察托管或 V8 堆、进程与容器内存、缓存条数和字节、订阅及句柄。基线应在允许波动和资源预算内稳定，保留量与实际活跃业务或明确容量相符。只比较两个端点、只看分配量或重启后下降不足以通过。
- **清理**：停止本次会话、订阅和采样，确认所属资源释放；保留真实草稿与业务状态。

## 容量与延迟

- **触发**：需要验证已确定的业务容量，或并发、数据量增加后变慢或失败。
- **场景**：使用代表性数据规模与分布，覆盖列表、筛选、详情、已授权写入及回读；按实际比例混合请求。将并发登录与已登录业务流量分开。逐级升载，每级观察稳定窗口，再撤除负载。必要的过载场景须在本次授权范围内。
- **指标与判定**：同时报告设定和实际到达率、完成吞吐、在途数量、错误率、超时、P50/P95/P99、样本数、CPU、内存、连接池及负载端资源。区分到达率模型与固定并发模型；固定并发会随响应变慢降低发压速率，不能用吞吐下降后的低错误率证明容量。用既有工具报告丢弃迭代或未发出的请求。只在业务断言正确、需求负载达成、尾延迟与错误预算满足且仍有规定余量时判定通过。
- **清理**：停止发压并等待在途任务按契约结束；确认连接、队列和单用户业务恢复。只删除本次可归属的测试数据。

分位数是当前样本的统计。样本量、观察窗口或业务分布不足时标明尾延迟证据不足，不把少量请求的 P99 写成总体保证。失败和超时需与成功请求分布并列报告，不能因未完成而从尝试总数中消失。

### 登录慢链路

从原用户动作计到业务数据可操作。分别测凭据验证、认证回跳或令牌交换、平台身份与租户读取、应用准入与权限计算、首个业务请求及页面渲染；只记录实际存在的环节。用同一请求的脱敏关联信息连接浏览器时间线、服务端等待和数据库/认证调用，避免把并行耗时相加。

区分首次登录、重复登录、会话复用和令牌续期；保持固定身份与权限范围一致。重点核对每次登录是否重复初始化、权限是否写回、连接池是否等待以及依赖调用是否串行。已有账号复用遵循项目固定账号规则；没有账号变更授权时不改密、改权或新增身份。权限拒绝不能在统计时混成意外失败，也不能通过跳过授权换取低延迟。恢复后仍从原用户入口验证业务可用。

## 服务器资源

- **触发**：延迟、吞吐或内存问题可能跨出应用层，或需要核实实例资源预算。
- **场景**：在基线、负载和排空三个窗口，对实际进程、容器与宿主同步观察利用率、等待/饱和与错误，按[操作系统参考](os.md)选择入口。
- **指标与判定**：核对 CPU 配额与节流、线程及运行队列、内存压力与 OOM、连接池等待、套接字和文件句柄、磁盘容量及 inode、I/O 延迟和错误。结合配置上限、业务延迟及背景流量判断，不能因总 CPU 低或磁盘使用率低排除资源等待。
- **清理**：停止本次采集，核对输出占用；不通过删业务文件、扩容或改内核参数掩盖诊断结果。

## 队列与慢消费者

- **触发**：消息流、任务队列或消费者变慢时出现持续积压，或改变背压与缓冲行为。
- **场景**：在隔离且获准的范围内降低消费速度，观察持续生产、消费暂停、恢复、断开和取消。流连接同时覆盖客户端断开与模块卸载。
- **指标与判定**：记录产生/消费速率、积压条数与字节、最老任务年龄、在途量、拒绝或丢弃量、排空时间及取消后的资源。容量和满载行为按业务契约判断；恢复后在预算内排空，既定顺序、重复、丢弃与持久语义均满足。队列变短若源于静默丢失仍应失败。
- **清理**：恢复消费者速度，停止测试生产者，确认本次订阅与任务结束；待处理业务按原契约处置，不直接清空队列。

## 超时与重试

- **触发**：请求超时、用户取消、重复提交、连接断开或重试策略变化。
- **场景**：覆盖执行前取消、执行中取消、已提交但响应丢失、重复请求及多层重试。注入位置必须对应真实可达路径。
- **指标与判定**：比较客户端结果与后台完成时间、实际尝试次数、总时限、连接释放和持久副作用。超时响应不等于后台停止；重试不得突破既定总预算或产生契约外重复结果。非幂等写入结果未知时，先按业务查询或恢复契约处理，不盲目重放。
- **清理**：取消本次未完成工作并确认终态，核对最终业务结果；移除注入设置，保留必要幂等和审计记录。

## 外部依赖故障

- **触发**：数据库、认证、模型或其他实际依赖可能变慢、拒绝或不可用，或相关恢复代码发生变化。
- **场景**：在已授权的隔离边界内分别模拟延迟、错误、断开和恢复；一次改变一个因素。覆盖受影响业务与一条应保持可用的无关业务。未授权影响共享依赖时，使用已有故障证据或隔离替身，并注明真实性边界。
- **指标与判定**：核对用户可见结果、超时预算、线程/连接/队列、重试放大量和影响范围；恢复后从原入口重试或查询终态，检查重复写入、旧连接、失效身份及积压。恢复时限来自业务或依赖契约，不能以健康接口转绿代替业务恢复。
- **清理**：撤销本次注入，恢复原依赖条件与配置；验证原固定身份、业务回读及资源恢复。没有恢复证据时保留未完成状态。

## 长时间运行

- **触发**：问题只在长时间后出现，或需要验证过期、续期、周期任务及峰谷交替。
- **场景**：按实际周期选择观察时长，让代表性负载重复经过峰值、低谷与静置。覆盖新数据种类进入、缓存失效、令牌续期和周期任务；隔离测试中的时钟加速只能证明相应逻辑。
- **指标与判定**：逐轮比较低谷资源基线、尾延迟、错误、过期回收、续期和后台工作完成情况。无重启、OOM 只是一部分证据；周期未覆盖、样本不足或未知背景流量时不能给出长期稳定结论。
- **清理**：结束本次发压与采样，确认定时故障设置或时钟模拟已恢复；任务原本的计划和真实数据继续保留。

## 启停与升级恢复

- **触发**：启动、停止、模块装卸、身份/租户切换、升级或恢复路径变化。
- **场景**：覆盖启动就绪、运行中退出、重复装卸、取消及已有恢复入口；核对旧连接与在途工作。升级和回滚仅在当前任务已授权的测试或部署范围执行，程序回退与数据兼容分别判断。
- **指标与判定**：比较就绪和退出时长、端口/连接/订阅/锁数量、后台工作终态、持久状态和再次进入的业务结果。新路由不可达不证明旧连接已释放；启动成功不证明上一实例已经退出。资源所有者须在约定时机关闭所属资源。
- **清理**：关闭本次临时实例和连接，恢复原入口与本次修改的设置；核对状态可回读，不能删除工作区或数据库换取干净启动。

## 业务正确性与可诊断性

- **触发**：稳定性改动涉及身份、租户、并发写入、重试或故障反馈，或采样缺少业务结果。
- **场景**：按已授权范围验证有权/无权读取、跨租户隔离、既有撤权用例、并发修改和重复执行。使用有可区分记录的范围内/外数据；空列表不能证明权限过滤。
- **指标与判定**：断言业务内容、持久副作用及合法拒绝；错误证据能关联版本、实例、时间窗口和脱敏请求标识。成功状态码、零错误日志或管理员可用不替代普通用户与数据隔离结果。
- **清理**：恢复本次获准修改的测试权限、数据和故障配置，复验原固定身份；保留必要业务记录与最小诊断摘要。
