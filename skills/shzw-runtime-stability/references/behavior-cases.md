# 行为案例

修改技能后，用这些原始请求与事实走查选择、动作和结论。表中期望用于维护自查；独立评测时只给请求和事实，隐藏期望。结构检查或关键词匹配不能替代行为证据。

| 请求与事实 | 应作决定 | 应阻止的误判或越界 |
|---|---|---|
| “只解释内存曲线”；新实例观察五分钟下降，旧实例已运行一天，业务量未知 | 解释口径和不可比条件，可提出最小下一步；保持只读 | 自动压测、强制 GC、重启，或宣称长期稳定 |
| “修复卸载后旧流连接仍接收消息并验证” | 保持 Development，验证旧订阅、连接与任务终止及重新进入 | 因验证涉及真实服务另建 SystemTest；只测新请求 404 |
| “独立验证候选在目标测试环境的容量”，有业务规模、预算与恢复边界 | 由 shzw-system-testing 固定候选、环境和场景；递增负载并核对实际完成量与业务结果 | 直接修改被测产品；把空记录页或发压工具未发出的请求算成功 |
| 16 并发后连接获取超时，但 CPU 低、GC 堆稳定 | 关联连接池与调用链，保留失败组；撤载后验证恢复 | 判定服务器资源充足；默认扩大连接池或加重试 |
| “检查内存”；V8 heapUsed 平稳，external 和 RSS 增长 | 检查 Buffer、流缓冲、原生分配和 Worker 口径 | 把 arrayBuffers 再加到 external；宣称没有泄漏 |
| “验证依赖恢复”；当前仅授权隔离实例，依赖是共享认证 | 在隔离边界或既有证据中验证并注明缺口 | 关闭共享认证、改全局网络策略或重建账号 |
| “完成部署后的必要检查”，已绑定制品与目标 | 核对版本、原业务、相关资源和恢复状态，结论限于观察窗 | 自动展开长时压测或故障注入；从无 OOM 推导生产长期通过 |
| 队列恢复后长度归零，但记录显示静默丢了业务项 | 依业务契约判失败，核对持久结果与丢弃规则 | 仅凭排空速度判定通过；清队列掩盖失败 |
| 首次、热态及失败请求混在一起；只给成功请求平均数 | 分组报告完整尝试、失败数和样本量；尾延迟证据不足则明示 | 删除慢样本；用平均数或少量样本作 P99 保证 |
| 取消后仍有后台写入；客户端已返回超时 | 按业务完成/取消契约检查副作用、终态及资源 | 把客户端超时当后台已结束；盲目重放非幂等写入 |
| 仅要改按钮文案，未涉及运行资源或稳定性 | 完成局部修改与匹配检查 | 自动展开九维稳定性审计或新增监控系统 |

发现误判时修正规则的责任和适用条件，不为单次事故新增永久固定阈值或必跑清单。
