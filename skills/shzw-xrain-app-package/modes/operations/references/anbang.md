# 铵帮安装与开通

用于“安装铵帮应用”“租户准备好后安装铵帮”及已安装后的重新开通。沿[标准流程](../GUIDE.md#标准流程)完成用户已授权的结果，复用目标租户、身份、应用和安装。用户只要求解释或只读核对时保持只读。

## 找到项目入口和目标

通过工作空间项目路由或保存的项目列表定位铵帮 Local checkout。读取该仓 `AGENTS.md`，沿入口读取当前设计及运行契约中的本机入口和角色授权配置。项目命令在铵帮仓执行；技能安装目录不作为业务仓根目录。

从运行契约进入新模型实现说明，核对模型、包来源和已有验证事实。若当前项目提交提供批量开通入口，先核实该入口和其覆盖范围；没有时使用已交付的 `xrain-cli` 正式接口逐项开通，不依赖其他分支上的脚本。安装已交付包不要求取得 XRain 私有源码或重建包。精确版本、digest、目标 ID 和当前安装指针使用本次交付及目标配置，不在技能中固定某个测试租户或旧版本。

“重启租户”结合原请求区分服务重启、恢复租户启用和明确授权的重建。普通重启保留原数据和身份；只有原范围明确包含重建时，才由已有租户管理入口执行相应动作。准备完成后，以实际返回的租户和有效成员接续安装，不因更换租户另建维护者身份。

## 安装前必须具备的输入

| 输入 | 从哪里取得、如何使用 |
|---|---|
| 目标平台、租户、维护者 User ID、CLI profile | 从获准目标及原身份取得。使用目标租户的正式登录会话；需要创建租户或导入本地原包时，分别使用获准 Host 会话。 |
| 业务包及实际依赖的身份、版本和 digest | 按当前产品契约确认公共顾客、铵帮及业务所需的 Workforce 等依赖组合。先就绪公共依赖，再安装铵帮；已装版本直接复用，版本缺失沿原制品导入路径处理。 |
| 应用及业务角色 | 已有目标使用实际 ID；新目标通过受支持的应用和角色接口建立。不得将旧租户的应用、角色或 operation ID 复制给新租户。 |
| 门店销售、店总及发布成员 | 只使用本次声明的有效租户成员。空成员数组不表示清空现有成员，也不表示全部员工已开通。 |
| 安装请求和环境引用 | 每个需要初装或升级的包提供本目标的固定 `requestId`。Workforce 消息连接器等需要的凭据变量先在目标租户按 Runbook 准备；`tenantBindings` 引用其真实 ID，不放原始凭据。 |
| 宿主接入配置 | 使用目标 Runbook 指定的租户、应用、后台凭据引用及状态路径，保留原 Runtime、定义、会话和工作区。 |

现有租户先核对模型兼容性和原安装。新模型配置不能直接套到未验证兼容的旧模型租户；也不能为消除不兼容而自行卸载、重建或清库。

## 使用正式接口开通

使用 `xrain-cli` 和目标租户的原会话读取应用、包及安装现状。按[操作](operations.md)固定目标版本和请求身份，使用 `app preview`、`app install`、`app installation show` 与原 operation 接续安装；已有安装和应用保留原 ID。需要创建应用、关联资源、配置授权上限、角色和发布范围时，使用 `application` 的实际子命令与平台 DTO，整集合写入先读取并合并未获授权移除的配置。记录共享与成员授权分别按当前项目契约和实际接口核验。

业务目标包含销售助手时，还须核验该租户 Runtime 的目标定义已启用、工具与工作区可用；通过 `agent application show <应用ID>` 读取完整选用，合并原有选用后用 `agent application set <应用ID> --values-json <完整选用.json>` 设置目标及默认助手，再回读并使用 `agent use <助手ID> --application-id <应用ID>` 检查资格。选用接口失败时保留具体错误和原应用，按平台能力修复；不改库或创建重复助手绕过。

绑定缺失、配置冲突或未获准影响只阻断相关步骤，保留原 operation。日常启动和单独包升级不重放人员开通；已有声明被撤销时按项目合同处理。

## 核对授权来源和记录范围

| 职责 | 应有来源和范围 |
|---|---|
| 维护者 | 复用 `tenant_admin`，平台能力由 `xrain-admin` 提供；组合 `anbangSales`、`anbangMaintainer`、`storeassistOperator`、`workforceService`，取得已声明的资料维护能力。 |
| 门店销售 | `storeassistOperator` 与 `anbangSales`；读取获准基础资料，顾客和报价保持本人范围。 |
| 店总 | 在门店销售组合上增加 `anbangStoreManager`；当前仍保持本人范围，不因角色标签扩大跨销售访问。 |

所选铵帮包须实际交付维护权限集；顾客和协作权限继续来自各自公共包。包缺定义时由包维护者提供兼容的新版本，不能向 `xrain-admin` 逐项补业务权限掩盖缺包。迁移历史补权须以原回执证明替代来源已覆盖，并保留其他授权。

角色绑定、共享范围与应用准入分别核验。基础资料的业务读取和管理员维护规则依当前授权规划配置；顾客与报价不因此增加跨人员共享。包安装 `Succeeded`、权限集存在或导入按钮可见，都不能单独证明这些配置已经完成。

## 接到宿主并验收

1. 在目标 Runbook 中核对宿主实际连接的租户和应用。授权包含本机启动或重启时，从 Workforce 根的一键入口加载该目标配置，沿用原状态；不另起 Web/API 服务，不因安装改在线智能体定义。
2. 用 CLI 回读实际依赖和铵帮包的安装身份、版本、组件、角色、权限来源、共享、维护者准入和应用助手选用。只读对象检查证明当前维护者的读取，不代替普通销售或消息发送验证。
3. 使用原维护者核验产品列表、字段类型、资料维护和导入入口。用户要求导入客户资料时，按原授权转换、导入并核对结果；仅为验证而写入的合成资料应在获准范围内标记并核对清理结果。
4. 本次声明销售成员时，按原成员核验本人顾客、报价及相关范围外拒绝。若要求先通过 CLI 验证，先沿 CLI 完成真实业务操作及保存回读，再进入页面核验。真实资料缺失时，分别保留完整导入、报价和历史读回的未验证项；不能用空列表或管理员结果替代。
5. 回执分别说明包安装、开通配置和实际业务结果；必要的恢复记录保留目标、版本、摘要、资源与 operation，不保存 token。重复执行核验关系和数据保持，不能把“没有发送绑定请求”当作接口幂等性的证据。

## 失败时从哪里继续

| 停止点 | 接续方式 |
|---|---|
| 登录、401、403 或成员未就绪 | 按原身份和原业务动作核对会话、目标成员、应用准入及授权来源，使用访问权限入口恢复；不另建用户或换身份绕过。 |
| 缺原包版本或凭据引用 | 从本次交付及目标配置补齐前提，再以原配置继续；不重建包、不借其他租户引用试错。 |
| 安装 Waiting、Running、Finalizing 或回执未知 | 按原 requestId/operation 和当前安装状态接续，使用当前修订及确认；不换 ID 重装。 |
| 角色或权限集绑定回执丢失 | 可以重复提交原绑定；保留声明外配置，不先逐项查询来实现去重。 |
| 应用或角色创建回执丢失 | 定位原创建结果并复用真实 ID，不另建同名资源。 |
| 包已安装但业务授权不全 | 核对本包、公共包、应用上限、角色、共享和发布范围，使用正式接口补声明配置；缺包定义则回到包来源修复。 |
| 助手定义已启用但应用未选用 | 回读并保留现有应用选用，经 CLI 追加目标助手及默认值；接口不可用时保留错误并修复平台，不通过临时数据绕过。 |
| 需要清理旧包 | 分别盘点本地制品和平台版本及其安装引用；平台没有正式单版本删除能力时，保留未完成项，不以卸载其他租户或直接改库代替。 |
| 宿主仍连接旧租户或旧应用 | 修正本目标接入配置，并按原 Runbook 重启；不重新安装已正确的包或覆盖原运行状态。 |
