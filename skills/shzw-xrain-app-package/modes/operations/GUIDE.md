# 租户应用操作

本模式负责已交付应用的安装、开通、升级与恢复。用户要求应用可用时，完成下列标准流程；只要求安装单个包时，完成相应包操作及核验。复用原目标、已有效的回执和选择。消费原包不要求 .NET SDK、作者源码或平台私有源码。

## 标准流程

1. **确定目标和动作。** 沿用户请求及前文固定平台、租户、应用与人员。区分重启、恢复启用、重建和重新安装；重启保留数据、身份与安装，不能解释成清库或另建租户。已有目标和授权清楚时继续，不重新询问同一决定。
2. **完成必要前提。** 原请求包含租户创建、重建或成员接入时，先使用既有租户管理入口完成获准部分，再取得真实租户 ID 和有效成员。Host 管理员负责创建租户，租户管理员负责获准的租户内安装与配置。同一人复用全局身份，通过成员关系进入目标租户。凭据变量、账户及外部连接按包所需准备；已有有效配置直接使用。
3. **确定制品和依赖顺序。** 从交付清单或项目安装配置选定兼容的依赖包、业务包与精确版本，核对身份、摘要及目标支持。按依赖先后准备版本。版本已在目录时直接消费；缺版本时按[制品来源](references/operations.md#按交付来源进入)导入原制品。安装请求包含服务端预检；需要提前审阅影响时单独 preview，不固定重复预检。
4. **完成包安装。** 按[包安装顺序](references/operations.md#安装顺序)提交并跟踪原操作，处理已获授权的绑定、确认和冲突。已有活动操作先接续，成功后核对当前安装指针及组件；安装依赖已经就绪时不重装。
5. **完成应用开通。** 用户目标包含业务应用可用时，调用项目正式开通入口，依次处理应用资源关联、可授予权限上限、角色、包内权限集分配、记录共享范围、声明成员与应用准入。具体步骤按项目依赖确定；已有命令负责这些步骤时整体复用，不在技能中另拼补权脚本。凭据与租户配置不进入包，权限集定义由所属包交付。
6. **接到实际运行入口。** 核对宿主连接的租户、应用、后台凭据引用与包版本。授权包含启动或重启时，按责任项目 Runbook 使用原入口，保留状态；服务镜像发布仍由原交付入口处理。包安装或启动不会自动覆盖在线定义、导入业务资料或恢复人员授权。
7. **按原用户目标核验。** 分别核对包安装终态、应用开通配置和实际用户操作。按范围检查进入应用、读取字段、资料维护及相关允许和拒绝；依赖真实资料的导入或报价，须有对应输入和业务证据。空列表、可见按钮、管理员只读检查不能证明普通成员完整业务可用。未完成项保留具体停止点、原资源或 operation 及下一条件。

租户和账号准备按 [shzw-xrain-access](https://github.com/xingshukeji/skills-hub/blob/main/skills/shzw-xrain-access/SKILL.md) 处理；本机启动按 [shzw-runtime-operations](https://github.com/xingshukeji/skills-hub/blob/main/skills/shzw-runtime-operations/SKILL.md) 及目标 Runbook 处理。只加载本次确实需要的方法，原授权不因内部衔接重新申请。

## 重复执行与接续

| 操作合同 | 执行和恢复方式 |
|---|---|
| 添加角色、成员或权限集绑定，接口支持重复提交 | 直接调用已有接口，由服务端按关系集合保证重复执行。绑定回执丢失可以重复提交相同绑定，不把逐项查询、客户端去重作为幂等性的前提。 |
| 接口替换整个集合 | 为保留声明范围外的配置，读取并合并现有项，使用接口要求的修订条件。这里的读取用于合并与冲突处理，不是防止绑定重复。 |
| 创建租户、应用或角色 | 使用原受支持的请求身份或稳定资源标识；回执未知时先定位原结果，不按同名或随机后缀另建一份。 |
| 包安装、升级或配置维护 | 保存原 requestId、operation 和 revision，按[状态与恢复](references/operations.md#状态与恢复)接续；结果未知不换 ID 重装。 |
| 已有声明被管理员撤销 | 日常运行和单独包升级不重放人员开通；显式执行开通命令前核对其声明，按项目合同处理撤权与配置。 |

重复执行核对稳定资源身份、关系集合、声明外配置与业务数据；接口请求数量不必为零。命令返回的“已执行请求”也不等于新增关系。缺权限集定义或包控字段时修原包；只有未分配已存在的合法权限集时，才通过正式开通入口分配。
