# XRain 应用包

先识别用户要生成制品、操作已交付应用，还是修复已安装资源。修复先按下节判断归属，再选择编写或操作方法。有原 operation 就读取原记录和当前安装接续，结果未知不重复提交。市场发布、平台导入、租户安装和原用户可用分别验证。

编写与离线校验分支的工具要求 .NET 10 SDK；安装、预检与恢复不需要该工具，也不要求平台私有源码。Node.js 脚本单独要求 22.12+。服务端制品通过目标支持的统一构建端点生成，本地验证不冒充服务器准入。

保留稳定 ID、原包摘要、request/operation/revision 及业务数据。更换版本、覆盖定制、扩大权限或删除数据只能在已授权影响内执行。按原管理入口读取终态和安装指针，首次交付再核对选定组件和原用户业务动作；未配置和未授权与安装失败分别判断。

产品协议变化时，在实际责任项目验证读取器和消费者，同步本技能相关目录与离线工具。包编写、安装和服务部署的授权不互相代替。

## 修复先判断资源归属

用户只说字段不对、权限缺失、保存失败或初始化后仍不可用时，也要判断是否需要修包。元数据和权限虽然存放在数据库中，修复位置仍由资源及属性的管理归属决定。

先核对原用户失败的动作、目标安装版本及异常资源的稳定 ID。读取可用的管理描述，区分包控制的定义、租户可配置属性和业务值；再对照所属包的源码或生成器与已交付制品。缺少归属证据时先查组件、安装记录或责任项目，不按页面名称、权限集标签或所在租户猜包。

| 已查明的原因 | 修复位置与生效方式 |
| --- | --- |
| 包控制的对象、字段、权限条目、共享条件、编排定义或应交付的默认值有错或遗漏 | 修改原包源码或生成器，保留既有身份，生成新版本；通过正常构建、预检和安装/升级交付。升级保留合法的租户显式配置，采用新默认值按目标管理合同处理。不得以直接改库、管理接口就地改包定义或启动时补数据代替。 |
| 正确版本已交付，但目标仍是旧版、组件被隐藏或原操作未完成 | 按实际安装状态升级、恢复或接续原 operation；不另造包、重建对象或重复初始化。 |
| 租户允许的配置、人员与角色绑定、权限集分配或普通业务记录有误 | 在原授权内使用标准管理或业务入口修正；包初始化的记录在交付后按其实际管理合同处理，不为改一条业务值重发包。 |
| 平台固定资源、权限计算或包构建/升级机制有缺陷 | 由平台责任项目修复初始化或实现，并按既有授权交付；业务包不得复制平台基线或通过额外授权掩盖缺陷。 |

权限问题要沿实际授权来源核对包内权限集、平台基线、角色与直接分配。包升级删除权限项时，分别检查应用角色、租户角色和直接用户分配；静默或定时的拒绝也可能重新生效。同一包资源身份可跨租户复用，只判断目标租户可生效的角色关联。一个业务动作可能同时受公共包和业务包影响；修复一个来源后，其他来源仍可能继续授予权限。跨包依赖按各自归属和依赖顺序纳入交付验证，不把公共资源复制到业务包。权限集是所属包的资源，分配关系是另一项事实，不能把二者误当成两个包或移到别的包重复声明。

包构建或升级被拒绝时，先区分源码错误、目标版本不支持、合法租户配置冲突及平台缺陷，再沿相应责任方处理。不得为绕过拒绝而解绑现有角色、删权限来源、改安装记录或覆盖租户配置。只有当前升级合同允许且本次授权覆盖的配置处理，才随原操作提交；已有修复与目标升级授权继续有效。

验证修正能从责任源码重建，并覆盖本次受影响的初装或升级路径，确认无需手工补丁。实际升级后回读版本与组件，用原业务身份核对字段、有效权限和数据保留；权限变更同时验证相关允许与拒绝。若历史业务数据确需纠正，按其受管修复或迁移入口另行验证，不能以数据已修正代替源码修复。构建成功、包已导入和隔离测试通过均不代表目标已生效。

例如，包权限集漏了一个应交付的字段读取项，应修包并升级；已有正确权限集仅未分配给获准的新店员，应补原角色绑定；店员填错一条顾客资料，应走业务编辑。三种情况不能统一成“补一条数据库记录”。
