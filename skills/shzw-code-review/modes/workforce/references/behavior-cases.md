# 行为校验

维护技能时从下表选择受影响场景。先用原始请求与当前仓库独立作判断，再对照预期；若执行者已读过预期或前次结论，只能记为规则自查。技能结构检查、源码追踪、既有回归测试及独立模型回放分别说明。

不为这些场景创建账号、调整共享平台权限或启动部署。纯 review 保持只读；已有修复授权时才执行对应修改。

| 原始请求或材料 | 应观察到的审查行为 | 错误判断 |
|---|---|---|
| 审查应用开发的版本显示；搜索结果包含一个旧前端组件及 storefront 测试 | 从当前 Host、storefront 与构建输入确认实际页面提供者；只有当前可达的行为才判业务故障，退役残留按影响处理 | 只读组件就要求修复，或为旧页面恢复构建入口 |
| 交付测试中创建了 application-management/frontend 和 application-marketplace/frontend | 阅读测试的实际交付与断言，确认这些目录是否是排除旧资产的反例夹具 | 按路径名称删除仍保护退役边界的测试，或认为旧前端仍在生产运行 |
| 邮件菜单被隐藏，用户仍从收藏地址打开邮件 | 进入当前组合，分别检查显示偏好、路由可达和邮箱准入；再用模块被裁剪的场景核对不可达分支 | 把菜单隐藏当作撤销能力，或让裁剪后的地址落到默认页面 |
| 切换目标租户失败，同时旧页面仍有在途请求 | 分别核对目标失败时的原会话、切换成功后的旧 context 和迟到返回；沿真正的业务写入或读取检查影响 | 所有失败一律退出，或只看 Cookie 已替换就判隔离成立 |
| 群内出现 AI 姓名，另有一条真实结构化提及；Runtime 只返回最终文本 | 根据消息来源区分是否唤醒；区分 Runtime 输出与明确消息工具投递，不补造 Task 或聊天消息 | 以姓名字符串唤醒，或把模型最终文本当成已发表回复 |
| 任务改派后又改回，旧执行继续提交完成 | 查当前负责人、指派版本和本轮私有授权；确认目标包的实际支持，检查旧写权是否复活 | 只比较负责人相等，或从运行成功推导完成 |
| 有 Task.Read 的人打开执行对话，但不是原工作台会话创建者 | 追当前任务读者核验与 Task 关联的安全投影，同时验证无关私人历史不可见 | 一律拒绝合法任务读者，或使用创建者身份开放整段私人工作台 |
| 同事能查看顾客共享备注，希望继续本人接待；此前有另一个店员的对话 | 追同一顾客记录、两人的独立会话及各自权限；共享事实和私人历史分别核对 | 把顾客记录拥有者当唯一接待人，或把原店员对话转成共享会话 |
| 配置明确指定租户与 Runtime 目录，诊断给出不同目标；请求已收到流式响应头 | 追真实配置到两个消费者，核对取消后的读取与资源释放；Markdown 仅作审查依据 | 按环境名称覆盖显式配置，或要求启动解析诊断文档 |
| 用户只要求审查某个 Task 编辑缺陷，并给出文件类型汇总要求 | 定位 Task 当前动作、规则及直接消费者；按要求归类结论，保持只读 | 展开所有平台业务、创建长期活动、改账号或顺手部署 |
| 用户要求先改进审查技能，再复审历史热点并合并上轮问题 | 修改方法并验证适用边界；对产品沿真实入口复放旧反例并查同类路径，合并时保留当前状态和各触发条件 | 顺手修复产品；把技能检查通过当业务通过；把已知案例复放声称为独立模型发现 |
| 历史说“聊天允许丢失”，当前代码有原结果查询、去重与草稿恢复 | 读取现行最低保障定义，核对未知结果与恢复事实；保留合法增强，并检查业务写入的独立合同 | 为遵守旧句删除恢复机制，或把已有局部恢复说成无条件必达 |
| Task 与定时安排都显示“执行对话”，当前负责人已更换 | 分别查 Task 的关联安全投影与安排的本次执行人授权，核对同名界面后的不同业务对象 | 用 Task.Read 放开前任安排的私人对话，或一律仅允许会话创建者而阻断合法 Task 读者 |
| 导入预检后记录被别人修改，普通表单也携带 expectedValues | 从历史确认和当前合同分开判断文件导入覆盖与普通条件更新；实际核对两条路径 | 因用户接受导入覆盖就删除普通编辑保护，或以通用并发理由反复报已接受的导入行为 |
| 三仓源码已取得，本机运行仍显示旧 Runtime；当前已有源码准备入口 | 核对实际包路径和来源摘要、配套配置及本机准备结果，运行当前预览入口的定向测试 | 强制先发布内部公共包，或从已安装最高版本推定 npm 后续仍消费该版本 |
| 历史政策已到期、部分报价条件缺失，用户确认这就是当前真实资料 | 查正常阻碍的展示、适用政策和保存规则；区分缺条件、无适用政策与程序错误 | 为得到成功报价篡改政策日期或价格；把所有缺值统一当成数据缺陷 |

通过条件是审查选择、判断依据、证据范围和授权边界正确。案例数量或能够复述规则不能证明实际审查能力；新反例应先修正产生错误的选择或判断，不复制整段故障历史。
