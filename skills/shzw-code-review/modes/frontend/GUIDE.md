# 前端视觉与体验评审

用于前端页面 review、截图评审、审美评价，以及页面开发后的视觉自查。以 **Awwwards、Webby Awards、FWA 获奖级网站的完成度为品质基准**，从**排版、留白、视觉层级、色彩、动效、微交互、响应式和原创性**逐项审视，持续自检、优化、复验，直到本次范围内没有明显可提升之处。

品质判断服务当前用户与产品。优秀作品提供阅读节奏、空间组织、识别和反馈的参照；采用具体处理前，说明它对当前页面的收益。业务工具可以通过克制、清晰和一致达到高完成度，不必增加展示站的头图、装饰或动画。

## 选定范围与动作

沿用用户已给出的页面、截图、报告、主要任务和视觉规范。整组评审逐页覆盖；局部修改检查受影响画面与消费者；纯逻辑或接口 diff 沿代码审查方法处理。截图数量和检查轮数由实际范围决定。已有信息足够时直接开始，不为评审格式或缺少品牌资料追加问卷。

只读评审交付发现与建议；已有开发或修复授权时，继续完成范围内的调整和复验。视觉调整保留业务行为、字段语义和有效设计。内部契约约束行为、数据与责任，可见内容仍须有用户任务依据；技术标识在管理员排障等确有需要的场景中保留。

## 按顺序审查

1. **列出画面。**记录页面或状态、用户主要任务、视口和截图来源。保留原图编号；补查截图另行编号，注明当前版本或环境。
2. **逐张看原图。**先看整体构图，再看文字、边缘、对齐和控件。核对目标窗口、完整区域和预期状态；误截、意外裁切和未稳定画面重新取得。加载、空态和错误本身属于审查对象时，保留截图并说明触发条件。缩略总览、源码和 DOM 不替代原图观察。
3. **逐项检查品质。**按下表记录当页具体问题及应保留部分。适用维度缺少证据时标记待验证；不适用的维度说明原因，不强行凑发现。
4. **跨页比较。**比较同类页、同一应用的不同入口、同一控件的不同状态。合并共同原因，保留全部受影响页面及定位。
5. **补查实际行为。**围绕静态疑点和原任务打开相关页面、菜单、抽屉、弹窗及长内容，完成所需操作和视口复查。可继续核实的疑点先核实，再确定结论。

## 八项品质检查

| 维度 | 如何判断 | 证据与保留边界 |
|---|---|---|
| 排版 | 标题、正文、说明的字号和字重是否形成清楚阅读顺序；基线、左右边缘、行距是否一致；长名称、数字和说明是否便于扫描 | 在原尺寸下看不自然断词、文字被次要按钮挤压、同类控件位置漂移；保留足够字号和点击面积 |
| 留白 | 空间是否表达分组；主表、表单或内容能否及时进入视野；重复页头、统计卡、外框及无实际选择的侧栏是否挤占工作区 | 可记录内容起点、可用宽高和占比，找出具体原因；不设全站统一比例，也不为填满空白新增内容 |
| 视觉层级 | 当前位置、主要信息和下一步是否明确；标题、导航、搜索筛选、数据工具及业务动作是否主次清楚；容器是否承担独立用途 | 找出重复标题、竞争的选中样式、低频动作抢占注意及状态归属不明；保留有业务意义的上下文与导航 |
| 色彩 | 强调色、状态色、中性色是否协调且语义稳定；说明和边框是否可辨；错误是否同时有文字或形状提示 | 精确对比度取实际前景、背景、透明度、字号及字重后计算；仅凭截图只报告可见风险，不给精确合规结论 |
| 动效 | 过渡是否解释状态变化、维持位置感；开始、结束和中断是否连贯；动画是否妨碍阅读或操作 | 实际观察时序和流畅度，按需检查减少动画；没有动效本身不是缺陷，静态截图不能证明流畅 |
| 微交互 | 悬停、按下、焦点、等待、成功、失败与重试是否及时清楚；表单完成条件、禁用原因和错误归属是否明确 | 操作核对 Tab、Esc、焦点返回及相关校验；保留有效焦点。区分首次无数据、搜索无结果、未选择和失败，提供真实可做的下一步，避免重复报空 |
| 响应式 | 关键入口、内容和操作是否在目标尺寸下可达；长文案、表格、抽屉、弹窗及软键盘如何占用空间；滚动容器是否争夺操作 | 记录桌面及相关窄屏的实际尺寸；单列重排不等于体验通过。表格局部横向滚动可合理，仍须保留上下文、表头和操作 |
| 原创性 | 字体、图形、图标、色彩和交互是否形成适合该产品的整体表达；同一应用能否跨导航、目录、市场及已打开列表保持身份；不同应用是否易于区分 | 需要参照时选与当前场景相近的获奖作品，指出可借鉴处理及适用条件；避免模板拼接、随页面换身份或直接复制作品 |

## 按证据约束结论

使用已有预览入口及当前可用的浏览器或原生工具，并遵守对应工具方法。沿用既有身份；只读评审不提交、发送、删除或改变共享业务数据。必须写入才能验证的行为使用已授权隔离场景，否则说明具体缺项。纯截图评审可直接完成可见部分，不以源码、登录或额外插件为前提。

区分图中确认、实际操作确认、源码确认和待核实。截图不能证明按钮校验、动画流畅、键盘行为或整站无障碍合规；浏览器窄屏不代表原生客户端。证据冲突时核对版本、视口和数据状态，不能拼接不同版本的局部成功。

## 形成可修改、可复验的报告

先给页面质量结论与最高影响事项，再给完整逐页记录。每页写明编号、名称或状态、视口、截图、视觉结论和应保留部分；每项发现说明**位置与现象 → 用户影响 → 具体建议 → 复验方法**。确无明显问题时给出已检查范围和保留依据；个人偏好不冒充缺陷。

| 视觉结论 | 判断依据 |
|---|---|
| 优先调整 | 妨碍主任务、关键入口或主要信息识别，或造成明确操作及可访问性障碍 |
| 需调整 | 任务可完成，但存在持续扫描负担、误解、注意力竞争或跨页不一致 |
| 局部打磨 | 主路径清楚，仍有具体排版、措辞或节奏改进 |
| 保持 | 已检查部分有明确优点，未发现需要改变的问题 |

问题等级、证据和修复状态分别表达。“待核实”不表示轻微，“已修复”须对应已复验的版本和状态；同页已修复一项，不代表其他问题也已通过。

例如：**金融政策页，优先调整，图中确认。**1280×720 画面中的表头约在 y=420px，上方重复标题、选择区和计数条挤占首屏。建议收紧重复层级，让用户更快进入政策内容，保留有业务意义的品牌选择。复验时对照同尺寸画面的内容起点，并补查窄屏入口与表格操作。这里的坐标用于说明当前问题，不作为其他页面的固定标准。

少量页面直接展示截图和说明；多页形成可打开的逐页图注报告，提供全量索引及图中定位。沿用用户已选格式；未指定时自行选择可用的本地报告。交付前核对图片可见、图注对应、定位不遮挡内容和覆盖完整。截图及报告留在允许的本地证据位置，不提交客户资料。

## 自检、优化与完成

评审完成与页面质量分别判断。只读评审须覆盖原范围、核实可调查疑点，并交付逐页发现和限制；页面存在待改问题不妨碍报告完成，也不允许据此宣称页面通过。

已有实现或修复授权时，按 **整体回看八项品质 → 调整明确问题 → 新版本实际复验 → 再看整体** 继续工作。范围内可处理的明显问题继续完成，不留作“可选优化”等待再次提醒。每轮用阅读、识别、操作或视觉协调上的具体收益说明调整依据，保留已有效的设计。

复验沿原页面、视口和状态展开；共享组件变化覆盖受影响的代表性消费者，手机布局变化回看宽屏及相关空态、长内容和弹层。发现回归就继续处理，只补变化影响的证据。

当原要求已覆盖、范围内明确可改的问题已完成并验证，且整体回看未发现明显改进项或新回归时结束。未验证项、确实受阻和授权范围外的事项分别说明，不能用留项掩盖可完成工作。纯偏好不驱动无限重设计；“没有明显可提升之处”只针对本次已检查范围，不等于获奖认证或所有场景完美。
