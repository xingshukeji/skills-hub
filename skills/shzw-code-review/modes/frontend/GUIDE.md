# 前端视觉与体验评审

用于页面 review、视觉检查、截图评审，以及“再仔细看看”“提高审美”“按优秀网站标准检查”等请求。目标是判断当前用户能否清楚识别信息、理解操作并完成任务，同时评估排版、留白、层级、配色和产品辨识度。无错位、无溢出、构建通过只证明其中一部分。

## 固定对象与质量目标

以 **Awwwards、Webby Awards、FWA 获奖级网站的完成度为品质基准**。完成初稿或修复后，从**排版、留白、视觉层级、色彩、动效、微交互、响应式和原创性**逐项自检，并持续优化、复验，直到本次范围内没有明显可提升之处。只读评审将这项要求用于逐页审视和建议的完整度；已有实现或修复授权时，将它落实到实际页面。

先沿用用户提供的页面、截图、报告和已确认范围。区分整组逐页评审、局部组件审查和开发后的自查；用户指定全部页面时逐页覆盖，局部修改只查受影响画面与消费者。截图数量由范围决定，不设固定张数或发现数量。

读取已有用户任务、产品行为和视觉规范。内部契约约束数据、行为与责任，不自动成为可见文案。已有依据足够时直接开始；缺少品牌资料也可判断布局和使用问题，不要求用户先填写设计问卷。

把优秀作品的完成度落实为可观察判断：主内容是否获得合适空间，阅读路径是否清晰，同一产品是否易于识别，操作是否有及时反馈，窄屏是否仍可完成任务。原创性体现为适合该产品的表达和稳定身份；业务工具不必仿照展示站增加头图、动画或新交互。审美建议要解释它如何改善当前画面。

## 逐页建立画面证据

1. 列出页面或状态、用户主要任务、截图来源及视口。已有截图保留编号；当前补查另行编号并注明版本或环境，不能把旧图当作当前运行结果。
2. 逐张打开原尺寸图片，先看整体构图，再看文字、对齐、边界和控件。总览缩略图可用于发现跨页差异，不能代替逐张检查。只读 DOM、源码或截图文件名不算看过画面。
3. 核对截图是否展示目标窗口、完整区域和预期状态。误截、意外裁切或尚未稳定的画面不能作为正常完成态；加载、错误、空态本身是审查对象时保留，并注明触发条件。
4. 当页记录具体发现、影响、修改方向与应保留部分。可继续调查的疑点先保留，再用实际页面或源码核实；没有证据的问题不强行凑数。
5. 看完后横向比较同类页、同一应用的不同入口，以及同一控件的不同状态。把共同原因合并，但保留每张图的结论和定位。

## 从整体到细节判断

按页面实际内容选择下列维度。每个发现都要落到位置、可见现象和用户影响，不能只写“层级不清”“不够高级”。

| 维度 | 具体看什么 | 可用证据与判断边界 |
|---|---|---|
| 信息占比与首屏 | 主表、内容或表单从哪里开始；重复页头、导航、统计卡和外框占多少空间；侧栏是否承担真实选择 | 可记录内容起点、可用宽高或占比，说明哪些重复信息挤压业务。数值来自当前画面，不能变成所有页面统一的百分比门槛 |
| 排版、对齐与节奏 | 标题、正文、说明的字号和字重关系；基线、左右边缘、行距和间距；名称、数字、长文本的扫描路径 | 检查不自然断词、按钮挤碎说明、同类控件位置漂移。留白须支持分组和阅读，不能为了密度压缩点击区域或可读性 |
| 层级、导航与操作 | 当前所在位置、页面标题和主要动作是否明确；搜索、筛选、数据工具与业务动作是否分组；嵌套容器是否有独立用途 | 同时出现多种高强调选中样式、重复标题或次要动作抢占注意时说明竞争关系。主次由当前任务决定，不机械删除必要导航 |
| 配色与可读性 | 强调色、状态色和中性色是否有稳定含义；浅色说明和边框是否可辨；错误是否只靠颜色表达 | 精确对比度需取实际前景、背景、透明度、字号及字重并计算。只有截图时可指出风险，不把目测当精确合规结论 |
| 应用识别与一致性 | 同一应用在导航、目录、市场和已打开列表中是否沿用名称与图标；不同应用是否容易区分 | 稳定身份优先于随页面换图标；业务名称应支持识别。技术标识仅在目标用户的任务确实需要时突出，不一律隐藏诊断信息 |
| 空态、表单与状态 | 区分首次无数据、搜索无结果、尚未选择、加载和失败；下一步是否就近且真实可做；必填、禁用原因和结果归属是否明确 | 空态不能只是左右重复报空；已有操作可就近呈现，但不为美化新增业务能力。按钮颜色不能证明校验或权限存在缺陷 |
| 响应式与容器 | 关键入口是否被横向菜单藏住；多层滚动是否争夺操作；表格、抽屉、弹窗、长文案与软键盘是否挤占内容 | 单列重排和没有整页溢出仍不足以证明手机体验。数据表的局部横向滚动可以合理，需看表头、上下文和操作能否使用 |
| 动效、微交互与完成度 | 悬停、按下、焦点、展开、等待、成功和失败反馈是否连贯；过渡是否解释状态、减少突变；风格是否适合用户和品牌 | 流畅度、反馈时序和减少动画的表现需实际操作。静态图只能证明对应一刻；不强制加动效，也不凭截图宣称动画流畅 |
| 原创性与产品表达 | 字体、图形、图标、配色和交互是否形成适合该产品的整体表达；是否只是通用模板或无关风格的拼接 | 需要建立品质参照时，查看上述奖项中与当前场景相近的优秀作品，指出值得借鉴的具体处理。保留产品身份与易用性，不靠换主题、堆装饰或复制作品代替原创表达 |

例如，资料表的表头到 720px 高画面中的约 420px 才出现，先找上方重复标题和多层选择区，再说明首屏内容被挤占。不能仅因表头位置较低就删除有业务意义的品牌选择。应用卡片说明被固定按钮挤成短行时，可减轻该次要操作的视觉重量，并在窄屏核实名称和说明是否恢复可读。

## 用实际操作补齐判断

在当前工具和授权范围内操作真实页面。先读取相应浏览器或原生工具的使用方法；项目已有预览入口时使用该入口，不把安装额外插件作为评审前提。

- 根据静态疑点及用户范围补查代表性的桌面和窄屏尺寸，记录实际尺寸。打开相关抽屉、弹窗、菜单和长内容，检查关键操作是否可见、可达。浏览器窄屏结果不能冒充原生客户端证据。
- 对操作反馈检查实际触发及随后状态。按需检查键盘焦点、Tab 顺序、Esc 关闭、焦点返回、输入校验、等待、失败和重试。保留已经清楚有效的焦点样式，不为视觉简洁去掉可见反馈。
- 对动效观察开始、结束和中断时的表现；有相关支持时检查减少动画。截图不能证明动画、键盘可用性、屏幕阅读器体验或整站无障碍合规。
- 只读评审不提交、发送、删除或修改共享业务数据。沿用既有身份；只能通过写入才能验证的行为，使用已授权隔离场景，否则标注具体未验证项。纯截图评审或环境不可达时，继续完成可见部分，不声称补查已完成。

证据冲突时先核对版本、视口、数据状态和当前实现。区分截图中确认、实际操作确认、源码确认与待核实，不能将不同版本的局部结果拼成当前全部通过。

## 输出能直接用于修改的逐页报告

先给整体结论和最值得处理的问题，再给完整逐页记录。每页包含：编号、名称或状态、截图、结论、问题位置与现象、用户影响、具体建议、应保留部分及证据限制。确无明显问题时说明已检查范围；未检查的维度保持未验证，不能用一个“正常”概括整页。

结论按影响区分：

- **优先调整**：妨碍主任务、关键入口或主要信息识别，或造成明确操作和可访问性障碍。
- **需调整**：可完成任务，但存在持续的扫描负担、误解、注意力竞争或跨页不一致。
- **局部打磨**：不影响主路径，仍有明确排版、措辞或节奏改进。
- **保持 / 已修复 / 待验证**：分别说明保留依据、对应修复版本或缺少的证据。

少量页面直接在回复中展示截图和对应说明；多页默认形成可打开的逐页图注报告，保留全量索引，在截图旁放编号说明或不遮挡原内容的定位标注。让用户能从问题直接找到原图和位置，不只交付一段审美总结或一串本地文件路径。沿用用户已选输出方式；没有指定时自行选可用的本地报告，不为格式再次询问。交付前检查图片可见、图注对应、编号与覆盖范围完整；截图和报告留在允许的本地证据位置，不提交客户资料。

相同根因可汇总到一项修改，但仍列出受影响页面。准确区分可用性缺陷、视觉改进建议和个人偏好；不能将全部建议标成同一严重级别，也不以发现数量证明质量。

## 修复后的自查与停止条件

只要求 review 时交付报告。已有修复授权时接续处理已确认问题，保留业务行为和做得好的部分；不因内部转入开发流程再次请求同一授权。

完成初稿或一轮修复后，按以下顺序继续自检：

1. 回看整体页面，逐项检查上述八个品质维度，重新判断主次、阅读节奏及产品表达，不只核对刚改的控件。
2. 对发现的明显问题，结合用户影响选择具体调整。已有修复授权且能够处理的问题继续完成，不把它们留作“可选优化”或等待用户再提醒。
3. 用实际加载的新版本，在对应视口和状态下复验。修复共享样式或组件时检查受影响的代表性消费者；修复手机布局时复查宽屏及相关空态、长内容和弹层。
4. 根据复验结果继续下一轮，直到已检查范围内没有明确、可说明收益的明显改进项，且没有发现本轮引入的回归。只补变化影响的证据，不反复跑无关检查，也不预设固定轮数。

纯 review 的完成不要求页面已经修好，但须完整报告已确认问题。实现或修复的完成须有对应画面与操作证据；未验证项、授权范围外事项和确实受阻的改进分别说明，不能用留项掩盖仍可完成的明显问题。剩余纯偏好不驱动无限重设计；“没有明显可提升之处”限定于已检查范围和证据，不代表获得奖项认证或所有场景均已完美。

## 参考与适用边界

- [Awwwards 评审](https://www.awwwards.com/about-evaluation/)同时考虑设计、可用性、创意和内容；用于提醒评审兼顾质量与使用，不把奖项权重变成项目验收分数。
- [Webby 评审](https://www.webbyawards.com/judging-criteria/)覆盖内容、结构导航、视觉、功能、交互及整体体验；具体建议仍须由当前产品和画面支持。
- [FWA](https://thefwa.com/)与上述奖项的优秀作品共同作为品质和原创表达的参照；借鉴时说明对应页面、值得学习的处理及当前产品的适用条件。
- [W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)与[可见焦点](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)用于核对对应检查项。普通文字通常要求至少 4.5:1；按字号、字重和例外判断，不能向上舍入临界值。

这些来源是判断参考，不要求每轮重新浏览或安装外部设计插件。需要引用精确标准、标准变化或用户要求最新依据时再核对官方来源。方法边界可用[相邻判例](references/behavior-cases.md)自查；作者自查不等于独立行为评估。
