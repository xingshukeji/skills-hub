# 产品需求文档

为人和智能体写可以独立理解、讨论和验收的需求。先按用户要求确定产品、读者和功能边界，再从目标项目入口定位产品契约、当前设计、真实类型与测试。一个已确认的用户目标可以是一份 PRD；不要按源码文件或页面机械拆分，也不要把相邻产品、企业定制或未批准的未来能力混入标准功能。

## 判断事实

- 把已确认的产品目标、当前代码或部署证据、未确认事项分开；实现不自动成为目标，设计不自动成为已交付。无法核实的字段、默认值或失败行为标为待确认，不推测。
- 解释产品和功能定位、参与者的真实任务及边界；先用一个具体场景说明输入、动作与可观察结果。一般化示例不得包含客户资料或未经确认的能力。
- 以责任项目的 ProductContract 等正式来源维护规则。PRD 可以完整解释已确认需求，但不能成为静默修改规则的第二权威；要求变化先修订唯一所有者，再同步 PRD。链接用于追溯，不代替正文中的关键说明。
- 优先按业务动作描述功能、权限和页面反馈；区分可见、可操作、已保存、已触发和执行成功。对外部系统只声明真实接口和约定，不承诺本产品无法保证的结果。
- 核心行为尚未决定且会改变实现、权限或业务结果时，先核实现状和真实约束，再说明可供决定的具体选择、影响及推荐。取得明确决定后更新事实所有者；没有决定时指出受影响的开发与验收范围，不用一行“待确认”伪装成完整需求，也不把建议或现状写成已批准目标。

## 写清规则

先画出该功能的实际用户旅程，再按核心动作核对“谁在什么条件下，输入什么，造成什么状态或数据变化，成功、失败或结果未知后能做什么”。动作涉及多个角色、状态或读取入口时，用一张表或具体例子说明交叉条件；不要只写“按权限判断”。简单功能不强制展开无关章节。

按功能需要说明：

1. 业务目标、范围、使用角色、前置条件与代表性场景。
2. 功能动作及谁可以操作；保存、修改、撤销、退出、换用户和失权的影响。
3. 每个重要字段的业务含义、必填性、允许值、默认值、来源、校验、变更限制与显示方式；没有事实的具体值明确标记。
4. 从输入到执行、结果、历史和状态变化的顺序，说明条件、时区、版本、并发、失败、重试、恢复及不支持事项中实际相关的部分。
5. 与其他产品、组件、数据和授权的协作；逐项说明责任主体及不能推导的关系。
6. 可观察的正常与异常验收场景；把目标要求、已验证范围和待确认项分别写清。

字段和状态的说明要与动作连起来：明确实际可选值、来源、默认值、生效时机和修改限制；业务事实缺失时写出影响及待确认问题，不以“以接口为准”替代已经能查到的关键规则。失败要对应具体阶段、已确认结果、保留内容和可做动作；把部分成功、拒绝和结果未知分开，不假定业务回滚或重试安全。建议提示与已实现提示分别标明。

涉及 XRain/Workforce 时，沿责任项目入口查产品契约、直接消费者、平台元数据与授权、真实类型和测试；再按实际链路区分 Workforce 的用户入口、XRain 的身份/数据/调度、Runtime 的会话/执行及业务服务的结果。不是每项功能都涉及所有组件，也不为 PRD 引入新组件或第二套事实源。普通 Task 与定时任务在身份、触发、状态和历史权限上可能不同，不能套用同一规则。具体对照见[平台判例](references/platform-examples.md)。

使用读者能理解的中文，并在首次出现时解释必要术语。表格用于字段、状态和权限对照，步骤用于时序；不强制所有功能使用同一空模板。不要把实现或治理细节转换成用户界面的文案。度量只在任务需要且有依据时提供，区分已有数据、用户给定目标和待验证假设，不虚构基线、阈值或发布计划。

对定时或其他自主执行功能，用具体例子区分执行身份、实际执行配置及其来源；核对版本冻结、重叠或错过、人工处理、变更与失权后的不同读取入口。对相关失败写清触发条件、系统已知结果、用户可见提示、保留内容和下一步；结果未知时不能假定未执行或安全重试。将产品目标与当前代码的差距写在同一条业务链中。用户要求 SVG 或图示能帮助首次阅读者理解时，提供与正文一致、可放大的图，并检查真实渲染。

## 多功能交付与核对

用户要求覆盖系统功能时，先由产品范围、独立用户目标和实际消费方建立目录；逐份沿该功能的关键动作、角色、字段、状态、异常、组件与验收查证和修订，记录已核对范围及缺口，不给所有文档机械粘贴同一套规则。每份文档从目录可发现，读者无需先阅读聊天记录。新建目录遵循责任项目的 StructureContract，文档检查不替代业务事实核对。

完成后用至少一条正常主线和与该功能有关的失权、状态变化、部分成功或未知结果反例，检查读者能否从正文判断下一步；逐一核实图示和相关页面说明没有把目标说成现状。再检查首次阅读者能否讲清输入与结果，执行智能体能否找到事实来源和未决项，以及引用是否可达。文档事实核对不等于运行验证。用户要求只讨论或先理解时保持只读。
