# 接入应用修复

## 确认实际调用方

先保存非秘密的调用方信息：认证中心、client ID、授权 scope、完整回调地址、应用类型。来源是本次授权请求和调用方已加载的配置，而不是某个示例默认值。

- 平台 XRain CLI：目标平台公开的 `GET /api/application/v1/cli-config` 提供 authority、clientId、scope 和 redirectUri；这些是中心登记的依据。原生 CLI 使用授权码 + PKCE，通常回到本机 loopback。
- 网页应用：使用实际配置的浏览器公开入口、登录回调、退出返回地址和来源。服务直接监听地址不一定是已登记的浏览器入口；先使用已登记入口完成原验证。
- 独立应用市场等其他消费者：读取其自身接入配置，不能套用平台 CLI 或业务网页的 client ID、scope 和 audience。

`client_id` 无效只说明中心拒绝本次客户端请求，须检查登记、启用状态和实际 issuer，不能直接断言账号不存在或密码错误。scope、回调拒绝也不需要重置用户密码。

## 在中心核对和修复

1. 用已有且获准的中心管理员进入 `/admin/clients`，按完整 client ID 核对。存在时打开“编辑”读取现值；先核对是否指向正确中心。不要覆盖同名客户端的其他在用回调或 scope。
2. 当前修复已授权、调用方配置明确且完整 client ID 确实不存在时，选择“添加应用”。填入真实 client ID 和用途名称，设置正确应用类型。已有客户端只在“编辑”中补齐已授权的缺失字段，保留其他在用值。公开客户端不创建客户端密码。
3. 本机 CLI 选择“本机命令行工具”，使用 CLI 提供的完整回调地址，包含端口和末尾斜杠；不要填网页退出地址或 CORS 来源。网页类型按调用方实际契约填写对应字段，不因排查方便新增任意回调或来源。
4. 在“接口权限”中只选择调用方请求且本目标已存在的业务 scope。`openid profile` 是登录协议 scope，不要创建同名业务 scope。已有 scope 的 audience 映射由 `/admin/scopes` 读取复核，不能把其他平台/市场的 scope 改给当前消费者。
5. 新客户端内置账号密码登录可用，外部渠道仅按当前授权需要选择；编辑既有客户端时保留原有渠道设置，不借修复回调改变登录方式。保存并重新读取，确认类型、启用状态、回调和权限与目标一致。缺少 scope 或 audience 契约时先查目标所有者，不创造宽泛权限。
6. 用新一轮原应用登录或 CLI `auth login` 验证实际回跳。CLI 显式选目标 server、tenant、profile，后续管理操作使用 `--auth session`；检查远端真实接口。401/403 转到身份与业务授权核对，不自动给用户加权。

接入配置登记为非人员的公开 OIDC 客户端，记录责任项目及回调/scope，不计入固定人员数量。不要因为配置需要保存就重启共享服务或修改部署基础参数；中心管理页面保存后直接验证。

## 独立检查两条链路

中心建号使用管理员网页，不依赖平台 CLI 客户端。需要快速进入业务应用时，账号准备与原应用登录应先完成；平台 CLI 客户端只有在使用 CLI 时才是必要条件。若用户同时要求修复 CLI，则单独验证 CLI 新会话和权限，不把一条链路的结果冒充另一条。
