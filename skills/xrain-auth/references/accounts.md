# 固定账号准备

纳管系统先查台账中的固定账号约定、生产账号规划、账号清单及使用规则。复用同一认证目录中的固定身份；不同租户靠成员关系，缺密码走原身份获准恢复，不按任务新建替代人。

已有身份和凭据直接登录原应用。需要查重/创建/恢复时，用原中心管理员从 /admin/login 进入 /admin/local-accounts 按完整登录名查询，并在 /admin/users 核对外部主体；读完匹配分页。重定向、查询失败不代表不存在。

| 现状 | 动作 |
| --- | --- |
| 普通主体已有、只缺本地凭据 | 已获准时在该用户“设置本地登录”，保留主体 |
| 身份确实缺失 | 创建固定普通账号，提交“创建并生成激活码”；不勾管理员 |
| 待激活、原码可用 | 继续 /login/activate |
| 原码丢失/过期、密码缺失 | 原身份恢复需已有授权；“恢复密码与验证器”会撤销旧登录、清除验证器 |
| 锁定、停用、到期 | 按具体状态及授权处理，不另建身份绕过 |

提交未知先查是否生效。激活码只留受保护上下文；在 /login/activate 完成密码及要求的 MFA/恢复码。新合成身份用系统随机密码，保存到指定秘密存储，非秘密登记记录用途、稳定主体、角色、范围、责任方及创建入口。管理员发码不依赖邮件或新开登录渠道。

原应用再发起正常统一登录，核对 issuer/sub 与平台 userId、租户和准入；同名不代表已关联。需要平台接入时读[准入](platform-access.md)，保留原成员和数据。重跑准备须复用身份、密码、MFA 与角色。需要本人验证码仅交回该步骤；最高管理员要求专门恢复入口时不能新建替代管理员。
