# 固定账号准备

## 查重与用途

1. 确认原应用、认证中心、业务平台和目标租户。受服务台账管理时，先读取固定账号约定、生产账号规划、账号清单和生效使用规则。
2. 默认复用同一认证目录的已有身份。核对固定用途、登录名、角色、权限范围、责任项目和受管创建入口；缺失时先补齐非秘密声明。不能因日期、任务或应用不同另建同用途账号。
3. 新成员首次激活、尚无业务身份或不同权限隔离确实需要新人物时，选用目标约定的固定人物名。已有身份缺密码走原账号恢复，不把新建账号当恢复。
4. 已有登记且凭据可用时，直接以该普通身份登录原应用，无需先取得中心管理员会话。只有需要确认身份不存在、创建、设置本地登录或恢复时，才使用已获准中心管理员打开 `/admin/local-accounts` 查完整登录名，再到 `/admin/users` 核对普通用户及外部登录身份，避免已有外部主体被重复创建。

查询前确认当前显示管理列表，而不是重定向后的管理员登录页。搜索按完整登录名核对每个结果，存在分页时查完匹配结果。登录失效、查询失败或尚未加载完毕不能作为身份不存在的依据。

管理员入口为 `/admin/login`；普通账号不能直接进入管理后台。管理员有多个职责时，以当前页面允许的动作及服务器权限为准，不为建号新建管理员或扩大其角色。

## 创建与激活

1. 先按下表选择现有身份的动作。已有普通主体但没有本地凭据，且本次已获准设置时，从“用户与职责”中的该用户选择“设置本地登录”，保持原主体。真正缺失时，在“本地账号”选择“创建本地账号”。
2. 填写已声明的固定登录名，保持普通用户类型，提交“创建并生成激活码”。不要为业务测试勾选管理员或最高管理员。提交超时先重新查询；不得盲目重发创建。
3. 当次激活码只读取到受保护变量。打开 `/login/activate`，提交该码；为新合成身份使用系统随机源生成符合页面要求的密码。这个管理员发码流程不依赖邮件，也不要求先开通外部登录渠道。
4. 按实际页面完成新密码、确认密码以及要求的验证器/恢复码步骤。保留目标现有策略；不关闭 MFA、不创建默认密码、不为普通登录额外启用渠道。
5. 保存密码与必要恢复材料到目标指定的秘密存储；非秘密登记记录固定人物、稳定主体、用途、角色、范围、责任项目和创建入口。默认保留固定账号供复用。
6. 用一个新的普通用户会话登录 `/login?returnUrl=%2Faccount`，核对新身份可正常登录。再从原应用发起新的统一登录，完成正常回跳。

| 观察到的状态 | 下一步 |
| --- | --- |
| 已启用，凭据已保存 | 复用原密码登录；不生成激活或重置码 |
| 待激活，原码仍可用 | 使用原码继续 `/login/activate`；不再次创建 |
| 待激活，原码丢失或到期 | 确认本次已获准恢复该身份，再使用“恢复密码与验证器”；该操作会撤销旧登录并清除原验证器，不是无影响的“重发激活码” |
| 暂时锁定、已停用、已到期或凭据缺失 | 按具体状态和恢复授权处理原身份；不通过新建、启用或延期绕过 |

## 进入业务应用

- 认证中心主体与平台业务用户分别管理。平台已有用户时，核对实际 `issuer/sub` 与 `userId` 的关联；同名不代表关联成立。
- 平台需要加入租户、绑定既有身份或开通应用时，使用其现有受管入口及本次获准的成员/角色范围。不要直接写库、新建第二个同名业务身份或自动授予管理员。
- 原应用仍拒绝登录时，按[平台首次接入](platform-access.md)区分尚未建档、缺少目标租户成员和应用发布范围。该流程使用现有受管入口，不要求安装 CLI 或取得平台源码。
- 从原应用实际会话核对用户、租户及业务页面。新账号没有业务准入时，如实区分“认证成功”和“业务准入未完成”，继续处理当前已授权的准入步骤。
- 再次运行账号准备时查重并复用，不重新生成激活码，不覆盖密码、MFA、角色或绑定。

## 恢复已有账号

仅在已有恢复授权下使用当前账号的“恢复密码与验证器”或“解锁”入口。说明实际会撤销或重置什么；有权登录管理页不代表获得修改任意现存身份的授权。最高管理员页面要求平台维护者恢复时，转交该目标的受管恢复入口，不创建替代管理员。
