# XRain Auth

通过认证中心现有网页完成账号和接入管理。先从原应用、已保存的连接或运行配置确认认证中心与实际浏览器入口；不要用同名演示环境替换用户指定的测试环境。本 skill 可以独立安装，不需要 XRain CLI 或服务源码。

## 选择路径并连续完成

| 当前问题 | 执行路径 |
| --- | --- |
| 没有账号、需要快速登录、账号未激活 | [固定账号准备](references/accounts.md)：查重、必要创建、激活、回到原应用 |
| 账号存在但凭据缺失或被锁定 | 同一账号的已授权恢复；没有恢复授权时只请求这一决定 |
| `client_id` 无效、回调或 scope 被拒绝 | [接入应用修复](references/clients.md)：核对调用方真实配置和中心登记 |
| 登录成功但没有业务权限 | 核对稳定主体、目标租户和业务准入；由业务平台的受管入口处理 |

`xrain-cli security user ensure` 创建的是平台业务用户，不是认证中心账号。CLI 的 `auth login` 消费中心的 OIDC 服务，也不提供中心管理功能。CLI 客户端失效不妨碍管理员在中心创建账号；原应用登录应使用原应用自己的接入配置。

用户已经要求解决测试登录时，在已授权环境内完成必要准备、修复和复测，不把“CLI 不支持中心管理”当作任务终点。新增客户端须来自实际调用方配置；权限、恢复和现有身份变更保持对应授权边界。

## 执行与凭据

- 优先复用当前可用的浏览器工具。工具故障时可使用环境中已有的受支持浏览器自动化；不要求用户手工点击已获准代办的正常登录步骤。只有本人验证码或第三方批准确实不能代办时才交给本人。
- 使用目标允许的秘密存储读取现有凭据。普通用户与中心管理员属于不同目录，分别登录；不要把中心管理员当作业务用户。
- 在页面读取实际表单和状态，正常提交并保留 Cookie、反伪造字段、state 和 PKCE。不要手工造会话、直接写库或关闭认证校验。
- 管理写入要求重新认证时，用原管理员完成正常登录，再读取目标现状确认上次是否生效；未生效才重新填写当前表单。不要复用过期表单、盲目重放创建或调整重认证时限。
- 密码、一次性激活码、验证器种子、恢复码、授权码及会话只在受保护上下文流转。敏感页面不要整页输出或截图；凭据保存到指定秘密存储，账号用途和结果另行登记。

## 完成依据

账号准备结束后，从原应用重新发起登录，核对实际用户、租户和本次所需业务页面。中心显示“已启用”、CLI 本地会话存在、公开健康接口返回成功，都不能代替原应用登录证据。客户端修复须用新一轮授权请求验证，不能重放旧授权链接。

报告实际复用或创建的固定人物、接入修复、业务验证结果与仍未通过的具体步骤。创建、激活、认证、租户准入分别按观察结果报告；不把其中一步通过扩写成全部通过。
