# 人类文档

Resolve project entrypoints, source, documents and command working directories from the user's target project. Resolve this skill's `references/`, `scripts/` and `assets/` from its installed directory. Locate other responsible repositories through the target project's entrypoint; never infer the target from the skill installation path.

为读者编写能够理解和使用的中文内容。先确定受众、任务与事实所有者，再决定位置和结构；操作指南应能从入口选择场景、照做并判断结果，课程应帮助读者理解和运用。不要把正式契约、智能体治理或脚本索引复制成人类手册。

先确定用户要求理解、只读审阅还是编写修改。只有理解或审阅授权时不直接改课程、文档或发布；已授权的改写按原范围完成，不因选择课程模式再次要求确认。

## 选择内容类型

教程、教材或课程需要帮助读者理解概念、举一反三并形成判断时，读取[课程与学习内容](modes/learning/GUIDE.md)。按学习者和平台实际能力核对概念、难度、案例、练习与导航；下文面向执行命令的操作指南细则只在该课程确有相应操作时适用，不用 60 行或单步骤模板裁剪教学内容。

README、上手和部署指南以可执行操作与可观察结果为主，沿下文从任务入口和真实运行合同写作。混合课程与参考手册时分别判断内容目的，链接同一事实来源，不复制一套 API 或产品规则。

## 判断放在哪里

先用目标项目的 StructureContract 确定目录。下表中的 `/人类-文档/` 是已采用该布局的工作空间约定；xrainTrain 等已有课程站点继续使用自己的内容与导航目录，不为套模板另建一套。

| 内容 | 位置 |
|---|---|
| 跨项目上手、开发流程和面向人的任务导航 | `/人类-文档/` |
| 与单个源码目录紧密绑定的构建、调试或维护说明 | 对应源码根或功能目录的 `README.md` |
| 产品规则、能力边界和长期技术设计 | `文档/` 下职责唯一的正式事实所有者 |
| 智能体路由、治理动作和可重复操作契约 | `AGENTS.md`、Workflow、Runbook 或 skill |

请求混合多类内容时，先更新真实事实所有者，再让人类文档用链接和任务步骤消费它。不要让 `/人类-文档/` 成为公共契约、源码行为或运行参数的第二事实源。

受众与事实所有权分开判断：人会阅读某个事实，不等于该事实应从 ProductContract、CurrentDesign、Decision、Runbook 或源码迁入人类文档；优先从任务入口直接链接唯一所有者。

## 执行顺序

1. 识别读者和用户要完成的具体任务，再为该任务判定执行类型。项目和会话没有全局当前阶段；不把首次上手、Development、SystemTest、评审治理和 Deployment 混成一个主流程，也不把一个任务完成写成另一类型任务已获授权。
2. 查证运行契约。读取真实脚本、源码、配置、测试、`package.json` 和邻近 README，核实隐含依赖、默认路径、端口、输出、重载、停止、失败和副作用；不要从命令名推断行为。
3. 确认可达结果。只有现有入口能够从前置条件走到读者承诺的可观察结果时才创建任务页；脚本只覆盖构建或验证、却缺少发布或部署闭环时，记录实现缺口而不是编造人类流程。
4. 搜索唯一入口和加载者。工作空间根 README 只做最短任务导航，`/人类-文档/README.md` 做完整人类导航，任务页负责执行；检查 AGENTS、Workflow 和 skill 的入站引用，避免人类 README 被列为智能体默认必读。
5. 按人的场景组织。先给最短成功路径，再给日常重复路径和验证选择；按任务分组，不按脚本清单或系统模块机械展开。
6. 执行读者走查。从入口开始逐步模拟首次读者：每一步必须知道在哪里执行、为什么执行、看到什么算成功、失败看哪里、是否可重跑以及如何停止。
7. 标记副作用。对部署、发布、安装、卸载、生成文件、版本修改和远端写操作，明确目标、影响和停止条件。
8. 更新导航。新增、移动、重命名或删除 `/人类-文档/` 内容时同步人类入口；不要把具体人类文档挂到 `AGENTS.md`。
9. 验证后收口。检查命令、路径、语义链接和可观察结果，删除治理话术、重复背景、未经验证的捷径和无法执行的建议。

## 按平台上的真实任务编写

启动 Workforce 的指南核对根一键入口、实际业务应用、共享服务前提以及前后端各自的刷新/重启行为；不能把改了公共源码写成应用已经更新。业务应用开发指南从已交付 SDK、包导出和真实 API 开始，不要求读者取得平台私有仓库。账号接入指南分别解释统一登录、应用准入、租户成员和业务权限，用固定身份展示当前任务所需步骤。

发布指南先辨别公共代码包、`.appkg`、服务镜像和客户端安装包的不同入口，再给该目标的操作。面向人的正文使用“对象、字段、记录、接口说明、参数、响应、权限、版本”等准确常用词；内部治理术语只留在事实所有者。示例从读者能完成的一次输入与可观察结果展开，不把整套平台配置当作每篇文档的起点。

## 写作规则

- 新建或实质改写工作空间文档的技术正文时，遵循[共同语言约束](https://github.com/xingshukeji/skills-hub/blob/main/skills/shzw-workspace-maintenance/modes/documents/GUIDE.md#受控技术写作约束)；保留本技能的人类任务结构和验证要求。
- 默认使用中文。命令、代码标识、配置键、文件名和既有专有名词保持原文。
- 标题回答“读者现在要做什么”，不要从系统模块、实现层次或脚本全集起笔。
- 人类任务页的文件名去掉 `.md` 后与 H1 完全一致；`README.md` 只作为目录入口使用。
- 导航页只帮助选任务，不承载操作细节；操作页只完成一个读者目标，不重复导航树或治理规则。
- 用“首次完成、日常重复、修改后验证”等人的场景做主线；不把方案评审清单、智能体门禁或脚本目录放在操作主路径。
- 一个步骤只表达一个动作；紧跟必要参数、预期结果和失败时下一步。
- 用表格做场景选择，用有序列表写执行顺序，用代码块给可直接运行的命令。
- 不添加 `Status`、`Kind`、`Scope`、`Owner`、`Updated`、`Depends On` 等正式治理元数据。
- 不复制可从源码、测试或正式契约低成本获得的细节；链接唯一来源，并只解释完成当前任务所需的部分。
- 迁移意味着旧位置不再承担该内容；混合文档先拆出人类任务步骤，再由原权威所有者保留边界和链接，不保留两份同职责说明。
- 不按每个 `npm` 脚本创建独立页面。稳定场景优先合并到现有指南，专项细节留在邻近 README。
- 不声称命令会打开页面、热重载、自动清理、更新远端或完成发布，除非源码或实际运行证据支持。

## 编写逐步操作指南

- 对构建、发布、安装和部署指南使用低自由度写法，只保留前置条件、顺序命令、产物或验证结果。
- 从源码、配置和目标环境查出当前真实值；命令中禁止使用 `<version>`、`<host>`、`{name}`、`$VERSION` 等占位符。缺少必要值时先查证或询问，不提交不可直接执行的命令。
- 把脚本实际要求但命令行未体现的账号、凭据文件、配置文件、工具版本、目录边界和网络条件写在执行前。
- 构建、发布或部署依赖源码状态时，写明并验证实际分支、提交、工作树状态和产物版本，不用可能保留本地修改的更新命令代替输入确认。
- 不把密码、Token、私钥或连接串写进文档。需要凭据时只写已确认的本机凭据位置或配置键，并让命令引用该位置。
- 不同机器或 Shell 的命令分开；只有必须一起执行的命令才放在同一代码块。
- 写出源码真实输出或可独立检查的完成标志；同时说明长驻进程如何停止、修改后是否需要重建重启，以及日志或诊断位置。
- 完成验证必须直接证明任务承诺的能力；进程存在、端口打开、HTTP 2xx 或文件生成只能证明其真实覆盖的范围。
- 默认把单份操作指南控制在 60 行以内。超过时按独立任务拆分，不增加背景、历史、参数全集或重复的故障百科。

## 验证清单

- 从入口出发逐个打开新增或变更的相对链接。
- 将文中的 `npm run <script>` 与根 `package.json` 对照；将其他命令与对应 README 或实现对照。
- 对最短成功路径做一次静态 dry run：核对执行目录、全部前置条件、明确参数、真实输出、访问入口、日志、停止/重跑方式和高风险副作用。
- 搜索并删除命令占位符、错误职责链接、智能体治理话术，以及没有实现证据的自动打开、热重载或发布成功声明。
- 确认没有复制正式事实，没有创建空目录，也没有把人类文档加入智能体默认热路径。
- 修改后按目标项目入口和实际工具链运行该内容需要的文档检查、测试与构建；只有项目提供并要求 `npm run check:docs` 时才运行该命令。课程按课程仓库自己的验证入口执行，不套用其他项目的脚本。
