# .NET 后端性能与资源优化

沿原后端开发任务实施，保留公共 API、租户身份、授权、事务及恢复语义。通用取证、候选与工程取舍可按当前入口读取[性能优化方法](https://github.com/xingshukeji/skills-hub/blob/main/skills/shzw-runtime-operations/modes/performance/GUIDE.md)；这里负责把候选落到 .NET、AiInfra 与实际业务消费。

## 识别热点与责任

从当前调用追踪 AppService、领域操作、Repository、provider、数据库及公共包。把业务算法、元数据/权限投影、JSON 编解码、行映射、数据库往返和持久化分开计量。一个导入或导出同时有解析、校验、转换、暂存、检查点及最终提交，先明确哪一段主导成本。

AiInfra 拥有数据访问、事务、provider 和公共运行能力；XRain 拥有记录、导入任务及应用语义，业务应用拥有自己的规则。公开消费者只用受支持合同，不能为了性能直接写内部表或复制租户路由。类型与当前合同从责任项目读取；类名、旧评测或库默认值不能替代当前实现。

在 XRain/AiInfra 当前 checkout 中，可从下列实现线索查起，再沿引用确认实际入口和消费包；目录与命令从项目入口解析，不从 skill 安装位置推导。

| 需要定位的工作 | 实现线索与责任 |
|---|---|
| 记录导入、计划与摘要 | XRain 的 RuntimeRecordAppService.Import 相关 partial；检查同一数据的准备、确认、恢复及导出消费者 |
| 安装或绑定资料的重复解析 | XRain 的 ApplicationRecordResolver；先核对当前修订、输入来源和已有缓存，再决定可复用部分 |
| 编排的 JSON 与执行成本 | AiInfra 的 JintHttpOrchestrationRuntime 及其合同；保留独立预算、输入/输出所有权与实际 SDK 调用 |
| SQL、连接与原子结果 | AiInfra 的实际数据访问/provider/UoW 与 XRain 适配；性能改变落在能持有事务和资源的所有者 |

## 按热点比较实现

| 热点 | 优先核对 | 可试方向与保留条件 |
|---|---|---|
| 重复计算与映射 | 实际调用次数、相同输入是否重复解析、算法和字典查找 | 合并遍历、复用已解码名称或稳定映射、预先编译纯表达式；失效及版本来源明确，不缓存可变权限结论 |
| JSON 与文本 | 数据在字节、字符串、DOM 和业务对象间如何转换 | 对 UTF-8 数据尽量在字节边界完成校验、摘要及写出；使用实际目标版本支持的 Span/Memory 和 JSON API，保留数字、Unicode、转义、重复字段及原摘要字节 |
| 缓冲与对象 | 谁创建、谁借用、是否向外返回、何时最后使用 | 优先省去中间对象，必要时比较 ArrayPool、MemoryPool、IBufferWriter 或流；异步跨界、SDK 保留参数、异常和取消后仍要有正确所有权 |
| IO 与数据库 | 每业务项的请求数、SQL、结果列、读取方式及连接持有 | 复用已存在的批量、投影与顺序读取，比较索引、计划、批处理或 provider 的 COPY；保留原事务、租约、幂等回执及配额，不能用批量直写代替正常业务授权 |
| 异步与并行 | CPU 热点或等待、同步阻塞、执行名额、线程/连接池及在途字节 | 用真实异步 IO 缩短占用，按现有名额重叠独立工作；证明完成顺序、异常观察、取消排空与提交结果，避免每层另起无界任务 |
| 缓存 | 可复用事实、key、修订及所有消费者 | 缓存纯且稳定的投影，按实际修改失效；租户、安装/绑定与定义修订分别判断。当前成员、权限与业务状态按其合同重读，不因 JSON 相同复用旧授权 |

对标准库与驱动查目标版本的实际实现。驱动已使用顺序读取时，新增同名包装没有对应收益；改变连接缓冲、自动准备或事务参与前，先证明该设置是热点，并保留连接状态隔离与工作单元行为。CPU 高且在做计算时，增加 async 或线程数不会自动减少计算。

## 写出可维护的优化代码

把借用、使用和归还放在容易核对的作用域中；归还或 Dispose 后不再暴露借用数据。同步 Span 消费与跨异步保存的 Memory 所有权分别设计。向外返回 JSON 或交给可能保留参数的 SDK 时，按实际 API 的生命周期取得独立数据。需要临时文档时也要比较池的清理与保留成本，不以“池化”推导更快。

编码边界只转换必要次数。已经持有合法原 UTF-8 时，检查能否按原字节处理；转义字符串的长度要按合同中的解码后字节计算。哈希和规范化优化先固定旧协议，独立验证排序、精度、空值、日期和 Unicode；不能通过改签名版本或放宽校验使优化测试通过。

抽取函数时让职责、输入和生命周期明确，保持正常路径直接。优先当前框架能力与可解释的局部实现；只有实际收益足够时才维护自定义分配器、解析器、执行池或复杂缓存。保持同一错误的处理入口，显式呈现提交、回滚及重试边界，避免在多层 catch 中改写同一状态。

## 按原功能验证

先验证旧新转换结果及签名兼容，再验证相同业务的完整数据、顺序、身份、唯一性、持久回读和回执。并发或 IO 改动补相关取消、保存失败、撤权、租约丢失、响应丢失与恢复；只选择真实可达分支。把预检无业务写入、整批原子性或逐项结果等原承诺继续作为断言。

替身按真实公开类型和调用字段编写；它不能证明数据库事务或实际包消费。触及 provider/UoW 时使用匹配风险的真实依赖；公共库变更通过实际包验证 XRain、脚手架或命中的消费者。普通业务函数改动不因此要求完整发布流水线。

运行时版本、GC 模式、容器 CPU/内存限制、连接设置、数据分布及诊断开销纳入对照。分别报告分配、存活量、GC 暂停、IO 和完整业务时间，不把组件指标作为所有文件或所有负载的时限保证。

## 官方与开源依据

- [Memory 与 Span 使用指南](https://learn.microsoft.com/en-us/dotnet/standard/memory-and-spans/memory-t-usage-guidelines)：核对所有者、使用者与借用期限。
- [.NET 10 性能改进](https://devblogs.microsoft.com/dotnet/performance-improvements-in-net-10/)与 [System.Text.Json 源码](https://github.com/dotnet/runtime/tree/v10.0.0/src/libraries/System.Text.Json)：按目标版本比较解析、序列化和缓冲，不将示例加速比套到项目。
- [Npgsql 性能](https://www.npgsql.org/doc/performance.html)与 [COPY](https://www.npgsql.org/doc/copy.html)：核对现有读取、往返、准备及批量能力；执行事务仍由 provider 和当前工作单元持有。

这些是研究入口，使用前按项目实际版本核对；不自动升级、安装工具或引入新依赖。
