# 客户端性能与资源

从用户可见动作定位加载、交互、保存、媒体与退出成本。沿原产品、平台、身份及业务目标工作，不把接口更快、组件测试或静态画面当作实际操作更快。

## 分清成本与所有者

固定目标页面或原生入口、实际包、代表性数据和操作。分别观察首次打开、恢复会话、连续交互、离开与再次进入；按相关窗口核对网络、主线程、渲染、桥接、堆/堆外内存和媒体资源。已有性能工具与标记足够时不新增监控框架。

Workforce 公共界面、业务应用页面、Electron/React Native 等宿主及 Runtime 各有所有者。按项目实际依赖和构建确认技术栈；不因同一屏幕包含它们，就把服务端等待改成界面缓存，或把应用状态放到公共宿主。

| 已确认代价 | 可比较的方向 | 必须保留的功能 |
|---|---|---|
| 初次加载和重复请求 | 依赖裁剪、按需加载、已有缓存与请求复用、减少重复序列化和桥接 | 原路由、准入、错误恢复、实际可操作时间；不隐藏仍未完成的请求 |
| 大列表或高频更新 | 稳定标识、减少重复派生和更新、按实际控件虚拟化或渐进呈现 | 完整数据语义、滚动锚点、选择、键盘与无障碍、搜索和末页 |
| 输入与连续交互 | 缩短同步计算，按业务选择去抖/节流或后台计算 | 输入法、最终输入提交、取消、草稿和用户操作顺序 |
| 图片、音视频和附件 | 合理尺寸、按需读取、流式传输，释放不再使用的 URL、解码器和监听 | 播放/下载完整性、失败重试、在用资源的期限，关闭后停止后台活动 |
| 长时内存或多次进入 | 核对事件、订阅、计时器、缓存和原生句柄的创建与结束 | 已保存业务、共享实例、恢复状态；不能清空历史或重启来证明释放 |

请求复用和缓存按当前身份、租户、对象、版本及有效期选择。异步完成时再确认结果仍属于当前页面或执行；取消 UI 等待不证明服务端已经撤销写入。并发请求减少时同时验证权限变化、失败与后续恢复。

## 保持实现直接

先去掉重复工作和多余状态，再选择框架的更新、资源和生命周期机制。数据来源、加载状态及持久结果保持清楚；局部性能修复不新增一套客户端业务规则或通用请求框架。

虚拟化、预取、对象复用与后台任务会增加状态和调试成本，按实际收益决定。保留原交互与可访问性，不用空白占位时间、减少显示内容或丢弃迟到错误制造更好数字。需要新工作线程或桥接协议时，把消息边界、取消与清理责任同时说明。

## 验证原动作与相邻行为

性能对照包括实际可见结果和相关正常操作，再检查切换身份/对象、重复点击、失败、迟到响应、退出与再次进入。改列表不只测首屏，改保存不只测响应，改释放不只测调用 Dispose。必要时用可控事件顺序复现，原生或浏览器证据按当前平台入口取得。

前后使用相同的相关包、视口、数据和冷/热状态，分别报告可见延迟、失败和资源。API、组件或作者隔离例不能代替页面/设备验收。具体指标与生命周期断言可按目标可用的[功能回归方法](https://github.com/xingshukeji/skills-hub/blob/main/skills/shzw-testing/references/functional-regression.md)选择，不强制运行整张客户端矩阵。

技术选择先查目标版本的官方性能与生命周期指南。例如项目使用 Vue 时可查[Vue 性能指南](https://vuejs.org/guide/best-practices/performance.html)；其他框架按实际版本选择，不能直接套用另一框架的更新或释放模型。
