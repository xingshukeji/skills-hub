# 验证、复用与持续积累

## 连接两类真实业务

人员主线必须接到一条实际工作主线，才能判断开通是否有用。以下两类来自当前 XRain/Workforce 已确认的业务方向，展示复用边界；具体项目合同和目标状态仍须读取。

| 环节 | 顾客接待 | 成员处理自己的任务 |
| --- | --- | --- |
| 相同前提 | 固定身份、有效租户成员、应用准入及本人入口 | 同左 |
| 动作资格 | 顾客维护按专门业务权限与共享范围 | 已启用的任务全员权限集按声明覆盖有效成员，不复制接待角色 |
| 首件业务 | 查找/登记顾客、补充资料、保存回读 | 创建任务、修改内容、保存回读 |
| 再次进入 | 同一顾客引用下继续本人的对话 | 找回同一任务，核对原创建者和当前任务责任 |
| 协作结果 | 共享顾客业务事实；其他店员仍使用自己的私人对话 | 按任务模型处理责任与状态；不能用群成员关系代替任务授权 |
| 不可照搬 | 不把私人对话共享，也不从推荐推导成交 | 不引入顾客字段、接待会话关系或销售步骤 |

从第二类业务得到差异就保留差异，不以“一处成功”宣称所有业务通用。若目标没有装配某能力、没有所需资料或缺少已批准动作，登记该段未验证，不补造流程。

## 一次有意义的业务验证

选原使用者、一个必要对照者和受控虚构记录；优先复用固定人物。记录业务起点、实际环境/版本、人员用途、记录或操作引用及允许/拒绝预期。秘密、客户资料和原始过程日志留在目标受控位置，不进入主线知识。

顺序覆盖实际需要的“进入 → 办事 → 保存回读 → 刷新/续办 → 获准协作”。职责调整只有在本次已授权范围内实施；调整前保留来源与业务基线，调整后同时检查仍允许与应拒绝的动作。不能用管理员操作或离线模拟替代普通人的真实结果。

保持三种证据分开：

- **业务确认**：谁确认了什么结果及边界，来源指向项目模型/产品合同。
- **实现支持**：交付合同、源码类型或定向测试证明哪些行为；不等同目标已安装或可用。
- **本次实测**：明确入口、版本、身份用途、动作与实际结果；未执行、失败和阻断保留原状。

基础入口通过而共享、续办或职责变更未执行时，只报告已覆盖片段。长主线的目录结构完整不等于整条主线实测通过。

## 业务资产如何更新

主线保存跨环节的因果、适用条件、关键选择和异常后怎样继续；字段、接口、命令仍由各自唯一所有者维护。使用稳定标识链接已确认业务，长内容按业务环节拆开，保留一处完整总览。

需求确认时更新业务来源和受影响环节。实现改变时更新映射与验证入口。另一个业务复用时记录可复用部分、差异和不能套用的条件。只把具有独立复用价值的共同解法纳入 skill；具体业务决策继续保留在所属项目。

一次请求、一次测试或一个对象都不自动产生新 skill。主线是研发与运维共同使用的知识，不创建运行时状态表、业务审批流程或工作流引擎。
